# AI Knowhow Kit：七篇文章与首页的编辑性重构

日期：2026-07-12  
状态：已由用户确认按方向 C、方案 B 实施

## 目标

首页负责建立一条清楚的个人研究主线：模型如何进入真实组织，并通过评测、运行时和部署反馈形成可持续改进的闭环。七篇文章负责为 AI 从业者提供可独立阅读、可追溯证据、可被反驳的深度论述；协作入口保留，但不抢占研究内容。

这轮不是换一套更华丽的模板。核心工作是把 360 条 notes 中的判断重新组织成七个有不同问题意识的章节，并让页面视觉服从阅读，而不是服从“AI landing page”的惯例。

## 已确认的主要问题

### 七篇文章

1. 同一结论在引语、研究主线、关键判断、新增观察、实践建议中重复出现，篇幅增加但信息增量有限。
2. 七篇文章共用几乎相同的六段式结构，造成明显模板感；“洞察 1—5”“四条建议”“四个问题”没有体现主题差异。
3. 新材料被放进按月份命名的补丁段落，证据没有进入原有论证链。
4. 论文、公司内部实验、榜单、个人体验和作者推测被并排陈述，适用边界不够清楚。
5. “不是 A 而是 B”“真正要看的不是”等句式过密，形成判断口号，缺少机制、条件和可操作对象。
6. 结尾常以泛化问题代替证伪条件；读者无法据此判断观点在什么情况下应被修正。

### 首页与 UI

1. Hero、三个问题、研究主线、章节卡片和 About 多次重述同一定位。
2. 渐变背景、emoji、全大写英文微标签、阴影和圆角卡片叠加，视觉上接近通用 AI 落地页。
3. 卡片数量过多，章节之间的逻辑关系反而变弱。
4. `17.8 万字个人评论` 是低价值指标；“所有 notes 均经过人工 review”也超过了实际数据口径。
5. 移动端 CTA 和导航存在裁切风险；部分引用只支持鼠标 hover，不适合键盘和触屏。

## 内容设计

### 七篇文章不再共用同一模板

每篇保留四个共同约束，但章节标题和论证结构按主题决定：

- 开头给出一个可被理解、也可被反驳的核心判断。
- 正文区分证据类型、机制和边界，不按 note 时间顺序堆叠。
- 给出一个主题专属的工作工具，而不是通用建议清单。
- 结尾列出 2—3 个真正会迫使作者修改判断的观察条件。

建议标题与专属工具：

1. **模型能力不是一个分数：数据、训练信号与环境如何共同定界** —— 模型比较合同。
2. **Harness 不是提示词外壳：长程 Agent 的状态、约束与恢复** —— Agent 运行合同。
3. **先审计尺子，再比较模型：Agent 评测的任务、环境与验证器** —— 评测审计表。
4. **代码生成变便宜以后：验证、路由与维护成为新成本** —— 工作负载路由表与全成本账本。
5. **模型进入工作流之前：状态、权限与接管如何被设计** —— 授权与接管阶梯。
6. **模型毛利承压之后：价值为何向运行时与部署学习迁移** —— 价值捕获检查表。
7. **能力提升不会自动带来赋权：AI 部署中的判断权与责任** —— 隐性劳动与责任台账。

### 351—360 的处理原则

- #351 作为 scaling law 条件性的案例，明确“Kaplan bug”来自 Diogo Almeida 的复盘观点。
- #352 只支持 workspace-like 表征及其因果作用，不把功能类比写成主观意识证据。
- #353 把训练时顺序约束与推理时并行解码分开，限定在论文覆盖的 dLLM、数学和代码设置。
- #354 把长程表现写成 model × harness × environment 的系统结果；log-sigmoid 是跨任务总体规律。
- #355 用于定义 harness 边界；held-out eval、权限和人工节点留在自我优化循环之外。
- #356 作为毛利压缩假设，不把作者估算写成行业事实；与 #358 的真实企业 workload 证据配对。
- #357 强调 objective 与 guardrail 双重验收；榜单口径不外推为通用智能排名。
- #358 区分 token 单价与任务总成本，并限定为 Databricks 内部、可测试的代码任务。
- #359 支持 full-duplex 前台与后台委派的产品架构；不采用本地官方来源未清楚支持的“无视频/屏幕共享”断言。
- #360 用于说明评测数据点本身必须审计，并保留抽样与估计口径。

## 首页信息架构

首页改为五段，减少重复：

1. **Hero**：一句研究主张、一段边界说明、两个 CTA；纯色深色背景。
2. **研究问题与路径**：把原“三个问题”和“研究主线”合并成一段有因果顺序的说明。
3. **七章目录**：采用编辑式列表与分隔线，显示章号、问题、结论和阅读入口，不用七张悬浮卡。
4. **最近 notes**：显示少量最近条目并直接链接到证据浏览器；说明“why 是个人评论，缺失时只展示索引信息”。
5. **关于与协作**：两栏短文，明确适合交流的真实工作流、评测、Context/Harness 和部署议题。

文章页保留证据浏览器的三种视图（文中引用、最近更新、全部 notes）、搜索、类型筛选和增量加载。

## 交互与无障碍

- note 引用改为可聚焦的按钮或链接，支持键盘打开对应证据。
- 最近 notes 使用原生链接。
- 小屏导航只保留必要入口，Hero CTA 允许换行，页面不得横向溢出。
- 保留清晰的 focus 状态、语义标题层级和触屏可用的点击区域。

## 验收标准

- 数据包包含 360 条 notes，351—360 均有 1—3 个有效主题归属，并至少在一篇文章中被实质引用。
- 七篇文章不再出现独立的“2026 年 6—7 月新增观察”，也不共享完全相同的 H2 模板。
- 每篇文章有明确的证据边界、一个专属实践工具和 2—3 个证伪条件。
- 首页不再使用渐变 Hero、emoji 章节图标、虚荣字数指标或绝对化 review 文案。
- 桌面与 390px 移动端无横向溢出、CTA 裁切或导航遮挡。
- 构建、单元测试、JavaScript 语法检查、文本降噪扫描和浏览器检查全部通过。
