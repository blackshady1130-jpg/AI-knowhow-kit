# 模型降价之后，AI 企业靠什么赚钱

**讨论模型商业化、云、路由、FDE 和企业部署 · 更新至 2026.08**

---

## 核心判断：先看谁承担成本，再看谁掌握结果

> **模型更便宜，不等于模型供应商、路由平台和 AI 应用都会赚钱。长期利润取决于三件事：谁承担算力与交付成本，谁能判断任务是否真正完成，谁能把失败、修正和验收写回下一轮产品或训练。**

AI 产业不是一条统一的价值链。模型服务商生产 token，路由平台聚合模型和 provider，应用进入工作流，FDE 处理客户现场，芯片、云和数据中心提供稀缺资源。每一层的收入、成本和替换风险不同。把“需求增长”直接写成“这一层会获得高毛利”，容易忽略成本由谁承担、结果数据留在哪里，以及客户规模变大后会不会迁走。

因此，判断一家 AI 公司不能只看调用量、注册用户或模型榜单。至少要同时看单位成功任务成本、推理/交付毛利、客户留存、人工接管、资源利用率和学习回路的归属。

## 卖 Token 为什么可能越卖越亏

硅基流动的港股招股书提供了一个难得的独立 MaaS 样本（#366）。2025 年公司收入从 735 万元增至 5533 万元，整体毛利率却从 39.4% 降到 -24%。其中公有云服务收入 2926 万元，直接成本 6408 万元，毛利率为 -119%；本地部署收入 2607 万元，毛利率则为 82.5%。公司另有 5421 万元推广算力，用于免费 Token 和代金券。

这些数字只能说明硅基流动在该年度、该业务结构下的经营结果，不能代表所有 MaaS。它们仍揭示了一个清楚的机制：公有云平台要提前租赁算力、保障容量和稳定性，同时用低价与补贴获客；若没有自有云、自有模型或高毛利产品交叉补贴，新增 Token 可能扩大亏损。相较之下，本地部署把资源和交付方式绑定到具体客户，收入结构完全不同。

应用层也有类似问题。重推理、视频和多 Agent 产品的边际成本不会像传统 SaaS 那样接近零；订阅价格若低于重度用户的满额模型成本，盈利就依赖用户不把额度用完（#383）。套餐分层、隐藏模型、降档和积分体系可以控制成本，却也可能让产品目标从“帮助用户完成更多工作”变成“限制用户使用”。这类应用必须证明结果价值足以覆盖推理、重试、人工支持和模型采购，而不是只证明用户愿意消耗 Token。

## 路由平台能解决什么，不能解决什么

OpenRouter 证明了 provider 碎片化会产生中立入口的需求（#367）。开发者可以用一把 Key 比较不同模型与 provider 的价格、吞吐、可用率和数据政策，并在服务故障时切换。这些跨供给方信息很难由单个应用实时维护。

但“路由”至少包含四件不同的事：为任务选择模型、为同一模型选择 provider、在 Agent 内部安排子任务，以及管理企业权限与数据。OpenRouter 最强的是 provider routing；真正判断“代码是否通过测试、工单是否解决、邮件是否转化”的结果数据，通常留在应用、Harness 和企业自己的 Eval 中。越接近最终结果的平台，越有机会学会哪种配置适合哪类任务。

路由平台还存在“毕业问题”。约 5% 的平台费对小团队是便利成本；当年度模型支出达到百万美元级，客户有动力把稳定、高频流量迁往直连或自建，只留下新模型测试、故障 fallback 和峰值容量（#367）。这个阈值不是行业定律，但说明平台必须证明它提供的持续决策价值高于 take rate，而不只是帮助客户完成第一次接入。

任务级路由也不能只看百万 Token 单价。Databricks 的内部 coding benchmark 显示，同一模型接入不同 Harness，部分任务成本可相差两倍以上；Sonnet 5 虽然单价较低，总 Token 约为 Opus 4.8 的 1.9 倍，任务成本反而更高（#358）。企业应比较 cost per accepted task，并把模型、effort、Harness、缓存、重试和人工 Review 放在同一张账上。

## 开放模型会重新分配利润，但不会自动消灭闭源模型

中国开放模型正在被全球开发者用于产品底座、训练教师和合成数据。美国掌握领先闭源模型，西方企业却越来越依赖 Qwen、Kimi、GLM、DeepSeek 等开放权重模型，这一现象被称为“开放模型悖论”（#364）。Post-training 与蒸馏降低了能力转移成本，但不能把中国模型的进展主要解释为复制美国模型；预训练、数据工程、架构、推理系统和软硬件协同同样重要。

K3 进一步把开放权重的影响推到前沿：开放模型可能压缩闭源实验室 API 毛利和估值，同时降低社会使用智能的门槛、加速能力扩散（#368）。这两种作用方向相反。对模型公司是经济压力，对企业和开发者可能是更多可拥有、可修改和私有部署的选择。

开放权重也不等于低门槛或零服务价值。超大模型的显存、互连、量化、缓存、调度和升级仍需要专业系统；许可证也会限制部分用途。DeepSeek 把护城河定义为成本、迭代速度和全栈效率，而不只权重保密（#376）。它的风险同样具体：若 Agent Runtime、权限、日志、Eval 和真实反馈长期沉淀在其他平台，模型团队可能拥有强权重，却缺少最接近用户工作的控制点。

## 算力可能更贵，实验室仍可能赚不到股东预期的回报

“Token 商品化”不代表所有计算资源都会降价。Dwarkesh 提出一个条件推演：如果模型收入增长快于算力供给，一张 GPU 能完成的经济工作快速上升，算力价格和最强模型的溢价反而可能上涨（#378）。文章引用的收入、毛利和未来增长情景很激进，适合用于理解供需机制，不应写成已确认预测。

前 OpenAI 研究人员 Andrew Ho 从股东回报角度提出反例（#379）。前沿实验室不能像成熟软件公司一样停止研发、只收推理毛利；只要开放模型和竞争者持续追赶，训练下一代模型更像维持地位的资本开支。即使推理毛利提高，现金流也可能继续流向芯片、云、数据中心和电力。模型创造巨大社会价值，与实验室股权获得同等价值，是两笔不同的账。

这两个观点并不互相抵消。可能同时出现：普通 Token 价格继续下降，高利用率的大规模集群更贵，最强模型保留短期溢价，实验室仍因持续研发和竞争无法沉淀预期利润。AI Infra 的瓶颈也已扩散到内存、网络、电力、CPU、沙箱和 Verifier（#381）。最终需要观察的是每单位计算产生多少被接受的工作和现金，而不是单看芯片数量或 Token 产量。

## 企业应保留自己的学习回路

Satya Nadella 所说的 Reverse Information Paradox 指出，企业为了让外部模型有用，需要不断输入文档、流程、工具、判断标准和纠错经验（#361）。真正会复利的资产不只是原始数据，还包括 Agent 在哪里失败、人怎样修改、什么结果被接受，以及企业用什么 Eval 判断好坏。

这不意味着所有员工轨迹都能自动拿去训练。原始交互可能包含敏感数据、错误决策、未授权内容和无法归因的反馈。企业需要拥有自己的 private Eval、Memory、Trace、Feedback 与 Workflow，明确谁能写入、谁能读取、如何脱敏、怎样撤回，并保留更换基础模型后继续使用这些资产的能力。Learning-loop ownership 是治理与迁移能力，不是一句“数据归我”就已经实现。

产品可以帮助形成这条回路。#372 把 AI 产品描述为让真实任务可进入、可操作、可验证、可回流的环境。这个 Scale Environment 框架尚未被证明是一条 Scaling Law；其可用部分是把产品日志从点击记录升级为带意图、失败和验收的任务数据。只有结果被明确判断、反馈经过授权和质量筛选，工作流才可能变成 Eval、Skill 或训练材料。

## FDE 的价值要落到可复用资产

企业 AI 的难点往往藏在本地数据口径、审批、例外和 owner 中。#76、#97 对 Forward Deployed Engineer 的讨论共同指出，通用产品团队很难在远处理解这些约束；FDE 进入现场，把模型接到具体流程，再把重复问题写回产品。

FDE 不等于无限定制。一次客户项目至少应留下三类可复用资产：连接器和权限模式；带真实失败样本的 Eval；可以迁移到其他客户的 Workflow 或 Skill。如果每次上线都依赖同一批专家驻场、模型升级后还要重新手工修补，收入更接近高成本服务，而不是可扩张产品。

## 实践工具：AI 项目商业价值检查表

| 层次 | 需要检查的问题 |
| --- | --- |
| 模型 | 优势来自独占能力、价格、延迟还是模态；领先窗口多长 |
| 推理供给 | 谁承担 GPU、容量冗余、利用率和故障成本；毛利是否含补贴 |
| 路由与运行时 | 决定 provider、模型还是任务编排；是否真的降低 accepted task 成本 |
| 入口 | 是否拥有任务状态、权限、artifact 与用户验收界面 |
| 学习回路 | badcase 能否归因；专家修正会进入 Eval、Skill 或训练吗；授权如何管理 |
| 部署 | FDE 产物能否跨客户复用；上线与接管责任归谁 |
| 商业 | 谁掌握预算；按 token、seat、任务还是结果收费；重度用户是否负毛利 |
| 资本 | 训练与推理投入、利用率、现金消耗和收入兑现速度怎样变化 |
| 边界 | 替换成本来自真实资产，还是合同、补贴、惯性与短期模型差距 |

一家公司不必同时控制九层。使用这张表，是为了找到它承担的主要成本和掌握的关键结果。收入增长、Token 增长与注册用户增长都需要回到账上的同一单位：一个被客户接受的任务最终贡献了多少毛利，留下了什么可复用资产。

## 哪些证据会改变以上判断

1. 若独立 MaaS 与重 Token 应用在取消补贴后仍能随用量增长稳定提高毛利，且不依赖本地部署或其他业务交叉补贴，“Token 增长可能扩大亏损”的判断应当收缩。
2. 若中立路由平台长期保留大型高频客户，并掌握比应用与企业 Eval 更强的任务结果数据，价值可能更多集中到路由层。
3. 若前沿实验室持续扩大能力差距、减少研发资本强度，并在开放模型追赶下仍保留稳定高额自由现金流，应当上调对模型层长期利润的判断。
