# 行业格局与企业战略：当"造模型"变成"造生态"，谁在定义下一轮游戏规则？

**覆盖 100 篇判读 · 2025.05 – 2026.05**

---

## 一、当前正在发生什么

过去一年，AI 行业当然还在比模型，但更难的是后半段：谁能把模型能力卖成稳定收入，谁能扛住算力成本，谁能进入客户工作流。

几个信号放在一起看很明显：OpenAI 推出 Frontier 平台，派工程师驻场企业（#137）；AWS 把自己重新包装成“AI 代理人的管家”（#138）；Palantir 靠“厚软件”和 FDE 模式继续吃企业预算（#136）；另一边，一批 AI 创业公司陷入“Vibe ARR”的虚假繁荣（#15）。行业不是不看模型了，而是模型本身越来越难单独解释商业结果。

护城河也变得更难讲。算法领先可能几个月就被追平；数据被田渊栋排在第一（#195），但数据怎么变成产品，也不是一句“私有数据”能解决；协议和标准也开始进入竞争，MCP 的演化已经超出技术范围（#67），“掌握协议者，掌握生态”这句话虽然有点重，但方向值得看。

更现实的问题是钱。互联网时代的“免费 + 广告”在 AI 这里不顺，因为 token 成本太高（#40）。谁在赚钱，谁在烧钱，谁在用会计口径把亏损藏起来，谁把 capex 压到了现金流边界，这些问题会决定泡沫什么时候被戳破。

4-5 月新增材料把这个问题推到更硬的一层：OpenAI 试水 Guaranteed Capacity、成立 Deployment Company、收缩 self-serve fine-tuning（#281, #263, #264）；云厂商、HBM、半导体、电力和现金流被绑进同一个 capex 故事（#255, #256, #257）；Anthropic 借 AWS、Bedrock、Trainium 这条线说明，不拥有最强模型 IP 的云厂商也能在企业分发层赚钱（#286）。AI 竞争越来越像工业系统竞赛，不像单点模型竞赛。

## 二、核心观察与判断

### 洞察 1：头部玩家卖的东西开始分化

最清楚的变化来自几家头部公司的动作。

OpenAI 推 Frontier 平台（#137），卖点是帮企业把 AI 从工具变成“AI 同事”。真正值得看的不是这个说法，而是它派工程师驻场企业，做类似 Palantir FDE 的白手套服务。这说明 OpenAI 不满足于卖 API，开始往企业集成和落地服务走。

AWS 选择了另一条路。它不硬卷模型智能，而是用 Bedrock 做“AI 模型大卖场”（#138），把自己放在基础设施和分发层。自研 Trainium 芯片和英伟达结盟并行，等于是两条腿走路。微软在 Big Pause 之后（#95）也从拼 GPU 工厂，转向 API/Foundry/Copilot 这些毛利更高的入口。OpenAI 模型绑定到 2032、Foundry 的 Token 服务、Copilot 应用入口，都是在把算力投入转回可收费的产品面。

Anthropic 在白宫 DoW 合同上输给 OpenAI（#174），也很说明问题。Anthropic 更强调原则，OpenAI 则是原则、执行和政治公关一起做。最后结果是 OpenAI 拿到合同，也保住了红线。这个案例提醒：在政府和大企业场景里，技术能力之外还有很多非技术变量。

新一层竞争是 agent runtime 和 capacity control。Anthropic Managed Agents 开始收拢运行时和控制平面（#229）；OpenAI Guaranteed Capacity 把推理资源从按量 token 推向提前锁定吞吐（#281）。企业客户买 API 调用，也买稳定算力、状态层、运维层和出了问题谁负责。

### 洞察 2：Palantir 模式好学，但容易学成咨询

Palantir 是这一年被讨论最多的非模型公司。Q4 营收 14 亿美元，同比 +70%；美国商业业务增长 137%（#136）。Karp 引用邓小平“黑猫白猫论”，意思很简单：不追求最聪明的 AI，只解决客户问题。Ontology 把企业零散数据变成语义化、可执行的数字孪生（#144），这和普通数据湖不是一回事。

但“Palantir 化”也制造了很多幻觉。a16z 合伙人吐槽，几乎每家 AI B2B 公司都说自己是某领域 Palantir，实际是“精装修版埃森哲”（#130）。很多公司学到的是驻场/定制的表皮，最后滑向项目制交付：人越招越多，毛利越做越薄。

国内学 Palantir，最该学的不是派人驻场，而是怎么用驻场逼出平台化回收，把服务占比压下去（#129）。能复制的是平台优先、结果导向、FDE 深度参与产品迭代；难复制的是 Palantir 早期吃到的国防/情报市场红利：价值密度高、客户少但大、替代方案少、切换成本高。少一个条件，同样的高接触模式就会变成贵且难规模化的服务。

也有反面声音认为 Ontology 本质是数据库 Schema + API 的包装，被信息不对称和 FOMO 吹成了“屠龙之术”（#164）。这个解构有道理，但也有点低估脏活的价值。KA 客户关系、系统融合、跨部门推动，看起来没技术门槛，但不是所有团队都能干好。

新增材料里的 FDE 讨论更清楚（#280）：FDE 是 AI 企业落地的窗口期角色，解决模型能力和企业现实之间的集成之墙。真 FDE 的目标不是永远驻场，而是让第 10 个客户比第 1 个客户更容易部署。OpenAI 补 Deployment Specialists（#264），也是同一个方向。

### 洞察 3：泡沫不在“AI 有没有用”，而在成本和时间差

泡沫讨论很多（#94），但我觉得最该看的不是模型能力真假，而是单位经济模型。

我的几个判断是：第一，应用层货币化失败才是系统性风险的触发器。如果 AI 应用不能跑出正向单位经济，基础设施投资就会变成“僵尸 GPU”。第二，风险不只在财务流动性，也在物理约束。北美电网 3-5 年内未必能支持 hyperscalers 需要的电力增幅。第三，大厂 ROIC 改善可能有会计游戏成分：裁员、内部转移、成熟业务补贴 GenAI，都可能把真实成本藏起来。

a16z 用数据反驳泡沫论（#150）：Google TPU 7-8 年保持 100% 利用率，真正的泡沫不会有这种持续算力饥渴。Token 越便宜、用量越大的 Jevons Paradox，也说明需求天花板可能比多数人想得高。

Dario Amodei 的框架更精确（#193）：AI 行业盈利可能来自低估需求，亏损来自高估需求。算力要提前 1-2 年采购，判断错一年，公司就可能出大问题。“盈利”有时不是效率好，而是算力买保守了。

#249、#255、#256、#257 把泡沫问题拉回“谁买单”。AI coding、agent 和订阅制产品的真实 token cost 很多时候被平台补贴遮住；大厂 capex 占运营现金流比例上升，云、半导体、内存、电力、债务互相嵌套。泡沫不是 AI 没价值，而是市场用三年兑现速度给十年产业周期定价。

### 洞察 4：中国 AI 生态会被算力约束塑形

Kimi K2 的发布（#28, #39）体现了几个变化：产品交互从对话优先转向 artifact-first；模型 Agent 能力还在早期，不少数据在预训练阶段缺失；开源既是获客方式，也是在倒逼公司做更高标准，避免用 hack 粉饰效果。

杨植麟和阶跃张祥雨对 L1-L5 演进的分歧值得看（#39）。杨更强调各智能层级并行发展，高阶能力可以反哺低阶；张祥雨更强调串行解锁，需要核心算法突破。这个分歧不是学术口水，它会影响公司怎么分配算力、数据和研究资源。

模型壁垒也在从算力效率转向数据效率。Kimi 团队通过规模化 Muon 优化器和数据改写，在同等数据消耗下拿到近两倍智能增益。Nathan Lambert 对蒸馏的提醒也很关键（#168）：算力受限者确实会想通过 API 蒸馏领先模型，但真正前沿模型需要大规模 RL，on-policy 数据没法完全绕过。说中国模型永远追不上美国前沿太早，AI 里层级反转已经发生过。

新增的中国算力和实验室观察把路线差异讲得更具体（#230, #258）。中美算力差距真实存在，它会影响路线选择：美国更容易走 closed-source、bigger model、frontier training；中国更自然走 efficiency-first、distillation、MoE、推理压缩、开源部署。Nathan Lambert 对中国 AI labs 的观察也强调，fast-following、开源反馈和关键技术栈自有化是优势，短板是 0-to-1 研究文化、数据产业和训练算力。

### 洞察 5：AI 公司的 PMF 会过期

在 AI 行业，PMF 不再是找到一次就吃几年红利（#98）。模型能力和用户预期刷新太快，核心价值每季度都会移动。传统 SaaS 的品牌、漏斗、销售话术，很可能没有过去那么强的复利。护城河会更多来自发布节奏和产品体验。

#40 说商业模式从免费流量转向价值付费，产品价值从链接价值转向效率价值。落到企业软件，就是用户愿意为你少切多少上下文、少走多少流程、少承担多少不确定性付费。#159 的反共识也重要：AI 模型越强，流程工程越重要。企业软件的价值不是代码，而是对业务流程的理解，以及把协作方式编码成“社会契约”。在金融领域，80% 正确率就是 100% 错误。

#284 的“资本门、使用门、ROI 门”很适合给 Agent 商业化降温：终局正确不等于路径正确，demo 能跑不等于进 SOP，能替人做一次不等于客户愿意持续付费。#267 的 Ramp 数据显示 AI 软件采购正在从 record 走向 action，但 #285 的 SaaS-Bench 提醒真实工作流仍然很难自动化。下一步要看谁能跨过使用门和 ROI 门。

## 三、正在发生的变化与趋势

- **模型不是唯一壁垒，体系能力越来越重要**：Long Context 横评（#190）说明标称能力和可用能力差很远；#137 里的 Infra / context / onboarding / eval / permissions / observability，更接近下一代 MaaS 的差异点。田渊栋的数据 > Infra > 算力 > 算法 ≈ 人才（#195）也修正了对算法壁垒的高估。但算法先发仍有价值，几个月窗口期在高速洗牌里也可能决定生死。

- **FDE 模式要看能否产品化回收**：早期对 FDE 期待较高（#73），但 #129、#130 之后判断要更谨慎。如果赛道碎片化、ROI 密度不够、客户分散，FDE 很容易变成高级乙方。短期好签单，长期难沉淀。

- **泡沫问题要看成本和时间差**：#150 的 a16z 数据可以反驳“AI 完全没需求”，但 #193、#94、#249、#255、#256 说明，真正风险在 capex、现金流、电力和收入兑现节奏。突然盈利也未必代表商业模式更好，可能只是算力采购更保守。

- **企业客户会为稳定吞吐和部署能力付钱**：Guaranteed Capacity、Deployment Company、Bedrock/Trainium、Managed Agents 指向同一件事（#281, #264, #286, #229）：客户会为长期跑得起来的能力付钱，一次 API 调用只是起点。

## 四、接下来值得关注的问题

1. **协议主权之争**：OpenAI 在 Dev Day 为 MCP 引入 `_meta` 扩展域，提高了效率，也偏离了 MCP 原本“所有交互经由 LLM 上下文”的哲学（#67）。开放协议会不会变成封闭生态的护城河，值得继续看。

2. **一方产品的上限与 API 生态的命运**：杨植麟强调模型公司自研应用能实现模型与应用的正向设计（#39），但 Mercury 数据显示横向应用市场还没有定局（#68）。未来未必是一个模型统治一切，也可能是多个专用 Agent 协同（#133）。

3. **Scaling Hypothesis 的下一步验证**：Dario 说七个核心要素从 2017 年至今没变过（#193），RL 阶段也有缩放规律；田渊栋则认为 RL 推理上界可能被预训练锁死（#195）。这两个判断的冲突，可能是未来一年最值得跟踪的技术分歧。

4. **谁能把 capex 转成可持续现金流？** 未来一年不只看谁宣布更大的数据中心，也要看谁能把算力投入转成高毛利、可续费、可解释 ROI 的产品收入（#249, #255, #256）。如果 usage 上涨但单位经济模型说不清，capex story 会先在资本市场被重新定价。
