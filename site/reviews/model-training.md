# 模型能力是怎样训练出来的

**讨论模型训练、推理和测试环境 · 更新至 2026.08**

---

## 核心判断：能力来自一组条件，不是一个参数

> **模型表现同时受数据、预训练、后训练、模型结构、解码策略、推理预算和测试环境影响。讨论“模型变强了”时，需要说明改变了哪些条件，以及提升能否用于新的任务。**

参数量、训练算力和榜单分数都不能单独解释模型能力。预训练决定模型吸收了哪些分布；后训练提高某些策略出现的概率；Attention 和推理系统决定信息怎样保存与计算；reasoning effort 改变模型在一次请求中展开多少搜索和验证；Harness、工具与 Verifier 则影响模型能否获得反馈并修正错误。

同一个 checkpoint 换一档 effort、换一套工具或测试环境，结果和成本都可能不同。反过来，两代模型分数接近，也不代表它们使用了相同的数据、训练路径或推理成本。模型比较的第一步不是挑一个最大数字，而是把比较条件写清楚。

## Scaling law 要连同训练条件一起看

Diogo Almeida 对早期 scaling law 的复盘提供了一个具体争议（#351）。他的判断是，Kaplan 等人的实验让不同尺寸模型训练在近似固定的 Token 数上，并把 learning rate 用 cosine schedule 衰减到零；小模型相对训练充分，大模型更容易 undertrained，曲线也可能过早呈现饱和。Chinchilla 后来用更小模型和更多数据，在相近计算量下超过 Gopher，重新说明模型规模和数据规模需要一起调整。

这不能证明学界已经确认“原始 scaling law 有 bug”。它是一位研究者对实验设计的复盘。#330 对 scaling law 的系统梳理也说明，每条规律都来自特定数据、模型、优化器和评价方法，固定 Token、学习率日程和停止位置都可能改变拟合结果。

数据污染会让能力曲线更难解释。#25 发现，某些看似由 RL 带来的 MATH-500 提升，可能来自预训练阶段见过题目后被重新激活。分数上涨并不能自动区分记忆检索、分布内泛化和分布外迁移。

#409 又提出一个更贴近当前模型研发的作者判断：总参数、激活参数、预训练数据、post-training 环境、训练计算和最终推理成本正在成为联合优化变量。GLM-5.3 在 base model 与主要结构不变时继续扩大长程环境和 RL，Coding/Agent 分数仍有提升；这是一个公司模型迭代案例，不足以建立新的通用 scaling law。它提醒我们，当前模型的能力上限不能只从 base size 推出，哪一项投入边际收益最高会随阶段变化。

## Post-training 已经是一套能力生产系统

后训练容易把“分数提高”和“能力提高”混在一起，因为 reward 既指导训练，也参与评价。rubric-based RL 可以提高模型对评分项的遵循，#274 同时提醒，模型也可能学会迎合 rubric，而没有改善开放任务中的整体质量。teacher、judge 和被训练模型偏差相近时，分数更难解释。

RL 仍有明确价值：它可以提高已有策略的出现概率，训练工具使用、格式遵循和拒绝行为。数学、代码和游戏更容易提供自动验证，科研判断、组织决策与长期产品质量很难快速评分。OpenAI 团队在 ICML 现场交流中把瓶颈概括为高质量、反馈够快的可验证环境（#362）；这是团队口径，不是对所有研究方向的统一结论。

#407 对 2022—2026 年 post-training 演进的访谈整理，把当前系统拆成更清楚的分工：SFT 更多承担 cold start、行为塑形和能力整合；不同领域的 RL 专家负责数学、代码、搜索或工具能力；多教师 on-policy 蒸馏再把 specialist 的能力装回通用模型。每个领域背后还需要自己的数据、环境、reward、Eval、rollout 和 checkpoint。

这说明 post-training 的复杂度已经不只是一套算法 recipe。团队要同时管理教师版本、base、环境、Verifier、训练节奏和模型合并。#407 来自播客访谈与作者整理，不能证明 MOPD 或某种组织方式已经成为统一方案；它揭示的可检查问题是，最终提升依赖哪些专家、环境和评价链路，而不是只写“用了 RL”。

真实工作轨迹也不是天然训练数据。一个项目成功，不代表中间每一步都值得奖励。环境要能重置，结果要能验证，轨迹还要区分有效尝试与偶然通过。模型很少找到成功路径时，问题可能离能力边界太远，也可能是工具、环境或 Verifier 本身有缺陷。

## 能持续执行，不等于会改变研究路线

#416 分析了 PostTrainBench 公开的 1,338 条 post-training Agent 轨迹和 5,111 次验证训练实验。整体上，这些 Agent 能运行大量训练和 Eval，并在论文所覆盖的七个 benchmark 上把 base model 平均表现从 10.4% 提高到 23.0%。但在 3,557 对相邻训练实验里，只有 74 对改变了训练目标、数据来源或阶段结构，约占 2.1%。

不同 Agent 还表现出不同默认路线：Claude Code 轨迹中较多从 full-parameter SFT 开始，Codex CLI 则更常从 PEFT 开始。论文明确指出，这是一项观察性分析，无法分离模型、prompt、接口和 scaffold 的影响。上述比例也只属于 PostTrainBench 的四个 base model、七个 benchmark、20 种 Agent 配置和规定资源预算，不能外推成所有 AutoResearch 系统的固定行为。

研究者加入 Experiment Journal、Skill Library 和独立 Evaluator 后，Agent 在所测任务上的执行、调试和中间结果分析有所改善；但当证据要求更换方法时，主 Agent 仍可能继续搜索原路线的局部变体。这里区分了两种能力：Research Engineer 能把一条 pipeline 跑深，Research Lead 要根据反证停止、换假设或重新分配预算。运行时间长，只能证明执行持续，不能证明形成了完整研究闭环。

这也限定了当前 RSI 讨论。上一轮结果能改变下一轮实验，已经构成一定递归；问题定义、路线选择、Verifier 升级和最终晋级仍需要独立判断。搜索能力增强后，系统也更容易找到评价漏洞，所以自我改进不能只报告最高分，还要保存失败分支、评价版本和改变路线的理由。

## Attention、工具和 effort 解决的是不同问题

近期模型使用越来越多 Attention 缩写，#418 将它们分成三条线。MHA、MQA、GQA、MLA 主要处理 KV 怎样存，目标是减少每个 Token 的缓存成本；GDN、KDA 等线性机制更像维护固定大小的状态，长序列不会让状态无限增长，但早期细节可能在压缩中丢失；DSA、MSA、QSA 等稀疏机制保留历史，只在每一步选择一部分读取。QSA 的公开细节仍不完整，不能把它准确归入某一种实现。

混合结构是一个更稳妥的观察：Kimi K3 使用多数 KDA 加少数 MLA，其他模型也在组合线性、全局或稀疏 Attention。不同机制在解决存储、状态更新和历史检索，不能只凭缩写判断推理质量。模型是否更快、更便宜，还取决于 kernel、Serving Stack、batch、上下文形态和真实任务中的 Token 使用。

工具也不会让模型内部能力失去价值。#408 收录了 Jason Wei 对“小模型 + 工具可以替代大模型”的反思：工具适合查询动态和长尾信息，参数内化的知识则影响延迟、聚合判断和长链路中的稳定性。这是研究者观点，不是已证实的模型规模定律。更实际的结论是，高频且要求低延迟的能力、动态外部信息和复杂任务可以采用不同组合，再用结果和成本决定模型与工具路由。

Reasoning effort 同样不是质量承诺。Opus 5 的 model card 中，多数主流评测由 max 取得最好结果，但 FrontierCode 主集与扩展集在 medium 最高，FrontierBench 则是 xhigh 略高于 max（#374）。差异可能来自统计噪声、overthinking、重复验证、范围膨胀或预算耗尽，现有材料不能锁定一个原因。团队应同时画出成功率、Token、wall-clock、工具轮次和副作用随 effort 的变化，不能把 max 固定为生产默认值。

扩散语言模型也提供了一个反例。#353 的 *Flexibility Trap* 在论文选定的数学和代码设置中发现，任意顺序生成可能把关键逻辑分叉留到后面，反而降低 Pass@k 的推理多样性。它不否定并行解码或结构化填充的价值，只说明生成自由度增加不等于推理能力单调提高。

## 长窗口、长任务和内部机制不能互相替代

长 Context 提供容量，不保证模型保存了正确状态，也不保证能从失败中恢复。EdgeBench 的连续运行实验支持 workspace 与反馈历史对某些长程任务有价值（#354），但比较的是搭载不同 Harness 的完整系统。状态保存、checkpoint 和恢复由“架构与工程”展开；模型比较只需记录窗口、compaction、运行时长和环境是否连续。

内部机制研究也不能代替任务结果。J-space 等研究显示模型内部存在可以被报告和干预的功能表征（#352），#420 又说明可解释性方法仍面临解释器可信度和干预副作用。它们适合帮助诊断假设，不证明模型有意识，也不能保证找到一个表征后就能稳定控制行为。完整讨论放在“AI 安全与影响”。

## 实践工具：模型比较清单

| 字段 | 必须记录的内容 |
| --- | --- |
| 能力主张 | 具体任务、成功定义，以及准备外推到哪里 |
| 数据与预训练 | 模型版本、数据时间边界、潜在污染、总参数与激活参数 |
| Post-training | SFT/RL/蒸馏方法、教师、环境、Verifier、rollout 与版本编排 |
| 推理设置 | 解码策略、effort、Context、compaction、采样次数与停止条件 |
| 运行环境 | Harness、工具、权限、workspace、反馈和恢复是否连续 |
| 成本口径 | Token 单价、总 Token、wall-clock、重试、人工复核与失败成本 |
| 证据强度 | 公开论文、公司实验、榜单、产品日志、访谈或个人体验 |
| 适用边界 | 未覆盖的任务、语言、模态、时间跨度与组织条件 |

这张表用于固定比较口径。若两套结果使用不同 Harness、预算、数据可见性或 Verifier，应先报告差异，再讨论模型能力。

## 哪些证据会改变以上判断

1. 若跨模型族、数据和优化器的大量预注册实验仍得到稳定、可外推的同一能力曲线，训练 recipe 与运行条件在解释结果时可以降低权重。
2. 若 AutoResearch 系统在多类任务中能根据反证稳定更换目标、数据或训练阶段，并由独立 Evaluator 复现收益，当前关于路线锁定的判断应当收缩。
3. 若一种 Attention、工具路由或 effort 设置在不同硬件、任务和成本约束下持续占优，且优势不依赖特定 Harness，可以把本文的条件化比较简化为更直接的默认选择。
