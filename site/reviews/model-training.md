# 模型推理与训练：智能的来源到底是算法、数据还是计算？

**覆盖 91 篇判读 · 2025.05 - 2026.05**

---

## 一、当前正在发生什么

过去一年，模型推理与训练这条线一直绕着一个老问题打转：大模型的能力到底从哪里来？

表面看，话题很多：RL、RLHF、RLVR、GRPO、Scaling Law、推理模型、蒸馏、长上下文、上下文工程。每个话题都有论文，也都有产品叙事。但把材料连起来看，争论其实集中在三个变量上：算法、数据、计算。到底哪一个是当前瓶颈？

我原来更容易被“新训练范式”吸引。跟踪到现在，判断变得保守了很多。RL 很重要，但它很少凭空创造能力；长上下文很重要，但窗口大不等于可用；后训练很重要，但 reward、grader 和 eval 一旦没管好，也会把模型带偏。

4-5 月新增材料把这件事讲得更清楚：模型发布不再只是 checkpoint 的事情。#226 讨论的是训练栈，#287 讲的是 OpenAI 后训练流程，#274 和 #275 讲 reward 与 distillation 的副作用，#263 和 #264 则把 fine-tuning 和部署团队放进同一个商业选择里。模型能力差异越来越像一条链路的差异：数据、训练、评测、reward、部署、反馈，少一段都不稳。

## 二、核心观察与判断

### 洞察 1：数据仍然是推理能力的地基

这是这一年里最稳定的一条判断。

MiniMax 在 #92 里说得很直：Reasoning 能力不来自某个神奇算法，而来自高质量、结构清晰、多样且足够难的训练数据；很多推理 badcase 最后都能追到训练数据里的脏源头。英伟达团队在 #70 里做了对比实验：把推理数据前置到预训练，能带来更持久的优势；预训练阶段更需要多样性，SFT 阶段更需要质量，盲目扩 SFT 数据反而有害。

田渊栋在 #195 中把话说得更狠：RL 推理的上界可能被预训练锁死。RL 能 work，是因为预训练已经给了足够多的思维材料，RL 只是在里面搜索和放大正确路径。如果预训练里根本没有足够的材料，再多 RL 也找不到解法。#81 补了另一个现实问题：真实世界到训练数据之间有多层损耗，现实变成语言，语言变成数字文本，数字文本还要公开可抓取，最后才进训练集。很多“知识”在这条链路上已经失真。

阶跃开源的 87 万条 SFT 数据（#198）和 DeepSeek 的 86 页训练细节（#121）也指向同一个方向：模型能力不是靠“多喂一点”就能堆出来，数据工程的细度已经变成分水岭。

新增材料里，OpenAI 后训练访谈和 MiniMax 10x Team 把“数据工程”讲得更具体（#287, #269）。可训练的数据不是原始行业知识，而是能被评测、能给 reward、能复盘的任务环境。coding 先跑出来，代码数据多只是一个原因，更关键的是它有运行环境、有反馈信号，也有懂任务的人。法律、医疗、金融要追上，缺的往往是“模型 + 领域 + eval/reward”都懂的人。

### 洞察 2：RL 有用，但要先看它到底在奖励什么

#5 的结果一度很反直觉：对 Qwen-Math 这类领域模型，即使用随机奖励或错误标签做 RL，也能提升 MATH-500 分数。但同样方法对 Llama3/OLMo 无效。我当时的理解是，虚假奖励也可能激活模型已有的某些推理模式。

#25 后来的“打假”实验给了更合理的解释：Qwen 底模在预训练中见过 MATH-500 的部分题目，错误答案 RL 只是激活了记忆检索。在干净数据集上，只有准确奖励能稳定提升。这个结论把问题拉回到数据污染：如果评测集和训练集混在一起，基于这个评测得到的 RL 结论都要打折。

OpenAI 的 Jerry Tworek 在 #77 里说：“纯粹的 RL 是不合理的。RL 必须依赖 pre-training 才能成功，pre-training 同样需要 RL 才能成功。”这句话比“RL 是不是新范式”更有用。预训练负责给材料，RL 负责在材料里找路径，两者不是谁替代谁。

5 月的 rubric-based RL 和 OPD 讨论又提醒了另一层风险（#274, #275）：后训练不能只问有没有 reward，还要问 reward 在奖励什么。rubric-based RL 可能把模型训得更会讨好 checklist；on-policy distillation 看起来便宜，但 teacher 和 student 的 reasoning style 不兼容时，会出现 rollout drift、重复前缀和局部奖励失真。后训练更像稳定性工程，不能只看算法名字。

### 洞察 3：开放域推理很难，难在“好坏”不好定义

Noam Brown 在 #19 里提出一个重要方向：推理/RL 不一定局限于有明确奖励函数的任务。只要专家能区分结果好坏，就可能形成反馈闭环。Jason Wei 在 #26 里用“验证不对称性”解释了这个思路：有些任务解起来很难，但验答案相对容易。

ScaleAI 的 #118 把这件事做成了工程方案：用结构化 rubrics 替代黑箱 scalar reward，把 reward 从训练黑箱里拉出来。但这个方案也把难题前移了。rubric 的质量依赖参考答案和强模型，如果强模型既当专家又当 judge，评测口径很容易被训熟。#105 的情感 RL 实验就是这个问题：Gemini-2.5-Pro 既当 teacher 又当 judge，还要调 judging prompt，“模型变好了”和“评测被优化了”就很难分清。

#36 的 CoT 实验也给了一个边界：模型在学过的范围里表现好，不代表它真的理解。一旦任务泛化、长度泛化、格式泛化超出训练范围，就会露馅。#167 用“分子结构”类比解释长链推理的失败模式，这个类比有启发，但我会保留一点怀疑：所谓稳定结构可能很依赖具体任务。

谢赛宁关于 AMI 和世界模型的访谈把问题放到更现实的位置（#279）：下一阶段竞争未必是谁有更多公域 token，而是谁能把真实世界任务改造成 state-action-outcome 的数据闭环。ELF 这类扩散语言模型也在挑战 next-token 路线（#271），但长度、流式、中断、长推理、Agent 行动这些问题还没解决。它值得追，但还不是替代路线。

### 洞察 4：上下文工程正在反过来影响训练和推理

上下文工程已经不再只属于应用层。它也在改变我们怎么看推理成本、训练数据和评测闭环。

#131 拆解 Codex 内部实现时提到一个很小但很关键的细节：prompt caching 只认前缀一致，连 MCP tools 的枚举顺序不稳定都会 cache miss。这说明推理成本不只由模型决定，还由上下文怎么组装决定。长对话也不是无限扩窗口，而是超过阈值后做 auto compaction，把历史理解压到 latent state 里。

#140 用 9,649 次实验把上下文工程的影响量化到模型层面：file-native 架构对前沿模型有加成，对开源模型可能是负收益。紧凑格式看似省空间，但 grep 输出密度高、模式不熟，反而可能吃掉更多运行时 token。这里的教训很朴素：不要把格式当魔法，模型是否能用好这种格式才重要。

#119 的反共识也值得放在训练视角里看：别迷信更大 context window。生产级推理真正难的是 context runtime、failure semantics 和 cost control。并发、工具不稳定、链式失败，这些不是训练一个更长窗口就能解决的。

DeepSeek V4、Anthropic Computer Use 专利和姚顺宇访谈都说明，agent 能力正在把训练问题“环境化”（#254, #262, #265）。工具调用、沙箱、轨迹恢复、UI grounding、操作前后状态、异常反馈，都会变成训练数据和评测的一部分。模型不是孤立变强，它是在更清楚的环境里学会行动。

### 洞察 5：效率竞争从算得快，转向学得值不值

杨植麟在 #39 中提到，高质量数据稀缺时，竞争关键会从计算效率转向 token 效率。Kimi 团队用 Muon 优化器和数据改写策略，在同等数据消耗下拿到接近两倍的智能增益。#162 对国内大模型进化的观察也类似：表面像参数军备竞赛，实际更像 compute-bound 到 data-bound 的切换。

Thinking Machines 的 On-Policy Distillation（#83）是一条值得继续看的中间路线：保留 RL 的“自己学习”特性，同时像 SFT 一样给密集反馈。在数学推理任务上，约 7 万条样本就达到 70% 正确率，比 RL 便宜近十倍。限制也很清楚：依赖强教师，评测范围目前主要还是推理和对话。

#88 的实战反馈提醒我们，benchmark 之外还有一笔账：deepseek R1 又臭又长的 thinking token 会侵蚀性价比，用户最后会用脚投票。Nathan Lambert 在 #168 中的评价更稳：真正的前沿模型需要大规模 RL，RL 的生成成本没法靠蒸馏完全绕开。但“中国模型永远追不上美国前沿”这种判断也太早，Claude Sonnet 追 Opus 的例子已经说明，快速迭代里层级关系会变。

## 三、正在发生的变化与趋势

- **RL 从主角退回链路的一环**：2025 年上半年（#5、#19）对 RL 的期待更高，到 #25、#77、#195 之后，判断收敛了很多。RL 不是无中生有，它更像在预训练已有材料里搜索和放大。

- **大窗口不等于好上下文**：#13 早期让人对千万级 token 很兴奋，但 #131、#140、#190 都说明，可用性取决于 cache、状态管理、工具确定性和模型训练基础。“标称 1M”和“可用 1M”中间有很长一段路。

- **模型能力越来越像系统工程结果**：早期更多谈架构和训练，后来越来越多材料转向上下文管理、工具编排、记忆、harness 和 eval。Devin 团队在 #66 里的问题很典型：不是让它能做事，而是让它知道何时、如何做得更好。

- **定制不一定先改权重**：OpenAI 收缩 self-serve fine-tuning，同时成立 Deployment Company（#263, #264）。普通应用可能先需要场景、数据、上下文组织、工具流程和评测闭环；真正要改权重的需求，会被更重的交付团队接管。

## 四、接下来值得关注的问题

1. **推理模型在非可验证领域的可靠性上限在哪里？** #19 和 #118 给了乐观方向，但 #105 提醒 judge 依赖和评测过拟合会制造“看起来在进步”的幻觉。#122 中 Qwen 负责人说超过 90% 客户不再使用 Thinking 模型，说明速度和成本在真实场景里可能比 reasoning 增益更重要。

2. **预训练数据的低保真问题怎么补？** #81 说模型学到的是世界的残缺投影。#21 引用 jason wei 的观点：科学进步主要依赖实验结果，而不是纯理论智力。如果 AI 的知识长期来自文本而非真实交互，推理上限可能比我们想的低。Ground Truth 谁生产、谁标注、谁验证，会越来越重要。

3. **不同智能阶段是否需要不同基模结构？** 阶跃的经历（#169）说明，L1 时代基模硬扛 L2 Reasoner 任务效率很低。下一个阶段可能需要从基模结构上重新设计，而不是在现有架构上继续叠训练 trick。张祥雨（#24）和杨植麟（#39）对 L1-L5 路径的分歧，值得继续跟。

4. **后训练 reward 会不会变成新的污染源？** 当 rubric、verifier、judge 和 rollout 都进入训练环节，模型可能学到的是迎合裁判，而不是解决任务（#274）。下一阶段需要看 anti-rubric、强裁判组、线上真实反馈和回归集，否则“训练变强”可能只是“更会考这张卷子”。
