# Loop Transformer：模型如何增加内部计算，以及这笔成本由谁承担

整理日期：2026-09-28

Loop Transformer 值得分析师关注，因为模型的参数量、生成的 Token 数和实际消耗的算力，正在变得更难用一个指标概括。同一组参数可以反复执行；两个模型即使用了相同数量的 Token，每个 Token 背后的计算量也可能相差很大。因此，看到模型“更省 Token”以后，还要继续判断：模型减少了多少无效推理，增加了多少内部计算，最终有没有降低完成任务的成本。

**Loop 的直接作用，是复用同一组网络权重，增加生成每个 Token 之前的计算深度。** 相比不断增加独立网络层，循环计算可以减少达到一定计算深度所需的权重存储；相比同一个模型只运行一遍，循环计算又会增加运算量。推理能力能提高多少、总时延能否下降、显存能省多少，都取决于训练方式和具体实现。

本文围绕三个问题展开：Loop 如何影响模型能力；访谈和 HLE-Diamond 数据分别提供了什么信息；这些变化怎样影响 GPU、HBM 和模型服务的经济性。OpenAI 的闭源架构细节均按**受访者说法**处理，公开论文用于解释机制，算例用于展示成本关系，不将访谈中的经验倍数视为通用规律。

## 一、理解 Loop，先分清权重、隐状态和计算深度

### 权重重复使用，处理的中间结果每轮都在变化

语言模型处理文本时，会先把文本切分成 Token。一个 Token 可能是一个字、一个词，也可能只是词的一部分。Embedding 层把 Token 转换成数字向量，后续 Transformer 层继续加工这些向量，输出层再据此计算下一个 Token 的概率。

一个 Transformer 层通常包含注意力和前馈网络等模块。注意力负责从其他可见 Token 中读取相关信息；前馈网络对每个位置的表示继续做非线性变换。后文提到的 MLP（多层感知机）也是一类前馈网络，可以用于特征变换或简单分类。

模型中的两类数字承担不同职责。**权重**是在训练过程中学到的参数，推理时通常保持不变；**隐状态**是模型处理当前输入得到的中间结果，会随着网络层和计算轮次变化。理解 Loop 的关键，就在于不要把两类数字混在一起。

普通 Transformer 通常让隐状态依次经过一组网络层，每一层使用自己的权重。Loop Transformer 则让隐状态经过同一组层之后，再把得到的新隐状态送回循环部分。第二轮使用的仍是第一轮那套权重，但第二轮接收的是已经加工过的输入，因此有机会进一步整合信息、修正判断。

可以用一个仅说明结构的例子理解：普通模型有 40 个独立层，执行一次就是 40 次层计算；循环模型有 20 个独立层，连续执行两轮，同样进行了 40 次层计算，但主体只需存储 20 层权重。Embedding、输出层和控制模块需要另计。

**相同的计算深度不意味着相同的能力。** 40 个独立层可以分别学习不同的变换；20 层循环两次，要求同一组权重适应不同阶段的隐状态。参数共享节省了存储，也约束了网络能够学习的变换方式。能否用较少参数取得接近甚至更好的效果，需要实验，而不能通过“20 × 2 = 40”直接推出。

### Loop 可以循环整段网络，也可以只循环其中一部分

循环架构并没有唯一形态。研究者可以重复一个 Transformer 块、重复一整段网络，也可以保留固定的前处理层和后处理层，只重复中间的计算模块。循环轮数既可以预先固定，也可以根据输入动态分配。

几个公开模型展示了不同的循环方式：

| 模型或研究 | 独立层与循环方式 | 展开后的层计算次数 | 应如何理解 |
|---|---|---:|---|
| Nanbeige4.2-3B | 22 层主体执行两轮 | 44 | 两轮共享主体权重 |
| Ouro-2.6B | 48 层主体执行四轮 | 192 | 相比单轮，计算明显增加 |
| Huginn-3.5B | 前 2 层、中间 4 层循环、后 2 层 | 中间循环 32 轮时为 132 | 只重复中间模块，不重复整个网络 |

这些数字描述的是计算结构，不能横向换算模型能力。[Huginn 论文](https://arxiv.org/abs/2502.05171)用 3.5B 参数模型展示了增加循环计算能够改善部分推理任务；这类研究说明参数规模与推理计算量可以分开扩展，不能据此认定某个 3.5B 模型普遍等价于几十 B 的普通模型。

循环期间权重没有更新，也没有凭空获得外部知识。模型可以更充分地组合已经学到的知识、处理上下文中的信息，因此知识题也可能受益；但反复执行同一组权重，不会自动补足训练时从未学到、上下文又没有提供的事实。

## 二、Loop 与 CoT 的区别：增加内部迭代，还是增加可继续读取的中间文字

### CoT 为什么有效

CoT，即思维链，是模型生成的中间推理文本。模型先写出一个判断，再把已经生成的判断作为后续上下文继续计算。例如，解决一道多约束题时，模型可以先列出条件，再排除不满足条件的候选，最后检查答案。

中间文字有两个作用：生成这些文字需要额外计算；写下的结果又为后续计算提供了可以重新读取的记录。长推理中的列式、分支尝试、错误检查和回溯，都可以利用这种记录。每次继续生成，模型都会结合已有上下文重新运行网络。

需要区分“用户看不见”和“没有生成 Token”。服务商没有展示原始思维链，不代表模型没有生成思维链；隐藏的 reasoning tokens 仍然是 Token。API 是否计入输出用量、如何展示推理摘要，需要按具体接口的统计口径判断。

### Loop 在生成下一个 Token 之前增加计算

Loop 的迭代发生在隐状态上。模型可以先对当前表示运行多轮计算，再决定输出哪个 Token；循环过程不要求把每一轮的中间结果转换成文字。因此，**内部执行三轮网络，不等于多生成三个 reasoning tokens**。

这种机制提供了一种减少显式推理长度的可能：如果一次生成之前已经较好地处理了相关约束，模型可能少写一些重复检查或错误分支。实际效果需要训练支持。将一个没有接受循环训练的普通模型机械地多跑几遍，并不保证答案更好，更不保证思维链更短。

也不能把一层网络理解成一个逻辑步骤。一个逻辑关系可能分散在多层、多组神经元之间；一层也可能并行处理多种特征。因此，不能把网络层数直接换算成能够完成的推理步数。有限的内部计算限制了单次预测的处理能力，而生成中间 Token 为模型提供了额外计算和可回读的状态。

| 比较项 | 延长 CoT | 增加 Loop |
|---|---|---|
| 增加计算的位置 | 多生成一些中间 Token | 对隐状态多执行几轮网络 |
| 中间结果的形式 | 文本形式，可继续放入上下文 | 数字向量，通常没有直接可读的语义 |
| 是否需要改架构 | 一般不需要，但效果依赖训练和推理策略 | 需要参数共享、循环连接及相应训练 |
| 主要成本 | 生成步骤增加，上下文和缓存随序列增长 | 单个 Token 的运算增加，缓存是否增加取决于设计 |
| 典型收益 | 展开长推导、记录候选、检查和回溯 | 在输出之前进一步整合当前信息 |

两种方法可以同时使用：模型既进行内部循环，也生成较长思维链。多候选采样和多 Agent 并行又提供了另一种分配计算的方式。因此，不能将某家公司的路线概括为“只做 Loop”，另一家概括为“只烧 Token”。应该比较同等任务质量下，厂商如何分配内部循环、文本推理和外部搜索的预算。

## 三、Loop、残差与深层训练：增加计算之后，模型如何真正用好计算

### 残差连接让已有表示有一条直接向后传递的路径

标准残差连接可以简化为：

```text
下一层的输入 = 当前表示 + 当前层计算出的更新量
```

网络层学习如何修改已有表示，同时保留一条直接传递当前表示的路径。这种设计也为训练时的梯度提供了更直接的传播通道，有助于优化较深的网络。[ResNet 论文](https://arxiv.org/abs/1512.03385)是理解残差机制的经典来源。

“保留直接路径”并不意味着原始信息永远不会被破坏。多层更新叠加在同一个向量中，仍可能互相干扰；归一化、更新尺度和数值精度也会改变信息的相对强弱。因此，残差改善了深层训练条件，但没有解决所有深度问题。

Loop 和残差可以共存。Loop 决定一组网络层重复执行多少次，残差决定每次执行时新计算与已有表示如何结合。循环块内部通常仍有残差连接，但循环模型不必只有一种残差形式，也不能把循环训练失败全部归因于残差设计。

### Kimi 的 AttnRes 和 DeepSeek 的 mHC，改的是信息传递方式

Kimi K3 的 Attention Residuals（AttnRes）机制，让后续网络层对先前不同深度的表示进行选择性读取。传统残差不断累加更新；AttnRes 则增加了“从哪些历史表示读取、分别读取多少”的选择能力。按块保存表示，可以控制逐层保存全部历史特征带来的开销。

这里的“注意力”容易与常规 Self-Attention 混淆。常规注意力主要在不同 Token 位置之间选择信息，例如读到结论时回看前面的条件；AttnRes 主要在不同网络深度的表示之间选择信息，例如让较深层重新利用较浅层保留的特征。两个机制选择信息的维度不同。

DeepSeek 的 mHC 则扩展残差通道，并对通道之间的混合施加约束，目标是提高信息传递能力，同时控制深层传播中的数值稳定性。AttnRes 的历史表示存储和 mHC 的多通道混合，会产生不同的内存与计算开销，不能统一归纳成“残差改进必然增加同一种通信成本”。

这些改动可以与 Loop 结合，但组合效果需要重新训练和验证。残差改进可能帮助模型利用更深的计算；是否值得增加循环轮数，还要看新增轮次带来的准确率和服务成本。Kimi 材料中的约 2.5 倍 scaling efficiency 是架构、数据等因素的组合结果，不能单独计入 AttnRes 的收益。[Kimi K3 内库解读](<D:/yantao/user/个人C/0625/agent_profile_kit/notes/AI行业扫描_md/377_Kimi_K3_技术报告深度Review_2026-07-27.md>)

### “加深网络”的三个挑战，应该怎样具体理解

增加网络深度以后，模型能否利用新增计算，取决于信息交互、训练数据和梯度传播三个方面。

**第一，后续计算能否形成有用的新表示。** 在具有全局因果注意力的模型中，后面的 Token 在一次注意力计算时，已经可以读取前面的可见 Token。继续加深网络的价值，不一定是“终于能看到更远的位置”，而是对已经获取的信息继续做组合和变换。循环模型第二轮会基于第一轮更新后的表示重新计算，从而有机会处理更复杂的依赖。相反，如果每轮得到的表示都几乎一样，新增计算就没有带来多少任务收益。

**第二，训练任务是否要求模型使用额外深度。** 如果大部分训练样本用浅层计算就能预测正确，多运行几轮也未必产生明显的训练收益。多步依赖、约束冲突、需要纠错的任务，更适合检验额外计算是否有用。不过，不需要为每个隐状态人工标注一句“正确的想法”；最终答案、下一 Token 预测或可验证任务结果，都可能提供训练信号。难点在于让这些信号稳定地奖励有用的迭代，而不是只奖励更长的输出。

**第三，训练误差能否有效地影响早期计算。** 梯度描述参数发生小幅变化时，预测误差会怎样变化，是训练调整权重的依据。训练时，最终预测的误差需要沿计算过程反向传播。循环展开得越长，梯度需要经过的变换越多，可能逐渐变小，也可能被反复放大。共享权重还会同时收到不同循环轮次的更新要求：适合第一轮的变换，不一定适合第五轮。残差、归一化、初始化、梯度裁剪，以及训练时循环轮数的安排，都可能影响稳定性。

还有一个与上线直接相关的问题：模型如何判断继续计算是否值得。即使深层训练稳定，所有请求都跑最大轮数也可能浪费算力；过早停止又可能损失准确率。循环架构需要同时解决“能够继续算”和“知道何时停”。

## 四、访谈中的 OpenAI 方案：部署线索、控制机制与尚未说清的部分

### 从实验到应用，受访者提供了什么信息

受访者把循环深度实验追溯到 o1 时期，称 GPT-5.6 Sol 开始真正引入 Loop 模块，GPT-6 Astra 扩大了使用范围。受访者给出的出发点，是模型继续扩大仍有收益，但权重存储与硬件扩容越来越昂贵，需要通过参数共享提高已有硬件能够承载的能力。

截图中的两句话概括了访谈的核心判断：

> “增加模型有效规模，同时让权重共享和复用。”
>
> “loop 两次到三次是性价比最高的一个平衡点。”

“有效规模”可以理解为受访者对能力收益的概括，不是一项可以直接计量的参数指标。Loop 是否减少存储搬运，也要进一步检查实现条件，不能从这两句话直接推导出 HBM 带宽需求下降。

循环位置的描述存在歧义。受访者先说循环发生在中间推理块，输入和输出部分不参与；追问是否所有 Transformer 层都参与时，又回答“是的”。前一种表述可能指网络中的局部模块，也可能把整个 Transformer 主体统称为中间部分。现有截图不足以确定具体层号，不能据此绘制一张确定的 Astra 架构图。

### 循环控制分成预算分配、运行中停止和服务端约束

**预算分配发生在计算前。** 按访谈说法，输入侧有一个轻量分类头，与主模型共享 Embedding 特征。分类头根据输入特征预测所需循环预算，输出 0、1、2、3 等离散选项。受访者提到的特征包括多步依赖、逻辑分支、校验需求和约束冲突。这里描述的是学习到的难度预测，不能简单理解成逐条匹配人工规则。

**停止判断发生在计算中。** 受访者称，每轮循环后会比较前后隐状态的变化，并结合模型置信度判断是否退出。一个小型 MLP 或线性投影头读取当前隐状态，参与停止决策。余弦相似度可以衡量向量方向是否接近，但不能直接判断答案正确：模型也可能稳定地停在错误表示上。因此，停止机制需要用任务正确率校准阈值，评估提前退出节省的计算是否值得承担错误风险。

**服务端约束决定最多允许算多久。** 如果请求逼近时延承诺，或者系统处于高负载，服务系统可以压低允许的循环预算。受访者用“已经达到 85 分”说明这种取舍；这个数字是口语例子，不代表线上系统可以准确测量每个答案的真实分数。

上述三种判断针对不同问题：预算头预测任务可能需要多少计算；停止头判断继续迭代的收益；服务系统决定当前能提供多少资源。公开的 [Mixture-of-Recursions](https://arxiv.org/abs/2507.10524)也研究了按 Token 分配递归深度和相应的 KV 管理，但不能用公开研究的结构补齐闭源模型尚未披露的细节。

### 轮数和“能力倍数”需要分开读

| 访谈说法 | 能保留的信息 | 不能直接推出的结论 |
|---|---|---|
| 普通问题约 2–3 轮，复杂问题 4–5 轮，基本不超过 6 轮 | 受访者描述了按任务变化的循环预算 | 所有模型、所有请求都采用同一个上限 |
| 路由输出 0–3，“第一轮”硬锁在 3 以内 | 初始预算受到限制 | 0–3 一定代表额外轮数，而非总轮数 |
| 循环 2 轮约对应 1.4–1.5 倍模型的推理表现 | 受访者认为循环具有能力收益 | 能力、参数量和 FLOPs 存在固定换算比例 |
| 3 轮约 1.8 倍，4 轮约 2.2 倍 | 受访者提供了进一步的经验估计 | 收益会稳定地按这条曲线增长 |
| 扩到 3–4 次之后收益下降，并可能训练不稳 | 循环存在边际收益和优化问题 | 第 4 轮必然让所有任务的准确率下降 |

截图没有统一说明“循环次数”是否包含第一遍，也没有解释初始上限怎样与更高轮数衔接。简单任务的“Loop = 0”可能表示跳过额外循环，或跳过某个可选模块，不能理解成完全不经过 Transformer 就能直接回答。

受访者还提到，团队在约 2.6B 的小模型上比较过循环、增加独立层数以及 best-of-n。截图同时出现了挑选最佳表现的描述，但没有完整评测集、训练预算、对照模型和方差。因此，“循环三轮约等于 1.8 倍模型”不足以支持“花三倍算力只得到 1.8 倍能力，所以算力上亏了”的计算。能力分数本来就不是线性量，所谓“对应模型”的训练与推理成本也没有披露。

访谈最有价值的线索，是循环轮数本身成为了需要训练和调度的资源。至于具体最优轮数，应理解为某个模型、某类任务和某种服务约束下的选择。

| GPT-6 Sol | 33.8% | 5k | 43.8% | 20k |
| GPT-5.6 Sol | 31.2% | 4k | 41.6% | 20k |
| Claude Opus 5 | 38.6% | 30k | 41.3% | 24k |

**最直接的观察是，Astra 在图示两个档位都取得最高准确率，同时使用最少的 Token。** 与 Opus 5.5 相比，Astra 在 High 档的用量约为 30%，准确率高 5.6 个百分点；最高档用量约为 29%，准确率高 5 个百分点。GPT-5.6 Sol、GPT-6 Sol 在 High 档也只有约 4k–5k Token，说明图中的低 Token 用量并非 Astra 独有。

Astra 的突出之处，是在较短输出下仍保持较高准确率。Astra 约 3k Token、60.6%，GPT-5.6 Sol 约 4k Token、31.2%，这组数字值得关注，但不能写成“相同预算下能力翻倍”：两者实际用量不同，准确率接近两倍也不意味着通用能力接近两倍。

截图展示的平均用量，还需要配合统计口径理解。各厂商的 High、Max 不代表相同计算预算；不同分词器会影响计数；平均 Token 用量是否覆盖相同样本、是否计入失败和截断请求、是否包含全部 reasoning tokens，都会影响比较。Claude Opus 5 在 High 档的图示 Token 数高于最高档，也需要先检查这些口径，不能直接诊断成训练缺陷。

### 为什么低 Token 与 Loop 相容，却不足以证明 Loop

Loop 增加内部计算后，模型可能用更短的显式推理取得同等结果，因而与 Astra 的表现相容。但至少还有三种解释，也会产生“分数更高、Token 更少”的现象。

一是知识掌握更好或基础能力更强，模型更快找到正确解法，减少试错。二是后训练改变了输出策略，减少重复复述和不必要的自我检查。三是任务执行策略改善，在 Agent 场景中表现为减少无效搜索、失败工具调用和上下文重复。上述变化都不要求采用循环架构。

因此，访谈与评测应分工使用：访谈提出了 OpenAI 可能采用的机制；HLE-Diamond 展示了值得解释的 Token 效率结果。**两者可以形成研究假设，但不能把结果反过来当成闭源架构的证明，更不能据此计算 Loop 贡献了多少提升。** 要识别因果贡献，需要控制模型规模、训练数据、后训练和推理预算，再比较不同循环设置的结果。

将 500 道推理题与 500 道知识题分开，可以进一步判断优势集中在哪类任务；即使优势集中在推理题，也仍可能来自训练配方。外部评测能够描述模型表现，能够识别的内部机制则有限。

## 六、推理成本：权重容量、HBM 带宽和 KV cache 必须分别计算

### 先看 GPU 实际存储和搬运什么

**模型权重**是训练得到的参数，需要在运行模型时可供计算单元访问。**KV cache**是注意力计算保留的历史信息：模型为已经处理过的 Token 计算 Key 和 Value，后续 Token 可以读取这些缓存，避免重新计算全部历史表示。权重在请求之间可以复用，KV cache 通常与请求内容和已经处理的长度有关。

GPU 的 HBM 容量较大，通常存放权重、KV cache 和其他运行数据；片上的 SRAM 缓存容量小得多，但访问更快；寄存器用于计算单元正在处理的数据。计算需要在这些层级之间搬运数据。HBM **容量**决定能放下多少数据，HBM **带宽**决定单位时间能搬运多少数据，两者不能互相替代。

还要区分推理的两个阶段。Prefill 处理输入，可以并行计算多个输入位置；Decode 连续生成输出，后一个 Token 通常依赖前一个 Token。小批量 Decode 容易受权重和 KV 读取速度限制，Prefill 通常具有更高的计算密度。但长上下文、批量大小、注意力结构和并行方式都会改变瓶颈，不能一概认为推理只缺带宽、不缺算力。

### Loop 最确定的节省，是与独立加层相比的权重存储

考虑“20 层执行两轮”这个例子。在层宽、精度和模块结构一致时，循环主体只存一份 20 层权重，少于 40 个独立层；但每次生成仍需要执行 40 次层计算。

| 比较维度 | 与 20 层、只执行一轮相比 | 与 40 个独立层相比 |
|---|---|---|
| 主体权重容量 | 大致相同 | 大约一半 |
| 主体执行次数 | 两倍 | 相同 |
| 主体运算量 | 近似增加一倍 | 可以接近 |
| 各轮分别存 KV 时的缓存规模 | 同等序列长度下近似两倍 | 同等配置下可以接近 |
| 真实时延与吞吐 | 取决于带宽、计算及调度 | 还受并行部署方式影响 |

这张表比较的是结构和资源，不预设三个模型准确率相同。只有在模型质量达到同一要求之后，才适合进一步比较服务成本。

权重变小可以产生实际部署收益，例如让一个模型副本在更少的 GPU 上装下，或为更大的请求批量腾出显存。但如果系统已经被 KV cache、算力或通信限制，减少权重容量未必能等比例减少卡数。增加批量还可能提高排队时间，需要结合服务时延要求判断。

### 权重共享，为什么不自动减少 HBM 读取

假设循环的对象是一整段很大的网络。第一轮执行完以后，第一层的权重未必还留在片上缓存里；第二轮再次使用第一层时，GPU 可能仍需从 HBM 重新读取。虽然 HBM 里只保存一份权重，这一份权重仍然可能被搬运多次。

受访者所说的“减少 HBM 到 register 的反复搬运”，需要特定条件支持，例如计算块足够小、权重能够在片上停留，或者硬件和执行顺序专门为重用做了设计。将整个网络重复执行，与把一个小块连续重复执行，具有不同的数据重用机会，也可能对应不同的模型计算。

较大的片上 SRAM 可能有利于某些循环实现，但不能只凭 Loop 就判断某类芯片一定受益。SRAM 容量、网络权重分布、芯片互连、支持的上下文长度和软件实现都需要一起比较。Cerebras 等方案同样不能仅凭“片上存储”四个字就假定整套前沿模型权重都无需片外访问。

### KV cache 是否增加，取决于循环各轮如何使用历史信息

同一层第二轮接收的隐状态已经变化，即使投影权重相同，得到的 Key、Value 通常也会变化。如果后续 Token 需要分别读取不同循环轮次的历史状态，系统就要为每个轮次保留相应缓存。

在每轮独立保存 KV、注意力结构与精度固定的简化条件下：

```text
KV cache 容量 ∝ 请求批量 × 已处理的 Token 数
              × 需要保存 KV 的层执行次数
              × 每次执行所需的 KV 数据量
```

因此，独立权重少了一半，并不能直接推出缓存少一半。另一方面，也不能断言所有 Loop 模型的 KV 都必然按轮数增长。公开的 Mixture-of-Recursions 研究了选择性缓存和跨轮 KV 共享；这类设计需要同时考察准确率、缓存访问和吞吐，属于额外的架构与系统选择。[论文](https://arxiv.org/abs/2507.10524)

输出缩短能否抵消缓存增加，可以用两个假设场景理解。假设原模型执行一轮，循环模型执行三轮，每轮独立存 KV，二者每层的 KV 配置相同，并且输入和输出都采用同样的循环深度：

- **短输入、长推理：** 原来输入 1k、输出 30k，生成末尾需保留约 31k 个位置的缓存；循环后输入 1k、输出 10k，缓存对应的执行量约为 `3 × 11k = 33k`。输出减少三分之二，末尾缓存仍没有明显下降。
- **长输入、较短输出：** 原来输入 100k、输出 10k，末尾约 110k；循环后输出降至 3k，对应约 `3 × 103k = 309k`。因为输入占绝大多数，缩短输出很难抵消按轮保存缓存的开销。

这些数字只说明方向，不是 Astra 的实际配置，也没有计算运行期间的平均占用。GQA、MLA、滑动窗口、KV 量化和共享方案，都可能显著改变结果。判断长上下文 Agent 成本时，必须知道输入阶段是否循环，以及缓存如何组织。

### 少 Token 不等于少算力，也不一定等于慢

假设原系统生成 30k Token，每个 Token 的计算量记为 1；新系统生成 10k Token，每个 Token 计算量记为 3。仅看这部分输出计算，两者都约为 30k 个单位。新系统减少了生成步骤，但没有减少这部分总运算。

真实总时延还包括输入处理、调度等待、工具调用和网络通信。一个模型即使单 Token 更慢，只要显著减少生成长度、失败重试和工具往返，仍可能更早完成任务。反过来，Token 数减少，也可能被更重的输入处理和内部循环抵消。

Loop 还会增加调度难度。不同请求执行不同轮数，会使批处理中的工作量不均衡；如果循环中包含 MoE 层，每轮可能重新分配专家并产生跨卡通信。参数共享减少的是独立权重数量，不会自动消除专家路由、通信和等待。

### 公开研究怎样检验循环是否值得

仅比较“同一个小模型跑一轮还是两轮”，可以检验额外计算有没有收益，但不能证明循环优于把计算预算用在其他地方。更有解释力的对照，是让不同架构尽量使用相近的训练预算，再比较最终效果。

SMELT 在尽量对齐每 Token FLOPs、非 Embedding 参数量和 KV cache 的条件下，采用中间一半网络层循环两次的方案。论文在最高 54B 非 Embedding 参数的规模内拟合训练规律，估计计算最优条件下可节省约 **6.8%–18.0% 的训练 FLOPs**。这个结果支持“循环可能改善计算资源的分配方式”，比同参数模型多算一遍后分数提高，更接近架构效率的证据；不过，训练 FLOPs 的节省不能直接换算成线上推理费用的下降。[SMELT 论文](https://arxiv.org/abs/2609.01343)

Loopie 也围绕相同训练算力进行对照，报告了循环 MoE 相对普通 Transformer 基线的优势。两项研究提供的增量，是循环的价值开始接受更严格的预算对齐检验；具体收益仍属于各自的模型、任务与训练设置。[Loopie 论文](https://arxiv.org/abs/2607.16051)

## 七、“550B 激活参数上限”应理解为条件性约束

第六张访谈截图同时出现了 550B、10T 和 8–12T，三个数字对应不同对象：

| 数字 | 访谈中的对象 | 对成本的主要影响 |
|---|---|---|
| 550B | 每个 Token 调用的激活参数量 | 单 Token 计算规模；仍需考虑注意力等额外开销 |
| 约 10T | MoE 全部专家等模块的总参数量 | 权重存储和模型部署规模 |
| 8–12T | 训练 Token 数量 | 数据预算与训练工作量 |

MoE 把部分网络划分为多个专家，每个 Token 只激活其中一部分。扩大专家总数可以增加模型容量，而不按相同比例增加每个 Token 调用的参数；但权重需要存放在设备上，Token 也需要被发送到相应专家所在的位置。

受访者描述的约束，是激活参数、网络通信和训练数据预算之间的平衡。当专家分布到更多设备、负载不均衡或通信无法被计算覆盖时，设备会花更多时间等待，实际用于模型运算的效率下降。MFU 通常用于衡量实际模型计算吞吐相对于硬件峰值能力的水平，数值还受到统计口径影响。截图中的 30%、25%、15% 应视为受访者举出的系统表现，缺少拓扑和工作负载信息时不能当作行业常数。

用 `550B × 20 ≈ 11T` 对照 Chinchilla，可以得到与访谈接近的训练 Token 数，但这个算式并不能验证访谈中的规模上限。Chinchilla 研究的是特定设定下参数规模、训练数据与计算预算的匹配，不能把常见的经验比例直接套到超大 MoE 的激活参数上，再据此证明 550B 是普遍上限。训练成本最优也不等于包含长期推理成本后的商业最优。[Chinchilla 论文](https://arxiv.org/abs/2203.15556)

Loop 在这种背景下提供了另一种扩展方式：在不同比例增加独立权重的情况下，继续增加计算。不过，如果当前瓶颈是每轮必须发生的专家通信，增加循环也可能加重瓶颈。评估 Loop 的价值，要具体判断厂商缺的是权重容量、可用计算，还是互连带宽。

## 八、思维链变短后，监控能看见什么

模型输出的原始思维链、API 展示的推理摘要和模型内部隐状态，是三种不同的信息。原始思维链本身也不是内部计算的完整记录；摘要经过进一步整理，信息更少。即使没有 Loop，读到模型解释也不能保证读到了全部决策依据。

OpenAI 的 [Astra System Card](https://deploymentsafety.openai.com/gpt-6-astra)提供了几组相关结果：沙箱逃逸测试中，低 effort 更容易绕过仅看 CoT 的监控，但该测试未出现绕过全上下文监控的成功案例；明确要求隐蔽装弱时，CoT 监控在 WMDP 上召回低于 11%，在 Monorepo-Bench 上为 0，全轨迹监控也存在漏检；数学副任务测试则没有观察到成功隐蔽完成复杂推理。报告将 CoT 可控性的上升主要联系到 RL，未将其归因于架构变化。

这些结果说明，监控效果依赖行为类型和监控可见的信息。越权访问往往会留下工具调用、文件修改或外部通信记录；故意少完成一点工作，则可能与普通能力不足产生相似结果。后者需要依靠独立测试、重复评估和最终产物验收，不能仅检查模型是否在文字里承认了意图。

系统卡还报告了 Astra 和 GPT-5.6 Sol 在无 CoT 数学评测中的任务时长估计，分别约为 30.9 分钟和 3.6 分钟，并提示可能存在数据污染。这是题目难度的时长参照，不是模型在内部运行了这么久，更不是循环次数的测量。

因此，短 CoT、较强的无 CoT 能力和循环架构，应分别分析。Loop 可能增加输出之前的内部计算，但更好的训练也可以提高无 CoT 表现；模型控制表达内容的能力又与训练目标有关。现有结果不足以建立“采用 Loop，所以能够逃过监控”的完整因果关系。

防蒸馏同样不能直接成立。受访者明确表示，防蒸馏不是 Loop 的首要目标；即使不公开完整思维链，其他模型仍可能从答案、工具行为和任务反馈中学习。减少可观察的中间文字可能改变模仿难度，实际壁垒仍需看能否复现任务能力。

## 九、分析师应如何判断 Loop 的商业价值

### 比较模型时，先固定要达到的任务质量

对模型服务采购，应该比较完成同一批任务所需的总费用和总时间。高准确率模型可能减少重试、人工复核和任务拆解，即使 Token 单价较高，也可能更划算。低价模型如果经常失败，额外调用与返工会侵蚀单价优势。

一个便于使用的指标是：

```text
单位成功任务成本 = 同一评测批次的全部相关成本 ÷ 成功完成的任务数
```

成本至少应覆盖输入、输出、reasoning tokens、工具调用和失败重试；如果比较业务收益，还应加入人工处理成本。成功标准和时延要求必须一致，否则分母变化会掩盖质量差异。

### 客户账单与服务商成本，是两张不同的表

客户按 API 价格支付，服务商承担 GPU 运行、内存、通信和调度成本。Loop 可能让单个 Token 包含更多计算，服务商可以通过定价、套餐和请求路由消化这种变化。客户 Token 数下降，并不能直接推出服务商的算力消耗、收入或毛利同步下降。

同样，权重变小可能降低单个副本的部署门槛，但业务调用量增长、上下文增长和更复杂任务又可能扩大总需求。判断 GPU 或 HBM 的产业影响，需要同时估计单位任务资源和任务数量，不能只抓住“参数共享”推导硬件需求下降。

### 外部测试能衡量产品取舍，不能直接还原闭源架构

把推理题与知识题分开，记录成功率、实际 Token 用量、首 Token 延迟、完成时间和费用，可以帮助判断模型的能力与成本特点。长上下文任务则应增加不同输入长度的对照，并把缓存命中、工具等待和失败重试纳入记录。

不过，难题输出更慢不等于采用了动态 Loop；排队、推测解码、批处理、输出内容和隐藏推理都会影响速度。高峰期质量变化也不能直接证明服务商减少循环。外部测试适合回答“这个模型在我的工作负载下是否更好用、更划算”，闭源架构归因仍需要披露或受控实验。

**对 Loop 最有用的判断标准，是同等质量和时延约束下，重复使用参数能否降低完成任务的总资源消耗。** 这个标准同时约束算法和工程：更深的计算必须产生可验证的能力收益，权重存储优势也必须能够在真实推理系统中兑现。
