# Agent Harness会转向自动生成，展望下一代Agent架构设计

**作者**: 孔某人的低维认知
**发布时间**: 2026-04-30 17:31
**原文链接**: https://mp.weixin.qq.com/s/d1aBQMx-JwLh4H8xlyV0OA

---



最近一段时间Harness概念大热，上一代的Context Engineering已经快无人问津了。AI媒体圈就是这么后浪拍前浪。Agent Harness其实要说的话，跟2023年的Agent Framework其实仍然是较为类似的生态位（这里说的不是LangChain和Dify），不过现在是更多为了Long-Horizon Task和目前的模型能力所特化。


之前有个圈内的戏谑但已经成为现实：只要学得够慢，就可以不用学。


以上是目前的状态，但本文想讨论的接下来的未来。

# 1、模型在演变，上层建筑也需要适配


真正做过长时间Prompt/Workflow/Agent产品维护的人都知道，Prompt/workflow的设计随着模型的不断换代，是会过时的。有些的问题只是变得不是最佳方案了，但有些可能会导致新模型的能力不能发挥出来。


那么问题来了，Agent Harness（以及Skill、其他prompt、SOP等）呢？


答案是，也会，没有什么理由能保证不会。如果你需要一个知名品牌的背书才愿意相信，那么可以去看最近 拾象的文章[深度讨论新一轮模型发布：当智能进入月更时代](https://mp.weixin.qq.com/s?__biz=Mzg2OTY0MDk0NQ==&mid=2247523769&idx=1&sn=30ad3042cd0523c0859c0c3dd466d5f9&scene=21#wechat_redirect)


最近的例子就是Opus 4.6升级到Opus 4.7，实际上Opus 4.7并不是一个全方位的提升。一种解释是，Opus 4.7的RL阶段更多使用了类似目前Claude Code的使用范式，也就是主Agent调用子Agent的方式来处理任务。以及从实际使用上来说，如果你仍然按照之前单Agent session的long context方式来使用的话，会发现Opus 4.7变懒了一些，在context较长时候表现很明显。


所以单单一个小版本的模型升级，就可能导致上层的Harness设计要进行调整适配才能保持原有的效果。


那么问题就变成，Harness这个层面，我们攒下的到底是技术资产，还是技术债？

# 2、可积累的方案


一个明显的答案是，如果考虑到模型的迭代进展，特别是在目前这个模型能力在具体方向不能保证不退步的时代，Harness这个层面并不适合作为一个长期积累的资产。它只是当前实现产品效果的手段，而且保质期还不长。


如何获得一个保质期更长的方案呢？一个答案是外包出去，你看中东的国防都可以外包。但很多读者想要自己解决方案。


**那么一个常用的思路就是：提升抽象程度，寻找一个更稳定的抽象层面，然后对它以下的内容进行自动适配/生成。**这在IT领域中不是什么新的想法，Java就是案例，当初的宣传就是“*一次*编写，到处运行”（Write once, run anywhere）。因为每个平台都有自己的特性和汇编语言，想要在一个更稳定的层面进行开发和积累业务逻辑，那么就构建一种稳定的高级编程语言抽象，然后把这之下的部分弄成按需适配，当时没有AI编译器，所以是给每个平台单独编写JIT runtime。


那么Harness之上还有什么更抽象的层面呢？一个答案是：生成Harness的方法论，或者说生成Harness的Harness。


当然这并非万灵药，因为你得能生成接近于原来方案的结果，才算得上是一个更可迁移的替代。否则它只是一个廉价的下位替代方案，当然读过《创新者的窘境》的读者会知道：这也很好了，只是等他成熟需要时间和耐心。


**从Harness变成从高层Harness生成Harness，缺了什么呢？缺的是解决当前问题的****最佳实践****的经验，**这被不少人笼统地称为know-how。这个信息并非不可获得的，如果是一个公开知识比较多的领域，这个know-how很可能已经被模型所知晓，那么就可以期待模型生成Harness时自动关联相关的知识。如果模型不能自主召回，但有公开的信息，也可以依赖于模型进行调研。


那么剩下的场景呢？如果模型的智力强大到能够根据当前场景推理出最佳实践，则也可以，这一般被称为第一性原理思维。


剩下的部分就只能指望用户进行反馈了，对于用户并非该领域专家的场景，产品效果就是退化了。


但所谓的产品效果退化是一个伪问题，大部分用户用不到专家为其定制开发的产品，大部分开发者也不能做到在大部分领域都专业。所以对于通用性产品来说，实际上只要我们比用户已经能使用明白的产品一般交付的效果明显更好就可以了。注意这里是普通用户的使用模式，而不是一些谙熟一些AI产品、Agent特性的专家才能挖掘出的效果。


实际上这个模式曾经出现过。Manus至于ChatGPT，就能对于一般用户交付更好的效果。熟练使用Claude Code的人不用Manus，但大部分人不是。

# 3、绝大多数方案都有窗口期


当然这种方式也不是永生的。


模型厂也可以把这种方式学进去，如果有人做出一个这方面的benchmark并流行，那么模型厂把它训进去的速度就会更快。


但目前来看，Claude Code和Codex都没有开始动这块。我们还有时间，至少是半年，有可能1年。


考虑到这类通用Agent产品已经成了各家模型厂收用户case的关键途径，只要模型厂对应的Agent产品没有实现这点，那么这个窗口期就会持续。


GenAI应用圈，每半年都会打开不同的窗口期，赶上了才能实现提升一个层次。
