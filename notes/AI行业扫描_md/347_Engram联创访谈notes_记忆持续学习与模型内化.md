# Engram 联创 Dan Biderman & Jessy Lin 访谈 Notes：记忆、持续学习与模型内化

来源：[PODSAI《Engram 联创 Dan Biderman & Jessy Lin：记忆与持续学习，AI 的真正瓶颈》](https://podsai.ai/wendao-training-data-engram-memory)

## 一句话总览

这篇访谈的核心问题是：当模型已经足够聪明之后，下一阶段让 AI 真正有用的瓶颈是什么？Engram 的回答不是“更长上下文”或“更强 RAG”，而是 memory 与 continual learning：模型需要持续学习新的、不断变化的 context，并把其中值得保留的部分内化进 weights 或 adapters 中。

Dan Biderman 和 Jessy Lin 的核心判断是，现在很多 AI 产品把所有事情都压到 test-time：写更长 prompt、塞更多 context、做更多检索、反复读取同样文件。但这不是长期最优解。真正的记忆不只是把东西存进数据库，而是让模型像一个在公司工作多年的员工一样，对组织、任务、人员、流程、风格和隐含优先级形成内在直觉。

---

## 最高价值观点清单

### 1. 模型的瓶颈不再只是原始智能，而是理解新 context

Jessy 开场提出，今天模型已经知道很多东西，也足够聪明。但它们真正的瓶颈在于理解新的、不断发展的 context。

这个 context 可以是一个人的工作方式、一个团队的项目历史、一家公司内部的流程、某个 Notion workspace、法律/医疗/金融行业的专属语境，也可以是 agent 在执行任务时不断积累的新信息。

Engram 的核心命题是：这些新 context 不能永远只靠 prompt、RAG、长上下文或工具调用在推理时临时拼起来。更好的方式是把其中值得长期保留的部分训练进模型，让它成为模型的直觉。

### 2. “模型始终在 training”是对 pre-training/post-training 二分法的反叛

Engram 网站上的一句话是：他们不通过 pre-training 或 post-training 的视角看世界，模型始终在 training。

这句话的意思不是模型每秒都在盲目更新 weights，而是他们认为“学习”不应该只发生在基础模型训练阶段或发布前的后训练阶段。模型被部署到真实团队、真实产品、真实工作流之后，仍然应该继续吸收新的训练信号。

这和今天大多数产品形成对比：frontier lab 训练一个通用模型，然后产品团队在模型外面包 prompt、RAG、工具和上下文工程。Engram 认为，用户输入、产品反馈、工作流数据和训练信号应该形成更紧密的闭环。

### 3. 外化记忆有用，但不等于真正的 memory

Dan 用人类记忆做类比：做笔记、贴便签当然有用，人类不会抛弃外部工具。但第二天回到工作时，我们脑子里也会留下某种痕迹，让我们知道事情大概是什么、该往哪里找、接下来应该怎么做。

当前 AI 产品更多依赖外化记忆：保存聊天记录、检索文件、把历史塞进 context window、维护大 prompt。这些方法有价值，但会遇到两个问题：

- 所有个人和组织生成的 tokens 会迅速膨胀到每天千万甚至更多；
- 保存、搜索、重新读取这些 tokens 本身会越来越昂贵，也会让模型困惑。

Engram 的观点是，长期记忆必须包含某种内化过程。

### 4. Engram 不是反对 RAG，而是要解决“什么该内化，什么该外化”

访谈里 Dan 反复强调，他们并不是押注工具、RAG、数据库和外部 memory 会消失。

真正的问题是分层：哪些信息应该留在外部工具里，哪些应该被模型内化？一年前住过某个酒店的房间号，也许不值得进 weights；你家的密码、公司的协作方式、团队长期偏好、某个 workflow 的隐含规则，可能就更值得形成长期记忆。

这也是 Engram 认为最难的问题：不是简单写启发式过滤器，把数据分成“保留/丢弃”，而是让模型像人类一样，在海量噪音中压缩重要信息。

### 5. 他们要把 frontier lab 的训练管线下放到每家公司/团队的 context

Jessy 认为，现在 frontier lab 能让模型精通前沿数学、代码、网络安全等领域，靠的不是简单检索，而是一整套训练管线：数据选择、合成数据、SFT、RL、评估、迭代。

Engram 想做的是把这种能力应用到企业和团队 context 上。比如 Notion、Microsoft、Harvey 这样的 workspace 中，有长期积累的文档、对话、反馈、项目、流程和协作痕迹。Engram 要从这些数据中提取训练信号，让模型真正理解一个团队如何工作。

这不是让模型测试时读一遍文件，而是像一个多年员工一样知道公司项目、流程、招聘方式、写作风格和默认优先级。

### 6. 技术路径更接近 adapters / LoRA / prefix / sparse architectures

Engram 的技术路径不是重新训练一个巨型基础模型，而是在白盒模型上做轻量持续学习。

他们提到的工具包括：

- adapter fine-tuning；
- LoRA；
- prefix tuning；
- 稀疏架构；
- supervised fine-tuning；
- RL；
- on-policy distillation；
- 将原始文档、交互和反馈转化成 training signal。

关键是，他们需要对 weights 有白盒访问权限。开源模型最容易做；闭源模型也不是完全不可能，但需要与拥有 weights 的公司合作。

### 7. 经济账：前期多花训练算力，换取推理时少读 100 倍上下文

主持人问得很直接：是不是先花更多 compute 把公司 context 学进 weights，然后推理时少发 context？

Dan 的回答是，这确实是重要收益之一，而且不是节省 50%，而可能是 100x fewer tokens。

很多涉及人员、团队、组织、优先级的知识，并不在单一文档里。frontier 模型可能需要 10 万 tokens 的 context 才勉强推断出来，而一个已经内化公司 context 的模型，可能用 100 tokens 就能回答。

这说明 Engram 的价值不只是降本，更是把推理从“实时拼装上下文”变成“基于长期直觉做判断”。

### 8. 事实记忆 vs 技能学习，是一个错误二分

主持人提出一个经典问题：模型 weights 中记住大量事实是 feature 还是 bug？模型是不是应该只学抽象能力，把事实留给数据库？

Jessy 和 Dan 的回答很重要：事实和技能很难完全分开。为了进行复杂思考，模型需要内化一些基础事实，否则每一步推理都要先检索，思考就走不远。

人类记忆也不是无损数据库，而是会压缩、遗忘、抽象和建立联系。智能的一部分，就是区分什么重要、什么不重要，并把重要信息压缩成可复用的表征。

### 9. 深度学习的神奇之处，就是数据库和算法被混在一起

Dan 给了一个很有洞察力的类比：传统计算机科学中，数据库和算法是分开的。数据库存储世界事实，算法处理信息。

但深度学习的神奇之处在于，事实、算法、技能、风格、概念都被混合在 weights 里。模型既“知道”事实，也“会”做事。

现在企业 AI 遇到的问题是，公司有自己的 context，而通用模型对这些 context 完全陌生。未来的关键不是重新把数据库和算法完全分开，而是在通用模型和私有 context 之间建立某种融合节奏。

### 10. Continual learning 需要一个类似“做梦”的离线整合阶段

访谈里一个很有意思的类比是“梦”。

Dan 认为，模型不应该只在真实交互发生时思考，也需要从交互中抽离出来，回顾、试验、整合它在某个环境中能做什么、知道什么、哪些长尾情况可能发生。

这和人类做梦不完全相同，但启发在于：学习不只是实时响应，也包括离线消化。今天大多数 AI 产品缺少这个阶段，所有东西都发生在 test time。

### 11. “RAG killer”不是不用检索，而是让很多查询变成本能

Dan 提到，Engram 在某种意义上可能是 RAG killer，但他并不是说永远不做 RAG。

RAG 的问题不只是存什么、放在哪里，而是模型是否知道应该找什么、怎么问、去哪找。很多时候，真正缺的是直觉和联想。

例如模型应该知道一个任务该分发给谁、某个流程通常怎么走、某个团队成员之前做过类似研究。这些知识如果全部依赖搜索，用户必须先把问题问对；但如果进了 weights，模型可以主动联想到。

### 12. 缓存只能解决一部分重复读取，不能替代内化

主持人问：反复读取同样文件的问题，caching 不就解决了吗？

Engram 的回答是：缓存有帮助，但这仍然回到“什么该内化、什么该检索”的问题。缓存可以让模型更快读取同一段内容，但它不一定能让模型基于这些内容建立抽象联系。

Jessy 的例子很直观：员工不会每次搜索“我昨天在做什么”，他们就是知道。公司内部很多反复使用的知识，也应该变成模型直接知道的东西。

### 13. KV cache 很有用，但它把小文本膨胀成巨大的“临时大脑状态”

Dan 特别提到了 KV cache。他说 Engram 起点之一就是对 KV cache 和缓存机制的深入研究。

他的观察是，今天 KV cache 的处理方式非常夸张：一篇 Taylor Swift 的维基百科文章对应的 KV cache，可能在 GPU 上占据 80GB HBM；而一个 70B LLaMA 模型的 weights 大约也就 100GB。

这说明 KV cache 可以保存模型对文本的临时理解，但非常膨胀。Engram 关心的是，能否用离线算力把这种巨大的“脑状态”压缩成小得多的表示，甚至进入 weights/adapters，从而让加载和使用成本下降 1000 倍级别。

### 14. Memory 的 ChatGPT 时刻：一个可被教会并持续变好的实习生

主持人问未来一两年内 memory 领域的 ChatGPT 时刻是什么。

Jessy 的回答是：大家都在等待 continual learning 的第一个清晰 proof of concept。比如你有一个实习生，可以随着时间教它东西，而它真的越来越好。

这个时刻的标志不是“它记住了一条偏好”，而是你会感觉模型和昨天不一样了。你投入的时间真正转化成了性能和质量提升。

### 15. 最大难点之一是不破坏原有能力

Dan 强调，如果模型要实时或持续学习新东西，必须避免 catastrophic forgetting。

也就是说，模型不能因为学习了某个公司流程，就忘记原本的通用能力；不能因为适配个人偏好，就失去基础推理、编程或语言能力。

这也是持续学习长期困难的原因：你既要让模型改变，又要让它以无害、可控、经济上可行的方式改变。

### 16. Engram 和 frontier labs 的分工：一个大模型 vs 每个人/团队自己的模型

Engram 对 frontier lab 的判断很现实：它们的 P0 是 AGI，是更大的模型、更多 pre-training、更多 RL、更多 inference-time compute，以及更强的通用数学、代码和长期任务能力。

Engram 则押注另一个未来：每个人、每个团队、每家公司都可能有自己的模型。这些模型需要学习私有数据、相互冲突的偏好、不同公司的做事方式，以及无法进入公开 post-training 数据集的 context。

这需要新的训练基础设施：不是少数大模型偶尔训练，而是大量小模型、团队模型、个人模型持续训练。

### 17. 记忆需要产品和研究的闭环，而不是模型扔给产品团队

Jessy 认为，在一个模型始终 training 的世界里，研究和产品不能分离。

今天常见模式是研究团队训练模型，然后把模型交给产品团队，产品团队在上面做 prompt 和 context engineering。但如果用户交互本身就是 training signal，产品设计、反馈采集、模型更新、评估和部署必须形成闭环。

这也是 Engram 认为自己不仅是研究公司，也是产品公司的一部分原因。

### 18. 记忆钱包：技能可携带，但 IP 和 context 需要隔离

访谈后段讨论了一个很有意思的问题：未来每个人会不会有自己的 memory wallet，可以带到不同应用和公司？

Jessy 认为需要隔离和控制。个人 context 和工作 context 不应该随便互通，否则会出现隐私、相关性和控制问题。

Dan 提出一个更长期的目标：人在公司工作时产生知识产权留在公司，但个人学到的技能、做事方式、抽象经验可以以清洗后的方式带到下一份工作。这相当于数字世界里的“技能迁移”，类似人类签了 NDA 但仍然带着经验跳槽。

### 19. 5-10 年愿景：数亿个个性化模型成为数据平面的神经接口

Dan 对未来的愿景是，每个人和团队都有真正懂自己的模型。这些模型不只是通用 frontier model 的副本，而是连接各自数据平面的神经接口。

他把这和 Databricks、Oracle 这类数据公司做类比：它们管理 human-readable data；Engram 想形成的是 neural memories，由个性化模型驱动，表征的不是文件系统本身，而是文件系统的“大脑状态”。

这和传统 RAG 很不同：RAG 是查找和拼接文件，Engram 想要的是一种更高效、更联想式、更压缩的模型内表示。

## 与 Tensor Mesh 访谈的连接

这篇和 Tensor Mesh 创始人那期高度相关，但两者关注的是“AI 记忆栈”的不同层。

### 1. 共同问题：test-time context 正在失控

两篇访谈都反对一种粗暴方式：把模型看过、说过、需要知道的一切都塞回上下文，让模型每次重新读。

Tensor Mesh 叫它 token maxing 的野蛮生长：agent 越跑越长，history 越积越多，input token 成本越来越高。Engram 则从产品和组织 context 角度指出，个人和公司生成的 tokens 会达到每天千万级，保存、搜索、重读都会变得昂贵且混乱。

两者的共同判断是：AI 记忆不能长期只靠更长 context window。

### 2. Tensor Mesh 做的是运行时记忆，Engram 做的是长期内化记忆

Tensor Mesh 的对象是 KV cache：模型处理输入后生成的中间状态，是 model-native data。它可以被存储、复用、压缩、迁移、更新，甚至改 attention。

Engram 的对象是 weights/adapters：把公司、团队、个人的长期 context 变成训练信号，写入模型内部，让模型下次不必重新检索或重读。

如果用人类类比：Tensor Mesh 更像短期工作记忆和临时脑状态的高效复用；Engram 更像长期记忆、习惯、直觉和技能的形成。

### 3. 两者都在讲 model-native data，只是位置不同

Tensor Mesh 说 KV cache 是 AI 时代的大数据，因为它是模型自己的中间表征，只有模型能直接理解。

Engram 也在讲类似方向，只是它更关心如何把 workspace 里的 human-readable data，转化成模型内部可用的长期表征。最终结果不是一个更大的文档库，而是 neural memory。

一个在 activations/KV cache 层，一个在 weights/adapters 层。它们都指向同一个趋势：AI 时代的数据基础设施，不会只管理人类可读文档，也会管理模型可读状态。

### 4. 对 RAG 的态度也相似：不是消灭，而是重新分层

Tensor Mesh 不否定外部存储，而是说 KV cache 不能只当黑盒缓存，要理解其语义和复用方式。

Engram 不否定 RAG，而是说 RAG 不能承担全部记忆。检索擅长精确事实、最新数据、原始文件；但联想、直觉、风格、流程、团队偏好、隐含优先级，更适合进入 weights。

两篇放在一起看，可以得到一个更完整的 AI 记忆分层：

- weights/adapters：长期语义、风格、技能、组织直觉；
- KV cache：热上下文、模型临时理解、可复用中间状态；
- RAG/database：精确事实、最新文档、可审计外部知识；
- tools/API：实时动作、动态系统状态；
- context window：当前任务的短期工作区。

### 5. Tensor Mesh 更偏成本/系统优化，Engram 更偏质量/个性化/持续学习

Tensor Mesh 的起点是推理成本、prefill、agent 长上下文、KV cache 存储和分发。它的直接价值包括降本、提速、提高长上下文质量。

Engram 的起点是模型不知道你的组织和个人 context。它的直接价值包括减少重复读上下文、提升个性化质量、让模型随时间变好，并让私有数据变成模型能力。

这两者未来可能不是竞争关系，而是互补关系：频繁复用的短期状态进入 KV cache 层，反复出现且值得长期保留的模式再被训练进 adapters/weights。

### 6. 两篇共同指向一个新市场：AI memory infrastructure

Tensor Mesh 把 KV cache 类比成 AI 时代的大数据；Engram 把 personalized model / neural memory 类比成连接数据平面的新接口。

合起来看，未来的 AI 基础设施可能不只是模型、RAG、向量数据库、agent framework，而会多出一层完整的 memory infrastructure：

- 哪些数据要进入长期记忆？
- 哪些只适合检索？
- 哪些中间状态要缓存？
- 哪些 cache 值得压缩或改写？
- 如何避免遗忘、污染和隐私泄露？
- 如何让个人技能迁移，而公司 IP 不外流？

这正是两篇访谈最强的交汇点。

## 访谈大框架

### 一、从 context engineering 走向 continual learning

现在很多 AI 产品的默认做法是 context engineering：长 prompt、系统提示词、文件检索、多轮对话、agent history、工具调用。

Engram 的判断是，这些会继续存在，但它们不是最终形态。真正强的系统需要把一部分 context 转化为训练信号，在部署后持续更新模型。

这意味着 AI 产品的迭代方式会变化：产品交互不只是服务用户，也是采集模型学习信号；模型更新不只是 lab 内部大训练，而是和真实 workspace 形成持续闭环。

### 二、从通用大模型走向团队/个人模型

Frontier labs 追求越来越强的通用模型，但公司和个人的很多知识是私有的、变化的、相互冲突的。

一家公司的写作风格，另一家公司可能不适用；一个团队的代码流程，另一个团队可能完全不同；个人偏好更是彼此冲突。

所以 Engram 认为未来不会只有一个通用巨型模型，而会出现大量团队模型和个人模型。它们共享基础智能，但拥有不同长期记忆。

### 三、从检索事实走向形成联想

RAG 的强项是查找和引用，但很多工作不是“找到某个文件”这么简单。

比如模型应该主动想到某个同事做过类似研究，知道某个流程应该找哪个团队，理解某个品牌风格，记得某个项目历史。用户不一定知道该搜索什么，模型也不一定能靠关键词找到。

Engram 的目标是让这些联想成为模型本能，而不是每次依靠检索管线临时拼装。

### 四、从外部数据库走向 neural memory

传统数据系统保存的是人类可读数据：文件、表格、日志、文档。AI memory infrastructure 要保存和训练的是模型可用表征。

这不是说文件系统会消失，而是文件系统之外会出现一层“模型对文件系统的脑状态”。它更压缩、更联想式，也更接近模型真正执行任务时需要的内部表征。

Engram 的长期愿景就是成为这种数据平面的神经接口。

## 可复用判断框架

### 1. 判断一段 context 是否应该内化进模型

- 是否长期稳定，而不是每小时变化？
- 是否反复影响任务结果？
- 是否难以通过单一文档准确表达？
- 是否包含风格、流程、偏好、组织结构、隐含优先级？
- 是否需要模型主动联想，而不是用户显式搜索？
- 是否有足够训练信号验证模型真的学会了？

### 2. 判断一段 context 是否更适合留在 RAG/database

- 是否需要精确引用和可审计来源？
- 是否频繁更新？
- 是否是一次性事实，而非长期模式？
- 是否涉及强权限隔离或合规要求？
- 是否用户明确知道要查什么？
- 是否不值得为它消耗训练预算？

### 3. 判断一个 memory 产品是否真正有价值

- 模型是否随着时间真正变好？
- 是否减少了 test-time token 消耗？
- 是否能避免 catastrophic forgetting？
- 是否能区分个人记忆、团队记忆、公司 IP？
- 是否能把产品交互转成可靠 training signal？
- 是否能让用户感觉“它和昨天不一样了”？

### 4. 判断它与 KV cache/RAG/工具层如何配合

- 长期稳定模式进入 weights/adapters；
- 高频热上下文进入 KV cache；
- 精确最新事实留在 RAG/database；
- 动态操作交给 tools/API；
- 当前任务指令保留在 context window。

---

## 反共识与金句

- 让模型更有用的瓶颈，不是原始智能，而是理解新的、不断变化的 context。
- 真正的 memory 不是把所有东西存下来，而是知道什么值得内化、什么应该外化。
- RAG 的限制不只是存储和检索，而是模型是否知道该找什么。
- 事实记忆和技能学习不是完全可分的；复杂思考需要一些事实被内化。
- 当前 AI 产品把太多学习压到 test-time，缺少离线消化和持续学习。
- 如果一个模型能被你教会，并且明天真的比今天更懂你，那会是 memory 的 ChatGPT 时刻。
- KV cache 是有价值的临时脑状态，但可能把很小的文本膨胀成巨大的 HBM 占用。
- 未来不是一个模型懂所有人，而是很多模型理解不同个人、团队和组织。
- 个人记忆和工作记忆需要隔离，但技能迁移可能会成为新的数字资产。
- 未来的数据平面接口，可能不是文件系统或数据库，而是个性化模型形成的 neural memory。

---

## 精简结论

这篇访谈最值得带走的判断是：AI 记忆的核心不只是“存储更多上下文”，而是把正确的 context 转化成模型内部可用的长期表征。

它和 Tensor Mesh 那期放在一起看，会形成一个很清楚的框架：Tensor Mesh 解决模型运行时状态的复用和优化，Engram 解决团队/个人 context 的长期内化和持续学习。一个在 KV cache 层，一个在 weights/adapters 层；一个偏系统和推理成本，一个偏个性化、组织知识和模型质量。

未来高价值的 AI 系统不会只靠更长 context window，而会有分层记忆：长期模式进入 weights，热状态进入 KV cache，精确事实进入 RAG，实时动作交给工具，当前任务留在 context。真正难的不是把所有东西都存下来，而是判断每类信息应该放在哪一层。
