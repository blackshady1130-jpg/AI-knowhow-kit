# 国内一家数据初创公司智能知识CEO访谈 Notes：大模型专家数据创业之路与行业思考

## 一句话总览

这期访谈的核心，是一位资深数据工程师从大厂转向大模型、再进入专家数据创业的完整判断链：大模型是颠覆式创新，模型能力继续向前不只靠算法和算力，也越来越依赖能真实映射人类专家工作分布的高知识密度数据。汪绍阳的创业命题可以概括为一句话：用中国专家生产 frontier data，帮助中国模型持续进步并参与世界 SOTA 竞争。

这期最值得带走的不是“做标注公司”的故事，而是对大模型数据产业的几个底层问题的拆解：什么是真正的高质量数据，为什么蒸馏和合成数据无法替代 expert-in-the-loop，为什么 benchmark 既是考试题也是产业分工标准，为什么模型公司和数据公司会走向分层协作，以及为什么中国要把“教会模型的白领知识收入”留在本土社会。

---

## 最高价值观点清单

### 1. 转向大模型，不只是追风口，而是判断上一代信息服务增长收敛

汪绍阳在 2023 年转向大模型时，已经在数据工程、搜索推荐广告、商业化数据团队等方向积累多年经验。按常规路径，继续留在大厂会更稳：有团队、有影响力、有职业信用、有向上晋升的轨迹。

但他当时做了一个判断：搜索、推荐、广告这一代互联网和移动互联网的信息服务技术，整体增长和变化已经没有那么大；对一个技术和产品从业者来说，个人成长空间和工作意义都在收敛。ChatGPT-4 发布、OpenAI 论文与 researcher 访谈，则让他看到大模型是真正的技术突破。

这个选择不是“AI 很热，所以我要转”，而是“上一代平台的主线进入成熟期，下一代平台的主线刚刚打开”。

### 2. 越资深的人转方向，风险越大

他强调，大方向转变 never easy。对初级工程师来说，转岗相对容易，因为沉没成本低；但工作十年之后再转向一个零经验方向，风险反而更大。

原因在于，资深人在原赛道积累的是一整套职业资产：

- 团队信用；
- 组织影响力；
- 业务结果；
- 管理经验；
- 晋升路径；
- 行业内的声望。

换方向意味着这些资产大部分要重新积累。你过去两三年建立的 credit，不能自动迁移到一个全新赛道。

这也是他对“冒险”的第一层理解：真正的风险不是热血，而是明知自己会损失已有优势，仍然选择进入更有长期意义的前沿变化。

### 3. 转型前要建立“知识结构”，不是只看热闹

汪绍阳在转大模型前做了大量知识储备。他提到的准备包括：

- scaling law；
- agent 的早期范式；
- LangChain 及相关 agent 框架；
- tool use、function call、multi-turn 等交互范式；
- pretrain、post-train、SFT、RL 等训练环节；
- 不同训练阶段各自解决什么问题；
- 数据如何影响模型效果。

这说明他对大模型的进入方式，不是只看产品 demo，而是试图建立一套可工作的技术地图。对想转入 AI 的从业者来说，这一点很重要：真正的转型不是“会用几个工具”，而是知道模型能力背后的训练范式、数据范式和工程范式正在如何变化。

### 4. 创业不是脑子一热，而是三件事同时成立

他对创业动机的描述很朴素：不是“这辈子非得创一次业”，而是深思熟虑后的综合选择。

他给出的底层条件大致是：

- 家庭和个人生活不会垮；
- 这件事对社会有意义；
- 这件事有商业价值。

当这三点同时成立，他选择冒险。

这和很多创业叙事不一样。他没有把创业包装成浪漫的个人英雄主义，而是把它看成一个经过约束条件筛选后的理性风险选择。

### 5. 大模型是颠覆式创新，新机会不一定出现在上一代大厂内部

他引用《创新者的窘境》的逻辑：颠覆式创新往往不是上一代大公司的自然延伸。大公司拥有资源、人才和客户，但也有既有惯性、组织边界、分工体系和文化磨损。

他在大厂做 pretrain 数据、医疗大模型数据时，能接触到非常深的工作，但仍会受到组织分工限制。比如一个团队可能只负责某个训练阶段、某类数据、某个模块，很难横向触摸 pretrain、post-train、RL、coding、math、医疗、法律等多个方向的数据全貌。

创业的吸引力在于：如果你做的是数据基础设施，就可以跨多个模型训练环节和垂直场景，直接触摸不同类型的数据问题。

### 6. 数据创业不是模型创业，创始人能力模型不同

主持人提出一个常见质疑：大模型创业是不是至少要计算机博士、算法 researcher 背景？

汪绍阳的回答很清楚：如果要做基座模型公司，当然需要顶级 researcher、AI 博士、顶会论文和模型训练能力。但他们做的是专家数据公司，不是基座模型公司、行业模型公司，也不是垂直 agent 公司。

数据公司的角色是帮助 researcher 持续获得好数据，推动模型能力前沿。它需要理解训练数据 schema，理解数据能让模型学到什么，也需要模型 taste；但它并不要求创始人亲自写 transformer loss function 或深入 GPU 训练底层细节。

相反，数据工程、互联网产品运营、平台治理、流程管理、专家组织和质量控制，反而更接近这个业务的核心。

### 7. 专家数据平台本质上是一个超大型互联网平台

他把专家数据业务定义为一种 C-to-B 或 B-to-C 的平台型业务：公司要在线组织大量专家标注员，共同完成训练数据生产。美国的大型专家数据平台，专家用户规模已经达到几万、几十万人级别。

这意味着它不是简单项目外包，而是一个重运营的平台：

- 招募各行业专家；
- 做专家培训；
- 定义什么是好数据；
- 管理返修和沟通；
- 设计审核流程；
- 结算和激励专家；
- 按数据品类建立 pipeline；
- 监控标注行为和质量。

因此，团队里既需要懂大模型的人，也需要上一代大型互联网产品运营能力很强的人。这类业务不是纯算法公司，也不是传统外包公司，而是“AI 时代的知识工作平台”。

### 8. 严肃场景的数据质量，不能只做到“差不多”

他创业的重要动机之一，是认为国内严肃场景的数据生产工具和流程还不够成熟。比如医疗大模型要给用户提供用药建议，即使只是普通感冒发烧，训练数据的准确性也不能停留在 95%、99% 这类水平。

在医疗、法律、金融、coding 等场景里，数据质量要追求三个九、四个九，甚至更高。因为模型学到的数据错误，最终会以建议、判断、代码、诊断或决策的方式回到真实世界。

他特别提到标注平台和流程的重要性：从标注员到审核员，从多人投票到时间监控，从插入带标准答案的任务到异常行为识别，工具和流程会直接决定数据质量上限。没有好的基建，就很难稳定产出高质量专家数据。

### 9. 创业公司和大厂的最大区别，是 mission-driven 而不是 OKR-driven

在大厂内部做事，往往要考虑季度 OKR、团队边界、组织汇报、资源审批和可见产出。创业公司则更容易围绕 mission 做深。

他举了 Terminal-Bench 相关数据的例子。他们做这类数据时，关注的不是“是否完成季度 OKR”，而是验证一个更大的命题：中国工程师标注员能不能做出 frontier 级别的数据，并达到美国同类水平。

这背后是两种组织逻辑的差异：

- 大厂逻辑：边界清晰、目标拆分、产出可考核；
- 创业逻辑：目标集中、激励一致、为使命投入到足够深。

这也是他所谓“生产关系决定生产力”的含义：如果团队成员有共同目标和长期激励，组织会更适合做探索性创新。

### 10. 数据需求随训练范式快速变化：从 RLHF 到 RLVR

他对市场认知的一个重要变化，是模型训练范式变了。

早期他们设想做最强的 RLHF 标注系统，把“一个问题、多份答案、哪一个更好”的 preference 数据质量拉到极致。但 DeepSeek R1 之后，市场主流需求快速转向 RLVR，也就是 verifiable result 的强化学习范式。

这带来数据需求变化：

- coding 数据要带 Docker 运行环境；
- 输出结果要能 pass unit test；
- reward 更干净、可验证；
- 开放式问题走向 rubric-based RL；
- 数据平台不仅要做标注，还要支撑运行环境、评测、rubric 构造、流程监控等更多工具。

这说明数据公司不能只做“标注系统”，而要随着训练范式变化，变成更完整的数据生产和评测基础设施。

### 11. 公司的使命：Frontier Data Made in China

汪绍阳把公司的使命说得非常清楚：frontier data made in China，帮助中国模型持续进步，参与世界 SOTA 竞争。

这里有两个层次：

- 技术层：用高质量专家数据推动模型能力前沿；
- 产业层：把 frontier data 的制造能力留在中国；
- 社会层：让中国知识工作者参与模型训练收益分配；
- 国家竞争层：让中国模型不是只跟随，而是参与全球 SOTA 竞争。

这也是为什么他反复强调 expert data，而不是只做蒸馏、合成数据或刷榜数据。因为如果目标只是“跟得上”，捷径可能够用；如果目标是“争第一”，就必须让真实专家进入数据生产闭环。

### 12. 蒸馏未必长期可持续

他把蒸馏拆成几个风险。

第一，蒸馏可能被对抗。强模型提供方可以通过 IP、metadata、query pattern 等特征识别蒸馏 query。一旦识别出来，对方可以降质、投毒或返回受控内容，而蒸馏方未必知道自己学到的是污染数据。

第二，蒸馏天然有损。teacher model 本身是概率机器，会输出错误。尤其在强化学习里，错误 reward 会被放大：该给正反馈时给了负反馈，该给负反馈时给了正反馈，模型可能越学越差。

第三，蒸馏会带来价值观风险。如果直接拿 foreign teacher model 的输出训练自己的模型，而不做正确性和价值观检查，那么模型可能继承不符合本土文化和社会期待的输出倾向。

他的结论不是蒸馏毫无价值，而是：把蒸馏当长期主路径，会在可持续性、正确性和价值观上留下结构性问题。

### 13. 合成数据有价值，但无法替代 expert-in-the-loop

他对软蒸馏和合成数据持中立态度：这是有效的学术方向，也确实能提升模型效果。但如果目标是持续提升模型上限和边界，就仍然需要 expert-in-the-loop。

原因有两个。

第一，合成数据受 teacher model 内部分布限制。模型生成的数据，本质上来自模型自己的分布，不等于真实世界里各行业专家面对的问题分布。要让模型能力映射到人类专家真实工作，必须让专家自己出题、抽样、构造数据。

第二，合成数据可能错误。专家进入闭环，可以把 60% 或 70% 正确率的 synthetic data refine 到 95% 甚至更高。这个质量提升对最终模型能力很关键。

他把 expert data 看成概率论问题：在什么样的人群里，用什么力度抽样，才能反映真实世界任务分布。合成数据解决不了这个根问题。

### 14. Benchmark 像考试题，公开以后就会被刷

他把 benchmark 比作高考题。公开 benchmark 一旦发布，就像提前泄露考卷，模型公司会找到标准答案、训练针对性能力，最后形成过拟合和刷榜。

所以 benchmark 有两个改进方向：

- private benchmark：一部分公开，一部分私有，避免完全泄题；
- rolling benchmark：持续更新题库和评测机制，像每年都有新高考题。

没有 benchmark，业界很难衡量模型能力；但如果 benchmark 太公开、太固定、太小、太容易被刷，它也会误导模型发展。

### 15. 商业公司拿 benchmark 逼模型公司买数据，不是最理想关系

他不太偏好某些数据公司的商业模式：先做一个 benchmark，把各模型分数打得很低，再对模型公司说“你看你不行，要不要买我的数据”。

他认为这容易形成一种“胁迫交易”的感觉。因为作为数据公司，你出的题是否足够高质量、是否代表真实能力，本身还需要验证；如果你用它公开压模型公司，再顺势卖训练数据，双方关系会变得敌对。

他更偏好的方式是 partnership：

- 可以做评估；
- 可以私下告诉模型公司哪里弱；
- 双方共同讨论下一波训练数据如何组织；
- 数据公司和模型公司一起推进 AI 能力边界。

这个观点很反共识，因为 benchmark 营销在行业里很有效，但他更看重长期信任和产业协作。

### 16. 好 benchmark 必须在对的时间定义下一阶段范式

他提到 SWE-Bench、Terminal-Bench 这类案例，认为一个 benchmark 要真正被行业认可，不只是“题难”或“题多”，而是它刚好在模型能力演进的关键节点，衡量了下一阶段最重要的能力。

SWE-Bench 之所以重要，是因为它很好地衡量了模型处理真实 GitHub issue、代码修复和 unit test 的软件工程能力。Terminal-Bench 则契合了 AI agent 在命令行、Linux 虚拟机和 sandbox 里执行任务的新趋势。

因此，benchmark 的真正价值在于：

- 对齐模型能力的下一条主航线；
- 在合适时间出现；
- 有足够高的数据质量；
- 有学术或前沿研究激励，而不是单纯卖数据激励；
- 能让全社会看清模型离“可服务人类”还有多远。

批量制造二流、三流 benchmark 意义不大。经典 benchmark 的稀缺性，本身就是价值来源。

### 17. Benchmark 也是产业分工的桥梁

他提出一个很有洞察的类比：在制造业里，电池、屏幕、零部件之所以可以进入不同整车厂、手机厂，是因为上下游对齐了标准和 benchmark。

大模型产业也是一样。benchmark 能让模型公司和数据公司形成分层协作：

- 数据公司按经典 benchmark 标准构造高质量训练数据；
- 模型公司的 RL pipeline 对齐同样标准；
- 同一类数据可以服务不同模型公司；
- 同一模型公司也可以从不同数据公司采购相同标准的数据。

因此，对中国数据公司来说，更务实的路径不是自创很多不知名 benchmark，而是在最 popular 的 benchmark 上构建更贴近真实分布、更高质量的数据生产能力。

### 18. 高质量数据不是“难数据”，而是高知识密度和真实分布

他认为“高质量数据”这个词已经有被说烂的风险，类似 AGI 一样容易失去清晰定义。

他反对简单把 coding、医疗、法律、金融叫高质量，把自动驾驶、人脸识别、语音采集叫低质量。更准确的区分是：

- 低知识密度数据：培训很短即可完成，比如简单语音采集、基础图像标注；
- 高知识密度数据：需要多年专业训练，比如资深程序员、律师、医生、金融专家才能产出。

但高知识密度也不自动等于高质量。真正高质量的数据，要满足两个核心标准：

- 能拟合人类真实任务分布；
- 数据内在逻辑正确。

如果训练目标本身是刷榜，或者 benchmark 质量很差，那么“训练后涨分”也不能完全证明数据高质量。

### 19. 数据质量还要看过程指标

除了结果指标，他强调过程管理同样重要。

比如一个标注项目里，大多数专家十分钟做一道题，某个标注员三十秒做一道题，那么他的行为数据就可能暴露低质量风险。平台需要通过时间、操作轨迹、返修率、审核结果、标准题命中、异常模式等过程指标，识别不认真或异常标注行为。

这也是他们选择重投入专家社区和行为监控的原因：数据质量不是交付后才检查，而是在生产过程中被持续管理出来的。

### 20. 任务更长、附件更多、rubric 更多，不等于质量更高

他反对一种常见误判：认为 coding 任务跑得越长、epoch 越多、生成题附件越多、说明越长、rubric 越多，数据质量就越高。

他把这类指标称为 metadata，而不是质量本身。

类比人类工作：

- 员工天天加班，不等于更优秀；
- 程序员代码量更大，不等于工作更好；
- KPI 指标更多，可能只是让人迎合指标；
- 标准过多，甚至会瘫痪决策。

真正好的数据，是准确、高效、逻辑清楚，并能帮助模型学到真实能力；不是堆长、堆复杂、堆过程。

### 21. 是否重投专家数据，本质上取决于 mission

为什么他们不把重心放在纯合成数据，而要做更重、更慢、更贵的专家数据？

汪绍阳的回答是：看你的 mission。

如果你的目标只是让模型“可用”、榜单看起来不错、跟得上，那合成数据和蒸馏可能够用。但如果你希望中国模型有竞争 SOTA、竞争第一的心，就绕不开真正的 expert data。

这句话也是整期访谈的精神主轴：数据路线不是纯工程选择，而是使命选择。你 day one 想让模型变成什么样，决定了你愿意为哪类数据付出成本。

### 22. 中国专家数据行业的天花板，受模型公司预算和竞争格局影响

他解释为什么美国 human data 公司能一天给专家发几百万美元，而国内很难出现同等规模。

原因之一是资金量差异。OpenAI、Anthropic 等公司融资和现金储备巨大，即使只把预算的十分之一或二十分之一投到数据上，也是十亿美元级别。国内模型创业公司的估值和现金储备小很多，对上游数据公司的预算自然受限。

原因之二是中国基座模型公司太分散。美国大厂之外，基座模型竞争逐渐集中到 OpenAI、Anthropic 等少数玩家；中国则有智谱、Kimi、DeepSeek、阶跃星辰、MiniMax，以及小米、蚂蚁、美团等更多玩家投入。

在总资金更少、玩家更多的情况下，大家都不敢长期重投专家数据。某家公司如果先花大钱做真 expert data，而竞争对手都靠蒸馏和合成数据快速追榜，它可能还没拉开差距就先被成本拖垮。

### 23. 更少、更强的基座模型公司，反而可能更利于数据行业健康

这个观点有点反直觉，但他认为成立。

专家数据是一条需要时间 ramp up 的产线。它需要稳定需求、长期订单、质量追求和模型公司对真实能力提升的耐心。如果基座模型市场过度分散、价格战严重、大家都追短期榜单，数据公司很难投入长期能力建设。

他用国产 GPU 类比：如果没有上游模型公司的订单支持，国产 GPU 很难独立长大，只会被英伟达倾销。同样，数据行业如果没有模型公司支持，也会被两种东西“倾销”：

- 蒸馏倾销；
- 美国数据公司倾销。

因此，产业链上游的健康集中，可能是下游专家数据能力成长的前提。

### 24. 模型公司不一定适合自己做专家数据

主持人问：既然最终买方是大厂和模型公司，它们为什么不能自己承担专家数据使命？

汪绍阳用电商和物流做类比。淘宝、拼多多、抖音电商并没有因为拥有订单，就把三通一达、顺丰等物流公司全部挤出市场。美团、滴滴这类重运营业务，也不是由腾讯或阿里自己下场替代。

原因在于，专家数据是一个重运营、重组织、需要管理大量知识工作者的独立 business。模型公司擅长训练模型、做算法、做产品，但不一定适合管理几万甚至几十万白领专家。

工业成熟后，分层分工往往更有效：模型公司专注模型，数据公司专注组织专家和生产数据。

### 25. 专家数据也是把知识工作者收入带回中国社会

主持人提出一个很重要的社会视角：如果 frontier data 的制造过程留在中国，本质上也是把“白领教会模型”的这部分收入带回中国社会。

汪绍阳认同这一点。模型变强可能替代一部分白领工作，这件事有人乐观、有人焦虑。但至少在模型发展的早期，如果模型公司的预算能通过数据公司流向中国知识工作者，那么国内白领可以把自己的知识再变现一次。

如果中国模型主要靠蒸馏海外模型追赶，那么中国白领并没有参与模型训练收益分配。这也是他认为专家数据本土化有社会意义的原因。

### 26. AI native 企业会被 harness 工具改变组织形态

在个人 AI 工具使用上，他提到 Claude Code 以及同类 harness 工具，认为这类产品不只是提高个人工作效率，还可能改变公司的组织方式。

他相信未来企业会越来越 AI native：很多协调、自动化、管理和执行工作，都可能被 AI 工具重新组织。对创业公司来说，这不只是“员工用 AI 写代码”，而是公司本身如何围绕 AI 工具设计流程、岗位和协作方式。

这个观点和他做专家数据的创业逻辑一致：AI 不只是产品能力变化，也会改变组织生产关系。

### 27. 他最看重候选人的选择逻辑

面试时，他喜欢问候选人过去职业轨迹是什么，为什么做那些选择，今天为什么选择这家公司。

他想听的是候选人的内在逻辑：是否深思熟虑，是否能解释自己的路径，是否有独立判断，而不是只是被风口推着走。

这和他自己的职业选择形成呼应：从大厂转大模型、从模型数据转专家数据创业，都不是孤立事件，而是一套关于技术周期、个人成长、社会意义和商业机会的连贯判断。

### 28. 值得承担的风险，是参与真正改变社会的前沿创新

他引用 Peter Thiel 和 Sam Altman 常说的观点：不冒险才是人生最大的风险。

但他也补充，这里的冒险不是日常的小赌博，也不是盲目下注。值得承担的风险，是进入前沿科技，参与能改变社会、推动颠覆式创新的事情。

这给“冒险”加了边界：风险本身不值得崇拜，值得承担的是有意义、有长期价值、有社会改变潜力的风险。

## 访谈大框架

## 一、个人转型：从上一代平台成熟期，跳进下一代技术主线

汪绍阳的职业故事，本质上是一个平台迁移中的个人选择问题。

他原本在数据工程和互联网商业化数据领域已经有很深积累。继续留在大厂，路径更确定；转入大模型，意味着经验优势重置、职业信用重建、组织影响力归零。

但他判断，大模型不是上一代互联网业务的小修小补，而是新的颠覆式创新。对一个技术从业者来说，选择下一代主线，长期上限比守住上一代成熟业务更重要。

这个选择的启发是：职业安全感不只来自当前位置，也来自你是否站在未来最重要的问题上。

## 二、创业命题：专家数据是模型能力继续向前的基础设施

这家公司不是做基座模型，而是做专家数据。它的核心假设是：模型继续进步，不能只靠更多参数、更多算力、更多合成数据，也需要真实专家把人类工作中的问题、判断、约束和标准转化为训练数据。

尤其在 coding、医疗、法律、金融等高知识密度领域，模型要学到的不是表层文本，而是专业任务分布和正确逻辑。

专家数据公司要解决的不是“找人标注”这么简单，而是：

- 找到真正专家；
- 设计任务 schema；
- 让专家产出能训练模型的数据；
- 做审核、返修、投票、标准题和行为监控；
- 把数据质量稳定到严肃场景可用；
- 随训练范式变化迭代数据平台。

这让专家数据成为 AI 产业里的基础设施，而不是传统意义上的外包标注。

## 三、技术路线：蒸馏、合成数据和专家数据不是同一层东西

访谈里最有技术判断价值的部分，是他对蒸馏和合成数据的边界分析。

蒸馏可以帮助追赶，但有可持续性风险、正确性风险和价值观风险。合成数据可以提高效率，也能创造复杂任务，但它仍然受 teacher model 分布限制。

专家数据解决的是另一个问题：真实世界的人类专家到底在面对什么样的问题？他们如何判断正确？任务分布是什么？哪些隐性标准无法由模型自己合成出来？

因此，三者的关系可以这样理解：

- 蒸馏：快速追赶已有能力；
- 合成数据：放大数据生成效率；
- 专家数据：锚定真实世界分布和能力上限。

如果目标是短期跟榜，前两者很有吸引力；如果目标是 frontier 和 SOTA，专家数据不可替代。

## 四、评测体系：Benchmark 既是考试题，也是产业标准

他对 benchmark 的看法很完整。

一方面，benchmark 像考试题。公开以后会被刷，固定以后会过拟合，题量太少会误导能力判断，所以需要 private 和 rolling 机制。

另一方面，benchmark 又是产业标准。它让数据公司和模型公司对齐同一个目标，就像汽车电池、手机屏幕有行业标准一样。只有上下游对齐标准，产业链才能分层。

所以，真正好的 benchmark 需要同时满足两件事：

- 在模型能力发展的关键节点定义下一阶段范式；
- 作为产业协作标准，帮助训练数据和模型 pipeline 对齐。

这也是他为什么不认同批量生产二三流 benchmark 来卖数据。benchmark 不是营销素材，而是产业基础设施。

## 五、高质量数据：不是越难越长，而是越真实越正确

这期访谈对“高质量数据”给出了一个相对清晰的定义：能拟合人类真实任务分布，且内在逻辑正确。

它不是简单等于：

- 任务更难；
- 文本更长；
- 附件更多；
- rubric 更多；
- 跑得更久；
- benchmark 分数涨得更快。

这些可能只是 metadata。真正的质量，要看是否服务真实训练目标、是否反映真实专家分布、是否经得起过程管理、是否能在严肃场景中降低错误。

这也是为什么数据公司要投入专家行为监控、过程指标和运营系统。质量不是最后验收出来的，而是在生产过程中被设计出来的。

## 六、产业结构：中国需要把 frontier data 制造能力做出来

这期访谈里有一条很强的产业判断：专家数据不是一个孤立创业机会，而是中国 AI 产业链的一部分。

中国模型公司如果长期依赖蒸馏，就会降低本土专家数据行业的天花板，也会让中国知识工作者错过把专业知识变现给模型训练的机会。与此同时，如果国内基座模型公司过度分散、预算有限、竞争都追短期捷径，专家数据公司也很难长期投入。

因此，中国要做出 frontier data，需要几个条件同时成立：

- 有模型公司愿意追求真实能力，而不只是刷榜；
- 有足够集中的预算支持上游数据产业；
- 有本土专家数据平台组织白领知识工作者；
- 有对齐经典 benchmark 的工程化数据产线；
- 有面向 SOTA 的使命感，而不只是低成本追赶。

这也是 “frontier data made in China” 的真正含义：不只是中国公司做数据，而是中国社会参与模型能力前沿的生产。

## 七、组织判断：重运营业务会自然走向分层分工

模型公司为什么不自己做专家数据？他的答案是产业分工。

就像电商公司拥有订单，但不一定自己做全部物流；平台公司拥有流量，但不一定亲自管理每一个外卖员或司机。专家数据也是类似：它要管理大量白领专家、设计激励、培训、审核、流程、结算和质量体系，本身就是独立业务。

模型公司可以参与、投资或自建部分能力，但长期看，很难把所有重运营环节都内部化。更合理的结构，是模型公司和专业数据公司形成 partnership。

这也解释了为什么数据公司不应该把模型公司当成“被 benchmark 打低分后必须买数据”的对象，而应该把它们当长期共同推进模型边界的伙伴。

## 可直接复用的思考问题

如果用这期访谈的框架分析 AI 数据产业，可以问下面这些问题：

1. 这类数据是低知识密度，还是高知识密度？
2. 数据是否真的映射了人类专家的真实任务分布？
3. 训练目标本身是否正确，还是只是在刷某个榜？
4. benchmark 是经典标准，还是商业公司批量制造的营销工具？
5. benchmark 是否出现在对的时间，并衡量了下一阶段模型主航线？
6. 数据质量是靠结果涨分证明，还是有过程指标持续管理？
7. 任务更长、rubric 更多，是否真的带来更高正确率？
8. 合成数据是否受限于 teacher model 分布？
9. expert-in-the-loop 在哪里提升了正确性和真实分布？
10. 蒸馏路径是否存在对抗识别、投毒、降质和价值观风险？
11. 模型公司是否有足够预算和耐心支持长期 expert data？
12. 这个数据公司是在做短期交付，还是在建设可复用的数据产线？
13. 数据公司和模型公司是敌对交易关系，还是 partnership？
14. 这项业务是否适合模型公司内部做，还是更适合产业分工？
15. 这条数据路线的 mission 是“跟上榜单”，还是“竞争 SOTA”？

## 精简结论

汪绍阳这期访谈的价值，在于把“数据标注”这个容易被低估的行业，重新放回大模型能力演进、产业分工和国家 AI 竞争的框架里。

他的核心判断是：模型继续向前，不能只依赖蒸馏、合成数据和公开 benchmark 刷分。真正决定模型能否进入严肃场景、能否接近人类专家真实工作分布的，是高知识密度、逻辑正确、过程可控、由真实专家参与的数据生产体系。

对中国 AI 产业来说，frontier data made in China 不只是一个商业口号。它意味着把专家知识、白领劳动、模型训练和产业收益连接起来，让中国模型在 SOTA 竞争中不只是追赶别人的输出，而是拥有自己的数据制造能力。
