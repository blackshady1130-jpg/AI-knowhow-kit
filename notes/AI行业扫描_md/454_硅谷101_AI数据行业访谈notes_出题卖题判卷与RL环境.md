## 一页结论

数据公司的产品正在从单条标注结果扩展为一套可供模型学习的工作系统：**任务、原始素材、执行环境、工具、验证器、成功轨迹和与特定模型相匹配的训练配方**。需求从数学、代码等容易验证的领域，向金融、医疗、药物发现、芯片设计和企业工作流延伸时，最难的环节往往是找到合法可用的原始项目，复现真实工作条件，并确认专家交来的任务和答案确实成立。

评测与数据销售既相互促进，也会发生利益冲突。好的 benchmark 能指出模型缺少哪类能力，进而带来训练数据需求；如果评测题、答案或等价变体流入训练集，榜单就失去测量意义。两位嘉宾认可针对有价值的评测改进模型，前提是能力能迁移到隐藏题、相邻任务和真实用户工作，且评测与训练材料保持隔离。

何允中认为，未来数据公司的竞争会越来越像研发竞赛：提前研究新领域，拿到有授权的素材，建立环境和验证机制，再证明数据能提升模型。孙一铀则强调，专家的主观判断远未被充分编码；随着 Agent 从执行进入决策，如何采集并验证复杂决策过程，会比给现成答案打分更难。

## 核心判断

1. **数据需求迁移没有让预训练失效。** 嘉宾描述的是后训练关注点从文本偏好与静态答案，扩展到可验证的 rubric 和 Agent 环境；预训练仍是模型能力的基础。
2. **Rubric 的核心是把专家判断外化。** 专家事先写明评分条件，较弱的模型才有可能据此监督更强的模型。其质量取决于规则能否覆盖真正重要、且允许多种正确解法的结果。
3. **RL 环境是比“题库”更重的交付物。** 它包含初始状态、任务、工具与沙盒、过程记录、奖励或验证方式，还必须防止模型通过捷径骗分。
4. **Rubric 与环境是组合关系。** 程序检查数据库状态、代码测试和资源消耗；人工或模型评分处理文档质量、审美和决策理由。同一任务通常需要多种验证器。
5. **值得训练的 benchmark 有两条路径。** 一类测能跨任务迁移的核心能力；另一类紧贴高价值的实际场景。榜单的知名度不能替代任务价值与测量质量。
6. **评测项目带来数据生意，也带来保密责任。** 出题者知道能力缺口，因此有生产相关训练数据的优势；必须阻断原题、答案及近似复刻进入客户训练集。
7. **长程 Agent 的“真实用户分布”很难直接采集。** 一次任务可能运行数小时，很少有用户会并行试多个模型、完整复核并提交反馈。模型公司仍需内部评测和任务级观察。
8. **小团队的机会先出现在合成环境和垂直领域。** 代码领域开放素材多、工程师熟悉；再往深行业走，版权、商业软件、私有数据库与专家流程成为新的进入门槛。
9. **真正稀缺的数据可能是决策过程。** 专家何时选题、放弃路线、调用资源，往往比最终成果更难重建，也更难设计可靠评分器。
10. **训练数据需要与模型能力匹配。** 难到模型一次也做不对的任务难以提供有效强化学习信号；可解的示范轨迹可以转为 SFT 数据，用于冷启动。
11. **数据公司长期价值来自持续发现新问题。** 合成环境供给增加后，单一品类会被竞争和模型自生数据能力挤压；采购、验证、训练适配与研发速度决定后续优势。
12. **高质量数据首先是可信的。** 专家署名、小时费或漂亮的任务描述都不能证明任务真实；提交者、审阅者与验证器本身需要反作弊设计。

## 一、数据公司现在交付什么

### 从人工标注走到 Agent 训练系统

何允中把近期需求变化拆成三个阶段，但强调它们会并存：

| 数据形态 | 典型内容 | 模型如何使用 | 主要难点 |
| --- | --- | --- | --- |
| 标注与示范 | 分类标签、优质回答、人工操作轨迹 | 预训练、SFT、偏好学习 | 覆盖面、准确性、标注一致性 |
| Rubric | 专家写出的分项要求、扣分点、容错规则 | 让人或模型充当评分者，构造奖励 | 隐性知识如何写清楚；多种合理答案如何评分 |
| RL/Agent 环境 | 任务、初始状态、工具、沙盒、可复位系统和验证器 | Agent 反复尝试，从结果及过程反馈中学习 | 环境真实性、授权、成本、奖励漏洞、训练稳定性 |

数学题可以根据标准答案直接判定；代码题可以运行测试。历史论证、医疗建议、金融分析等有正确约束，却常有多种表达方式。Rubric 的作用是将专家的专业判断转为可执行的评分依据，让较弱的评分模型也有机会监督较强的求解模型。评分细则一旦遗漏关键风险或偏好表面形式，模型就会学习这些偏差。

Agent 开始“动手”后，只看最终文本已不够。例如让它操作数据库，需要核实哪些记录被修改；让它生成文档，需要同时检查文件存在、数值正确和图表是否可用；让它管理软件项目，还要关心测试、回归、耗时与资源消耗。环境中可以同时使用程序检查、rubric、偏好比较与人工抽审。

### 两位嘉宾在 rubric 上的分歧

何允中观察到，静态文本问答的专家 rubric 曾是重要需求；新采购明显转向代码、工具调用和可执行环境。这是对近期市场采购重点的判断。

孙一铀强调另一面：主观或开放式产出的评分体系仍非常薄弱。游戏“好不好玩”、设计“好不好看”、企业决策“做得是否妥当”，很难靠唯一标准答案判断。即使规则不能穷尽全部标准，也可以尝试拆出可检查的部分，再让更强的验证模型或人类处理剩余判断。

双方随后形成共同框架：**任务环境定义 Agent 能做什么，rubric 与其他验证器定义什么结果值得奖励。** 随着被训练模型变强，验证器也需升级；验证依据和验证器的综合能力应足以区分真正完成任务与表面过关。

## 二、ALE 想把什么变成“考试”

孙一铀参与的 Agents’ Last Exam 试图评估具有经济价值、需要多步操作且有可验证结果的专业任务。节目介绍称，公开任务约 150 个，跨 50 多个细分领域，并计划扩展后续版本；项目公开材料还区分更大的完整任务池与对外开放的任务集，不能把两者当作同一数字。

项目的逻辑是先建立职业工作流的任务地图，再让专家提供真实项目、所需文件、执行条件和验收方式。孙一铀以生物学为例：细分工作节点很多，公开 benchmark 覆盖的比例仍很有限。这一覆盖率是他在节目中的粗略研究观察，受到领域分类和评测收录方法影响。

ALE 的关键难题在于每道题能否代表真实工作：

- **成果可复核**：结果有可运行的工件、可检查的状态或有根据的专家标准。
- **过程足够真实**：Agent 需要使用行业常见工具、素材和约束。
- **题目合法可用**：第三方代码、法院材料、医疗记录等需要确认授权与隐私边界。
- **难度保持区分度**：过于简单很快饱和；完全无解则难以诊断改进。
- **允许合理异解**：同一项目可以有不同设计和操作路线。

孙一铀希望评测推动模型从 coding 走向更广的工作领域。这里“刷榜”未必是坏事：若榜单测的是用户需要的工作，优化它可能产生真实能力；若训练只记住题目、测试脚本或某个固定输入，分数增长就无法说明泛化。

## 三、出题与卖题之间的利益边界

何允中概括了评测商业化的自然路径：研究者先发现模型距离某种理想能力的差距，设计 benchmark；模型公司希望缩小差距，于是询问出题团队能否提供相关训练任务。领域理解本身带来供给优势。

这条路径成立的条件是**评测集与训练集分离**。孙一铀提到，他听说有供应商把参与评测的材料拿去出售；节目没有给出可核实的具体案例，应视为他的行业警示。即使不直接出售原题，复制题目结构、答案或评分器漏洞，也会降低评测的独立性。

可以用四个层次判断“刷榜”是否有价值：

1. **题目可信**：任务真实、参考结果正确、评分脚本没有明显缺陷。
2. **材料隔离**：公开题、隐藏题和训练数据有清楚的访问与去重规则。
3. **能力迁移**：训练后的改善能出现在新的任务实例、邻近领域和不同环境。
4. **用户验证**：离线得分与实际任务完成率、人工接管率或用户偏好相符。

何允中给出两类值得投入的评测：测一般认知或执行能力、能带动多个 benchmark 同涨的评测；以及覆盖高价值产品场景、即便能力不通用也能直接改善用户体验的评测。有的评测还可帮助定位 harness 的工具、提示、状态管理问题，而不一定需要继续训练基础模型。

### 榜单选择有路径依赖

节目以 Scale 的 SWE Atlas 为例：代码库问答、重构、测试编写等方向分批发布，先发布的问答部分被聚合榜单采用，随即获得更多关注和训练需求。这个例子说明，某个能力在技术报告里出现得多，可能源于发布时点、榜单选择或模型公司引用，不能直接当作它最有产业价值的证据。Scale 的公开研究页可核对这些评测系列的存在。

## 四、模型公司如何建立自己的“真实分布”

孙一铀认为，综合榜单必须给各类任务加权，权重无法脱离用户与产品目标。聊天类产品曾能依赖人类快速比较两份短回答；长程 Agent 一次执行动辄数小时，用户通常不会同时运行几套系统并完整判卷。实际任务完成率的“标准答案”因此更难收集。

头部模型公司有资源建设内部评测，研究真实用户任务与线上反馈；较小实验室更依赖第三方 benchmark。即使是头部公司，科学发现等新场景也缺少足够用户量，仍须先构造代理任务。何允中预计，成熟场景会逐渐借鉴搜索推荐的 A/B 测试与留存指标；但模型好用、用户爱看、用户增长之间可能有偏差，不能用一个线上指标替代所有能力判断。

**对采购方的启示：** 购买数据之前先明确想改善的是通用模型能力、某个行业工作流、工具系统，还是用户感受；再决定要任务、rubric、示范轨迹、完整环境，或四者组合。

## 五、小团队机会：合成之外还有采购

何允中把数据产品化拆成两步：**采购原材料**，以及**加工成可训练、可验证的任务系统**。

代码领域适合小团队快速造合成环境：开放项目和工具丰富，创业者熟悉工作流，强模型可帮助生成任务、初始状态和测试。但下一批垂直领域的壁垒可能出现在更上游：

- 购买有权使用的私有代码库、游戏源码和视频素材；
- 为芯片设计任务取得商业软件使用权，复现专业设计流程；
- 为 DevOps 搭建可信的云服务模拟器；
- 取得可合法处理的医疗记录、药物发现数据库或行业项目；
- 从专家那里获得任务背后的决策理由和失败过程。

孙一铀举过一项游戏源码采购询价，卖方开出数百万元人民币级报价。它是单次谈判经历，不能视为行业通用价格；但很好地展示了行业进入门槛：原始素材可能昂贵、版权复杂，而且一份源码未必足够覆盖一个职业领域。

**编辑归纳：** 能生成一千个形式相似的沙盒，只证明“造环境”有产能。高价值供给还要解决授权、现实约束、任务分布、验证正确性以及客户模型是否真能从中学到东西。

## 六、数据买回来后，怎样进入训练

何允中描述了几种常见用途：

| 交付内容 | 可用训练方式 | 需要额外确认的事 |
| --- | --- | --- |
| 优质答案、完整操作轨迹 | SFT 或作为冷启动示范 | 轨迹是否正确、适合当前模型、会否教授捷径 |
| Rubric 与专家评分 | 训练评分器、提供 RL 奖励 | 标准是否完整、模型评分是否稳定 |
| 可复位 Agent 环境 | 让模型反复试错并用结果反馈训练 | 奖励是否可被操纵、运行成本是否可接受 |
| 长程研究或“模型训练模型”任务 | 仍在探索的定制方案 | 多日任务如何分配信用、验证真实增益和控制算力 |

评测任务常需要较高难度以区分强模型；训练却需要与**当前模型**相配的难度。如果模型始终无法做对，就难以从成功反馈中学习。供应商有时会根据客户尚未发布的模型筛题，采集该模型的尝试轨迹，再补充人工成功轨迹以便 SFT。这意味着同一任务库给不同客户交付的数据与训练价值会不同。

奖励设计还应考虑过程。Agent 即使完成最终状态，也可能使用过多 token、工具步骤或不合规捷径。何允中提到用强模型对环境进行“红队”测试，主动寻找 reward hacking；这只是质量控制的一环，还需真实任务复核和跨任务泛化验证。

## 七、真正难的质检：专家也会编造工作

孙一铀在 ALE 征集任务时遇到过明显不可靠的提交：有专家为了获得论文署名，使用 Agent 批量生成看似专业的材料，甚至编造并未真实执行的项目。另有提交包含不应公开的私有资料，需要剔除。

这里存在三类不同问题：

- **污染**：模型训练时接触过评测题、答案或同源修复代码。
- **题目缺陷**：任务说明不全、测试脚本过严、参考答案并非唯一正确解。
- **伪造工作流**：提供者根本没有执行任务，却提交貌似可信的成果与过程。

OpenAI 对 SWE-bench Verified 的公开分析指出了评测设计和数据污染问题，说明即使有自动测试的代码任务，分数也需要谨慎解释。对药物、化学或商业决策任务，伪造材料更难发现：另一位专家可能要花一两周才能完整复现，审阅者本身也可能敷衍。

何允中提出的方向是调整激励与证据要求，例如提交完整操作记录、可复算的中间结果和关键决策，而不只提交最终文本。但“录了足够长的视频”本身不是正确性的证明；更可靠的质检应组合来源核验、环境复现、独立专家抽审、对抗尝试和后续训练效果。

**关键机制：** 你奖励提交数量，就可能得到批量提交；奖励署名，就可能得到为署名而造的题；按小时付费，又可能得到拖延。数据质量取决于激励设计能否让真实、可复核的专业工作比造假更值得做。

## 八、模型公司与外部数商的边界

模型公司自己也在做数据、建环境、招专家。何允中认为，外部供应商仍有几种合理位置：

1. **时间优势**：模型研发团队有上线与训练窗口，未必能花数月深入一个陌生行业。
2. **采购优势**：外部团队专门处理版权、行业关系、私有素材和交易。
3. **信任优势**：某些企业可能不愿同时把内部工作流交给其 AI 服务提供方。
4. **研发优势**：供应商可提前投入新任务类型，在模型公司明确采购前验证任务价值。
5. **弹性产能**：实验室无需永久雇用所有领域的专家和环境工程师。

客户仍会担心同一份数据被竞争对手购买。嘉宾提到买断作为一种解决方式；实际还可能涉及排他期、许可范围、衍生数据和评测隔离，需要在交易时说清楚。节目没有提供这些合同的通用标准。

对外部数据公司而言，可持续性取决于能否形成一个研发循环：发现未覆盖工作流，采购合法素材，构建任务与验证，测出对模型有用的增益，再投入下一个领域。单一热门品类会因供给增加、客户内制及模型自己造数据而压缩利润。

## 九、值得关注的反共识观点

### 1. 数据公司更像“外包研究团队”

何允中将 Scale 在行业中的一种作用描述为外部数据研究团队。供应商需要研究模型的学习方式、任务分布、评分器和训练配方，交付物远超过人力标注工时。

### 2. 静态 rubric 热度下降，专业判断的提取却才刚开始

单轮文本评分细则可能逐渐标准化，但企业决策、审美、创意和长期项目评价仍缺少稳定表达。采购需求转向环境，不等于 rubric 技术问题已经解决。

### 3. 榜单之外的评测也可能带来真实需求

某个药物发现、AI tutor 或仓库维护评测即使没有进入热门聚合排名，负责该业务的模型团队也可能长期追踪。可见度与采购价值并不总一致。

### 4. 真实工作流经常通过代码和工具调用实现

孙一铀认为，许多看似非编程任务能够经 API、脚本或专业软件工具完成。这里的“coding”是 Agent 的操作接口，不等于刷 LeetCode。其“95% 以上”是访谈中的个人估计，尚缺统一统计口径。

### 5. 专家数据最贵的部分可能是“当时为何这样决定”

成果文件容易保存，失败路线、取舍依据、资源约束和被排除的选项常常消失。如果 Agent 未来要承担决策任务，训练材料需要重建这些过程，而不仅是正确结果。

### 6. 学术项目和商业数商拥有不同的上游激励

ALE 能用共同研究与论文署名吸引专家，但也因此出现为署名编造任务的问题。商业公司按小时付费，可获得可控产能，却未必请得到最资深、最愿意交出关键项目的人。两种机制都要支付质检成本。

### 7. 数据行业的估值叙事要看持续研发能力

模型迭代会迅速消耗旧题的价值。一次成功采购或一批合成环境难以自动累积成长期利润；行业覆盖、授权资产、验证方法和连续发现下一类任务的组织能力更重要。

### 8. 收购企业获取数据是一种情景，不是已验证的主路线

何允中提到，私募股权或数据公司可能把企业收购与 AI 改造、数据开发结合。这个想法成立还需跨过隐私、合同授权、数据迁移和整合成本。节目没有证明数商大规模并购已成为现实趋势。

## 十、对数据公司与模型公司的实际问题

**数据公司要回答：** 原始数据从哪里来，权利是否清楚？环境能否复位？验证器怎样防作弊？专家动机是否与真实质量一致？任务难度如何适配不同模型？改善能否在隐藏任务与真实工作流复现？一个品类过时后，能否持续开拓下一类？

**模型公司要回答：** 当前瓶颈究竟在模型知识、操作能力、harness 还是产品体验？外采数据相对自建节省多少研发周期？独占性是否必要？训练数据与评测集如何隔离？奖励是否包含任务质量、过程成本与安全约束？上线指标与离线评测不一致时相信哪一种证据？

**投资或行业观察要回答：** 收入来自可复用的产品、可独占的授权资产，还是按项目交付的人力？毛利是否随规模改善？关键客户是否会内制？供应商能否在代码热潮过去后切换到更难采购的行业？

## 最后判断

这场访谈把 AI 数据行业最关键的成本暴露出来：**取得真实专业素材、将经验转成可训练任务、确认验证器可信，并证明模型能把学到的东西迁移到新工作。** 对数据公司而言，持续做成这些环节才可能形成优势。对模型公司而言，采购重点应从“买了多少条数据”转到“哪项能力在独立任务和用户场景中实际改善”。
