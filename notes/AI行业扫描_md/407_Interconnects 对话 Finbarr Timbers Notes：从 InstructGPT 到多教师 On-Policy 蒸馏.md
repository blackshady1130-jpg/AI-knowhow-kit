# Interconnects 对话 Finbarr Timbers Notes：从 InstructGPT 到多教师 On-Policy 蒸馏

> 说明：本文基于 Interconnects 2026 年 6 月 16 日发布的 [Frontier post-training recipe review with Finbarr Timbers](https://www.interconnects.ai/p/frontier-post-training-recipe-review) ASR 转写稿整理。主持人为 Nathan Lambert，嘉宾为当时即将离开 Ai2 的 Finbarr Timbers；两人都参与过 OLMo / Tülu 体系的后训练工作。
>
> 原始 ASR 存在较多专名误识别，文中已将 “post trading” 统一为 post-training，将 “two loop / Tulou” 校正为 Tülu，将 “almost” 校正为 OLMo，将 “Deep Sea” 校正为 DeepSeek，将 “Nematron / Nivatron” 校正为 Nemotron，并将 “on pulse / bond policy” 按上下文还原为 on-policy。关键技术路线另用 [InstructGPT](https://arxiv.org/abs/2203.02155)、[Tülu 3](https://arxiv.org/abs/2411.15124)、[DeepSeek-R1](https://arxiv.org/abs/2501.12948)、[MiMo-V2-Flash](https://arxiv.org/abs/2601.02780)、[MOPD](https://arxiv.org/abs/2606.30406) 和 [Nemotron 3 Ultra](https://arxiv.org/abs/2606.15007) 的公开论文校准。未被论文明确披露的内部流程，均保留为两位对谈者的观察或推测。

## 一句话总览

这期对话最重要的结论是：**后训练已经从一条“先 SFT、再偏好对齐、最后 RL”的线性流水线，演变为一个由领域专家、合成数据、可执行环境、策略蒸馏和多轮反馈共同组成的能力生产系统。**

InstructGPT 时代，核心问题是如何让预训练模型更好地服从人类意图；DeepSeek-R1 之后，核心问题变成如何用大规模 RL 发现和强化推理行为；到 2026 年的多教师 On-Policy 蒸馏，问题又进一步变成：如何让数学、代码、搜索、工具使用、安全等多个专家团队并行爬坡，再把这些局部峰值稳定地压回一个通用模型。

这条演进背后不只是算法替换，还发生了四次权力转移：

1. **监督来源从真人演示和偏好排序，转向合成轨迹、可验证奖励和专家模型。**
2. **SFT 从主要能力注入阶段，逐渐变成冷启动、行为塑形和能力整合接口。**
3. **RL 从最后的对齐步骤，变成决定推理与 Agent 能力上限的主训练阶段。**
4. **recipe 的上限越来越取决于组织能否同时调度数据、环境、算力、专家团队和模型版本。**

因此，整场对话表面在讨论 MOPD，实质上回答的是另一个问题：**当通用模型需要吸收越来越多彼此异质的能力时，后训练怎样从一门算法实验，变成一家 AI Lab 的工业操作系统。**

## 核心技术演进图

| 阶段 | 代表 recipe | 能力来源 | SFT 的角色 | RL / 偏好优化的角色 | 主要瓶颈 |
| --- | --- | --- | --- | --- | --- |
| 2022 | InstructGPT | 人类演示与偏好排序 | 教模型按指令回答 | 用奖励模型和 PPO 对齐人类偏好 | 人类数据成本与奖励模型偏差 |
| 2023-2024 | Llama 2 / Llama 3 | 人类与合成数据、拒绝采样 | 多轮吸收筛选后的高质量答案 | PPO、DPO、奖励模型交替迭代 | recipe 轮次和组织复杂度上升 |
| 2024 | Tülu 3 | 开放数据、偏好数据、可验证任务 | 通用能力与格式学习 | DPO 后接 RLVR | 开放团队的算力和并行组织能力 |
| 2025 | DeepSeek-R1 | 基础模型探索、可验证奖励、拒绝采样 | 冷启动、可读性和通用能力回填 | 大规模 RL 成为能力主轴 | RL 稳定性、奖励与多领域扩展 |
| 2025-2026 | 领域专家 + trace distillation | 多个领域 RL 专家 | 用专家轨迹整合能力 | 最后再做通用 RL 爬坡 | 静态教师轨迹与学生分布不匹配 |
| 2026 | Multi-Teacher On-Policy Distillation | 多个领域教师在学生轨迹上的 token 级监督 | 仍可用于冷启动和教师训练 | 学生 on-policy 采样，教师提供稠密蒸馏信号 | 教师同源性、跨域干扰与版本编排 |

这不是一条旧方法被新方法彻底替代的时间线。真实 recipe 通常会保留多个阶段，只是能力生产的重心发生了变化。

## 最高价值观点清单

### 1. 后训练 recipe 的复杂度，本质上是一张组织结构图

Nathan 对 OLMo 3 的复盘是：团队并非不知道更复杂的方法，而是同时调度 compute、data、训练基础设施和多个研究方向，已经逼近 Ai2 的组织容量。要运行更复杂的 recipe，实际上是在管理一张更复杂的 org chart。

论文通常把流程画成几个方框，却不会画出背后的团队数量、交付依赖、失败重跑和版本管理。现代后训练的难度因此不只在损失函数，还在于组织能否让多个能力团队并行推进，并在同一时间点得到可集成的教师与学生。

### 2. 简单 recipe 可以做出强模型，但不代表它有相同的爬坡上限

Tülu 3 和 OLMo 3 采用相对清晰的 SFT、DPO、RLVR 路线。它有利于复现、研究和小团队执行，也可以得到很强结果。

但 Nathan 认为，把 reasoning 移植进旧 recipe 与围绕大规模 RL 重新设计 recipe，不是同一件事。前者更容易交付，后者更可能随着 post-training compute 增加继续提升。评价 recipe 不能只看当前 checkpoint，还要看它是否允许继续 hill climbing。

### 3. OLMo 3 的“晚”不只是训练慢，而是没有重建能力生产方式

从 DeepSeek-R1 到 OLMo 3 的 reasoning 版本约有九个月。Finbarr 认为这在完整模型周期中不算离谱，Nathan 则认为真正的差距在于 OLMo 3 主要把 reasoning 接入既有 Tülu 式流程，没有重做 R1 风格的 RL-first pipeline。

这是一条重要的研发管理判断：相同的上线时间差，可能来自执行速度，也可能来自架构路线不同。把新能力接到旧流程上，通常更稳，但也可能把旧流程的上限一起继承下来。

### 4. InstructGPT 定义了 RLHF，但它的三个核心部件都在退居二线

InstructGPT 的经典流程是：用人类演示做 SFT；用人类对多个答案的排序训练 reward model；再用 PPO 优化模型。它在 ChatGPT 前后定义了行业对“后训练”的基本理解。

四年后，真人演示不再是主要数据源，合成数据占比大幅上升；偏好数据仍存在，但更多来自模型和规则；reward model 也还在使用，却不再总是唯一的 RL 目标。recipe 没有消失，只是每个模块的权重被重新分配。

### 5. Llama 时代的核心变化，是从一次训练变成多轮工业迭代

Llama 2 和 Llama 3 把 reward model、拒绝采样、SFT、DPO 或 PPO 组合成多轮流程。每一轮用当前模型生成候选，筛选更好的回答，再训练下一轮模型。

从算法名字看，变化似乎有限；从组织运行看，数据生产、模型评估和版本选择都被重复多次。后训练开始从“执行一个方法”转向“维护一条持续更新的数据与模型流水线”。

### 6. Tülu 3 的价值不只是分数，而是把完整 recipe 暴露给研究社区

Tülu 3 公开了 SFT、DPO、RLVR 所需的数据、代码、评估与训练流程。它让开放研究第一次可以较完整地研究哪些阶段有效、哪些阶段失败，以及数据与算法怎样共同作用。

但开放 recipe 的透明度不等于 frontier recipe 的完整镜像。开放团队必须把流程压缩到组织能够稳定执行的范围，这本身就会改变可研究的技术边界。

### 7. DeepSeek-R1 把 RL 从“最后校准”推到了能力发现中心

R1-Zero 展示了无需 SFT 冷启动、直接在 base model 上做大规模 RL，也可以诱发更长推理、自我检查和反思行为。完整 R1 则加入少量 cold-start 数据，解决可读性、语言混杂和早期训练不稳定。

这改变了 SFT 与 RL 的主次关系。SFT 不再承担“把所有正确解法教给模型”，而是把模型送入一个更适合 RL 探索的初始区域。

### 8. R1 不是“纯 RL 神话”，而是一条多轮合成和回灌流水线

完整 R1 包含 cold-start SFT、reasoning RL、拒绝采样生成新 SFT 数据、通用能力数据回填，以及面向全场景的第二轮 RL。R1-Zero 是验证 RL 能力发现的实验，R1 才是面向用户的工业 recipe。

把 R1 简化成“不要 SFT，只做 RL”会误读它的产品化路径。真正的创新是把 RL 放在能力发现中心，再用 SFT 和多阶段训练修复可用性与通用性。

### 9. SFT 正从主训练阶段变成 cold start 与能力接口

InstructGPT 时代，SFT 主要学习人类给出的理想答案。R1 之后，SFT 更常承担三个任务：为 RL 提供稳定起点、约束输出格式和可读性、把专家或旧模型轨迹回灌给新模型。

这不等于 SFT 不重要。相反，它从“模型要学什么”的唯一主角，变成多个训练阶段之间传递行为的接口。SFT 数据与 base model 分布相差越大，后续训练越容易出现粗糙边界。

### 10. DPO 在 frontier recipe 中退潮，不代表它已经失效

DeepSeek-R1 之后，多数公开 frontier recipe 不再把 DPO 作为独立核心阶段，偏好信息被吸收到 RL reward 或其他训练目标中。原因可能是更完整的工业 pipeline 已经在数据和 RL 中处理了大量行为问题。

但两位对谈者都提醒，DPO 对资源有限、需要从强模型输出快速 bootstrap 的团队仍可能有效。方法退潮可能包含技术收敛，也可能包含研究时尚，不能把“顶级实验室没写”直接解释为“算法没有价值”。

### 11. preference loss 能改进的远不止语气与安全

偏好训练看似只是在两个答案中选择一个，实际却可能改善数学、代码和推理策略。一个粒度不高的对比信号，也能推动模型调整整条生成分布。

这说明后训练中的能力和风格并没有清晰边界。安全、格式、推理习惯与任务正确率都通过同一个策略分布表达，偏好信号可能产生比标签定义更广的迁移。

### 12. DPO 的价值与 recipe 的“粗糙程度”有关

如果 SFT 数据主要来自其他强模型，且与当前 base model 的概率分布差距很大，模型会学到能力，也会留下分布边缘和不稳定行为。DPO 可以进一步收紧这些粗糙边界。

如果团队拥有更 on-policy、更连续的合成与 RL 流程，模型已经沿自身分布逐步改善，额外 DPO 的边际收益就可能下降。算法是否有用，取决于它在整条 recipe 中修复什么缺口。

### 13. “蒸馏”至少包含四种不同操作，不能混用

对话中特别强调，蒸馏并不只指从闭源模型复制答案。至少应区分：

1. 从闭源或更强模型采样答案，训练较小学生；
2. 从领域教师生成完整轨迹，再用静态 SFT 学习；
3. 学生在自己的轨迹上运行，由单个教师提供 token 级监督；
4. 多个领域教师按任务路由，在学生轨迹上共同完成能力整合。

这四类方法在数据分布、监督密度、工程成本和可持续性上完全不同。

### 14. 领域专家不是从外部抄答案，而是内部能力分工

2026 风格的 recipe 会先训练数学、代码、搜索、工具使用、安全等 specialist teacher。每个教师都可能拥有自己的 prompts、environment、reward 和多轮 RL 流程。

最终通用模型不需要在同一次 RL 中同时解决所有领域冲突，而是先让专家各自在局部分布上爬到高点，再进行能力整合。这更像一家组织先建立多个专业部门，再解决知识回流问题。

### 15. 多领域 joint RL 容易产生 see-saw effect

把所有领域 prompt 混在一起做一次 RL，看起来最简单，却容易出现某个能力上升、另一个能力下降的跷跷板。不同领域的奖励尺度、轨迹长度、采样难度和梯度方向并不一致。

领域教师将探索阶段解耦，使数学团队不必等待搜索环境，代码团队也不用与安全训练共享每一个决策。但并行训练把复杂度从联合优化转移到了最后的能力整合。

### 16. trace distillation 的问题，是学生只看到教师走过的路

领域教师先生成完整轨迹，学生再用 SFT 模仿，这是 off-policy distillation。它简单、稳定，也能获得明显收益。

但上线时学生会进入自己制造的状态。一旦前面生成的 token 与教师不同，后续上下文就偏离训练数据，形成 exposure bias。学生可能会模仿理想路径，却不会从自己的局部错误中恢复。

### 17. On-Policy 蒸馏的关键，是教师进入学生的状态分布

在 MOPD 中，学生先基于当前策略生成轨迹。系统按领域把这些样本交给对应教师，再用教师在学生实际走过的前缀上的 token 分布，指导学生下一步应该如何调整。

它不是简单地让教师重写一份答案，而是让教师在学生会遇到的状态上提供稠密策略监督。学生因此学习如何改善自己的行为，而不只是在静态数据上复刻教师行为。

### 18. MOPD 的优势首先来自稠密信号

可验证 RL 常在整条轨迹结束后给出一个稀疏分数，例如代码测试是否通过、数学答案是否正确。MOPD 可以在大量 token 位置给出分布差异，告诉学生哪些局部决策偏离教师。

稠密信号提高了样本利用效率，也让教师的推理偏好更细致地传给学生。但它同时增加教师推理成本，并要求教师在学生轨迹上仍能给出可靠判断。

### 19. MOPD 没有替代 RL，而是建立在 RL 专家之上

领域教师通常先通过大规模 RL 获得局部能力。MOPD 负责把这些能力整合进通用学生，也可以与可验证 reward 同时训练。

更准确的关系是：`领域 RL 负责把能力推高，MOPD 负责把多个局部峰值装回一个模型`。把 MOPD 说成“RL 的下一代替代品”会忽略教师能力从何而来。

### 20. MOPD 不是 checkpoint merge

参数平均、task vector 或 model merge 在权重空间合并多个专家；MOPD 在策略空间里学习。系统保留一个学生模型，按 prompt 路由不同教师，并通过训练更新学生。

这使它不必假设多个专家的权重可以直接相加，也更容易处理领域差异。但计算量更大，因为学生要采样，教师还要对学生轨迹运行前向计算。

### 21. 同源教师是 MOPD 的隐含前提

Nemotron 团队披露，如果教师来自差异很大的 SFT 数据和训练 pipeline，直接进行多教师 On-Policy 蒸馏会出现次优结果。不同教师已经形成不同推理习惯和输出分布，学生轨迹对某些教师可能是 out-of-distribution。

所以“拥有更多最强教师”并不自动更好。教师之间以及教师与学生之间需要共享足够接近的行为底座，或额外进行 cross-teacher alignment。

### 22. 最终教师太强，反而可能教不会当前学生

一种看似自然的做法，是先把各领域教师训练到收敛，再一次性蒸馏给通用学生。对话提到的研究与 Nemotron 实践都暗示，师生差距过大时 KL 距离太远，学生难以吸收。

更稳妥的方案可能是渐进蒸馏：教师训练到 250、500、1000 步时，分阶段把能力传给学生，让学生与教师共同上升。这里的关键不是最终 checkpoint，而是保留完整训练历史。

### 23. 多轮 MOPD 说明 checkpoint 历史正在成为训练资产

如果只保存最终专家，团队会失去中间能力和分布的连续路径。多轮迭代需要知道教师怎样成长、学生在哪一阶段开始偏离，以及何时刷新教师。

这使 post-training 的数据资产从“样本库”扩展为 prompt、environment、reward、rollout、教师版本和学生版本组成的状态图。

### 24. MOPD 把跨域耦合从算法问题转成版本编排问题

各领域专家可以并行开发，这是 MOPD 最强的组织优势；但不同团队若使用不同 SFT、基础 checkpoint 或训练节奏，集成时就会出现分布不兼容。

recipe 因此需要统一 base、数据契约、checkpoint 节点、评价口径和交付时间。MOPD 没有消除组织复杂度，而是让复杂度变得更可并行，也更需要中央编排。

### 25. 2026 年的模型并没有全部收敛到 MOPD

访谈比较了几种不使用 MOPD 的公开 recipe。微软的 MAI-Thinking 采取更保守的路线：训练少数较宽的专家，用 trace SFT 合并，再做较长 RL；Kimi K2.5 和 GLM-5 的公开描述更接近 SFT 加分阶段 RL。

这说明 MOPD 是重要候选，而非已被证明唯一正确的终局。on-policy 蒸馏相对 trace distillation 的净增益、额外计算和组织成本，仍缺少充分公开对照。

### 26. “保守 recipe”在新团队中可能是正确策略

一次引入太多新数据、算法、环境和基础设施，很容易让整条 pipeline 在复杂度下崩溃。微软选择少数专家、静态整合和最终 RL，未必达到理论最高上限，却更容易确认每个阶段是否有效。

recipe 设计应先匹配团队的 debugging 能力。无法定位失败的复杂方案，实际价值可能低于上限略低但稳定可运行的方案。

### 27. 论文写法不同，不等于实际 recipe 一定不同

有些报告详细披露温度课程、难度过滤和教师构造；有些只列训练阶段；另一些用十五页描述各领域数据，却较少讨论训练动态。

研究者只能比较公开材料，不能从“论文没有写”推断“团队没有做”。模型 recipe 对比必须区分确认存在、确认不存在和未披露三种状态。

### 28. 相反的温度 schedule，暴露了后训练尚未成为成熟工程学

访谈提到，Kimi K2.5 与 GLM-5 都披露温度调度，却给出相反方向：一方主张先高后低，另一方主张先低后高。无论具体归因如何，这说明超参数结论高度依赖模型、数据和训练阶段。

在缺少统一消融和相同基线时，不能把某个 frontier model 的 recipe 细节提炼成普遍最佳实践。

### 29. 中国实验室更愿意披露细节，不等于可以完整复现

两位对谈者认为，中国模型报告常分享难度课程、温度、专家训练等更细的实施细节。NVIDIA 则公开了大量教师与领域列表，但部分训练动态仍难从表格完全还原。

细节披露提高了研究价值，却仍不等于开放数据、环境、训练日志和中间 checkpoint。透明度应按层次评价，而不是用“有技术报告”概括。

### 30. 后训练能力越依赖环境，开放研究的差距越可能扩大

数学答案和代码测试容易构造 verifier；搜索、网页操作、软件工程和真实业务任务需要可执行环境、状态数据、权限与稳定服务。环境成为 Agentic RL 的新基础设施。

frontier lab 可以购买或内部构建大量环境，开放团队则不仅缺 GPU，还缺可持续运行的世界和任务分布。算法公开并不会自动填平这一差距。

### 31. 单个高保真环境的成本可能达到六位数

Finbarr 分享了一次询价：复制一个类似 DoorDash 的复杂 Web 应用，包含可交互软件和虚构数据，报价约 10 万美元搭建，另加每年约 5 万美元维护；是否含 prompts 并不确定。

这是单一供应商、特定复杂度的访谈口径，不是市场统一价格。但它揭示了环境成本的组成：应用克隆、状态初始化、数据维护、可重复运行和服务稳定，而不只是写几十道题。

### 32. 带有已验证任务和 benchmark 增益的环境，价格会更高

只交付一个软件克隆，客户还不知道应训练什么、如何判断模型变好。若环境同时附带 prompts、verifier，并能证明改善某项能力，它就从软件资产变成训练资产。

价值最大的不是“有一个世界”，而是这个世界能持续生成有难度、可评分、与目标能力相关的轨迹。

### 33. 环境具有比完整 post-training recipe 更强的模块化开放机会

一个小团队很难复刻完整 frontier pipeline，却可能专注做好某个医疗、法律、网页或软件环境。环境天然可并行建设，只要存在合理的授权、奖励与维护机制。

这为开放生态留下了机会：把分散领域团队的环境与 verifier 汇聚起来，再由具备训练能力的开放实验室组合使用。

### 34. 企业未来可能主动发布环境和 benchmark

当通用 Agent 开始替用户访问 DoorDash、法律系统或企业软件，平台方会有动力发布自己的任务、环境或 benchmark，引导模型学会正确使用产品，并证明自家系统上的表现。

这既是训练基础设施，也是一种市场机制。谁定义环境和评价标准，谁就部分定义了“Agent 会不会使用这个行业”。

### 35. 环境独占权会显著抬高成本

环境公司希望把同一资产卖给多个实验室以摊薄开发费用。如果某家实验室要求独占，价格可能从十万美元上升到更高量级。访谈举出的五十万美元是推测性示例，不是已确认成交价。

因此，环境市场会围绕共享、独占、公开发布和数据权利形成不同价格层。开放研究最需要的，往往也是商业上最难免费释放的部分。

### 36. Tinker 式 API 可以降低研究门槛，也会集中研究基础设施

这类 API 把训练集群、rollout、推理和 learner 的复杂性封装起来，让研究者只操作较小的算法接口。对小公司和学术团队，它可以用规模采购价获得大模型 RL，尤其适合无法长期占满大型 MoE 集群的用户。

代价是研究逐渐依赖少数托管平台。即使存在可在自有 GPU 上运行的兼容框架，最便宜、最稳定的实验仍可能集中在商业 API 上，影响开放科学的可审计性与可迁移性。

### 37. RL API 本身可能不是最好的终局生意

两位对谈者给出的商业层级是：单纯卖 compute 的差异化最弱；托管训练 API 可以通过规模采购和软件抽象获得更高利润；长期 inference 流量通常更稳定、市场更大。

因此，训练平台需要把一次性的 fine-tuning 或 RL job 转成持续 Serving。否则它仍接近项目型算力生意，难以获得推理平台的长期收入质量。

### 38. 训练与推理的一致性，是平台锁定也是工程价值

模型在同一平台完成 RL、权重传输、数值适配和 Serving，可以减少训练 checkpoint 上线后的行为偏差，并让客户更快进入生产。

客户理论上仍可拿走权重，实际却会发现模型已经针对特定推理引擎和部署方式调优。这构成合理的工程便利，也构成迁移成本。评估平台时应同时看到两面。

### 39. 训练与推理混合负载，可以改善 GPU 利用率

单个学术团队或初创公司很难让上万张互联 GPU 持续满载。平台可在多个客户之间聚合训练、rollout 和推理需求，平滑峰谷并降低单位成本。

这种经济性解释了为什么小团队可能先用 API，而不是一开始自建完整集群。只有当长期利用率足够高、定制需求足够强时，自建才可能收回基础设施投入。

### 40. pre-training 与 post-training 的算力分配，是实验室最敏感的战略信息之一

外界很难知道一家 lab 把多少 compute、人才和时间投入 pre-training、mid-training、RL、环境或推理。因为这张分配表直接暴露管理层认为下一阶段进步会从哪里出现，也暴露当前最弱的环节。

模型技术报告可以公布算法，却通常不会公布完整资源账。理解一家模型公司的路线，资源分配可能比论文目录更有解释力。

### 41. 开放研究面临一个不健康但真实的均衡：谁拿到算力，谁更容易得出好结果

后训练实验越来越依赖大规模 rollout、多个领域环境和反复 ablation。算力不足的研究者不仅模型更小，连可尝试的假设数量都更少。

这会让研究成果与资源配置高度相关，削弱科学对错误路径的检验。完全开放的 recipe 因而不仅需要代码和论文，还需要能让外部团队实际运行关键实验的 API、数据、教师和中间 checkpoint。

### 42. 职业选择不能只比较薪酬，还要比较能否接触完整反馈链

Finbarr 认为，frontier lab 的高薪并不一定是短期投机，因为它们也提供最强资源和最有挑战的问题。问题在于加入后是否真正参与科学判断，还是只采购数据、提交训练任务并汇报分数。

长期更有价值的能力，是能提出假设、设计实验、解释失败并形成可迁移的结论。资源重要，但仅处在大系统里并不会自动转化为研究所有权。

### 43. 初级研究者最容易高估“错过这一班车”的机会成本

湾区高薪和新实验室融资会制造强烈的紧迫感，让年轻研究者认为不立即加入 frontier lab 就会被永久甩开。但大型团队中的 junior 往往只负责局部工作，未必获得高杠杆责任。

对谈者更鼓励在有 conviction 的方向上持续积累，只要它确实重要且能产生独立判断。短期品牌与长期能力并不总是同一选择。

### 44. 高 conviction 的小研究群体，可能在长期获得更大杠杆

Finbarr 举出阿尔伯塔大学计算扑克团队和 Ai2 长期 NLP 研究者的例子。这些人先在一个不一定处于市场中心的方向上形成极深能力，随后才获得 DeepMind 收购或更大机会。

这个判断不是“不要去大厂”，而是不要把市场当下最拥挤的岗位当作唯一有价值路径。真正稀缺的是形成一套别人无法迅速复制的研究判断。

### 45. 巨额种子轮可能削弱新实验室的路线多样性

当一家新 lab 以数亿乃至十亿美元起步，它必须很快证明结果并支撑高估值。团队规模和资本压力会迫使它训练与主流 frontier lab 相似的通用模型，以避免被竞争对手的侧项目压制。

资金让实验室能做更大实验，也提高了偏离共识的代价。真正独特的路线，可能需要公司愿意拿自己的估值和融资叙事承担风险。

## 五代后训练 Recipe 详解

### 第一代：InstructGPT 的三段式 RLHF

基本流程：

`人类演示 -> SFT 模型 -> 人类偏好排序 -> Reward Model -> PPO`

#### 它解决了什么

预训练模型学习的是下一个 token 概率，并不天然服从用户意图。SFT 用示范告诉模型“一个理想回答长什么样”，偏好排序把难以写成规则的质量压缩进 reward model，PPO 再让模型提高预期奖励。

#### 它留下了什么问题

- 高质量真人演示和偏好排序昂贵；
- reward model 是人类意图的近似代理，可能被模型利用；
- PPO 工程复杂、训练不稳定；
- 一套统一的人类偏好很难覆盖数学、代码和工具使用等异质能力；
- 监督信号主要服务“回答得更合意”，不一定能推动长程推理上限。

#### 历史意义

它把后训练从普通 fine-tuning 变成“行为与目标的优化”。后续方法更换了数据、奖励和算法，但仍在回答同一个问题：怎样让模型概率分布更接近我们真正需要的行为。

### 第二代：Llama 的多轮 RLHF 工厂

简化流程：

`SFT -> Reward Model -> 多候选采样 -> 拒绝采样 / SFT / DPO / PPO -> 更新模型 -> 再采样`

Llama 2 将拒绝采样与 PPO 迭代结合；Llama 3 则用更多轮次、更大规模合成数据、奖励模型筛选和 DPO，持续刷新数据与模型。

#### 关键变化

后训练不再只运行一次。当前模型成为下一轮数据生产者，reward model 成为筛选器，最佳 checkpoint 又成为下一轮起点。真正增长的是迭代次数、数据专业化程度和协作团队数量。

#### 为什么它是一座桥

它仍以 SFT 与偏好优化为主，但已经形成“模型生成数据、数据再训练模型”的循环。DeepSeek-R1 随后把循环中的 RL 从一个步骤提升为中心。

### 第三代：Tülu 3 / OLMo 3 的开放学术 Recipe

训练主干：

`Prompt 与数据策划 -> SFT -> DPO -> RLVR`

#### 优点

- 结构清晰，容易定位每一阶段的增益；
- 数据、代码、评测和 checkpoint 可公开；
- DPO 相对稳定，RLVR 适合数学与代码等可验证任务；
- 小于 frontier lab 的团队也能执行和复现。

#### 上限

它较难同时容纳大量工具环境和领域专家，也未围绕多领域大规模 RL 重新设计能力整合。OLMo 3 可以在这条线上加入 reasoning，却仍受到原有组织与 pipeline 的约束。

#### 对开放研究的意义

完全开放的价值不只是允许下载权重，而是能研究 recipe 如何工作。它牺牲部分工业复杂度，换来科学可见性。

### 第四代：DeepSeek-R1 的 RL-First Recipe

可拆成两条路径：

#### R1-Zero

`Base Model -> 大规模可验证 RL`

它证明强 base model 可以在结果奖励下自己发展出更长推理、验证和回看行为。但输出可读性、语言一致性和产品体验不足。

#### 完整 R1

`少量 long-CoT cold-start SFT -> reasoning RL -> 拒绝采样生成新 SFT 数据 + 通用数据 -> 再训练 base -> 全场景 RL`

#### 核心迁移

- SFT 负责启动和修复；
- RL 负责发现与提升推理策略；
- 当前模型输出成为下一阶段数据；
- reasoning 与 non-reasoning 数据在后段重新合并；
- 后训练 compute 可以持续换取能力，而不只做偏好校准。

### 第五代：领域专家与 Multi-Teacher On-Policy Distillation

基本流程：

1. 从共同 base 或中间模型出发；
2. 在数学、代码、搜索、Agent、安全等领域分别训练 RL teachers；
3. 通用 student 在多领域 prompts 上生成自己的 rollouts；
4. router 将每条学生轨迹送给对应 teacher；
5. teacher 在学生实际状态上提供 token 级分布；
6. student 用 KL 类蒸馏目标吸收教师策略，可同时加入 RL reward；
7. 必要时刷新 teachers，进行多轮渐进整合。

#### 它解决了什么

- 多领域 joint RL 的梯度冲突；
- 逐领域 cascade RL 的遗忘；
- 静态 trace SFT 的 exposure bias；
- 权重合并的不稳定；
- 专家团队无法并行开发的问题。

#### 它没有解决什么

- 教师与学生的训练分布仍需对齐；
- 教师之间需要版本和行为兼容；
- 多教师前向计算增加训练成本；
- router 决定哪个教师负责哪类样本，错误路由会传递错误信号；
- 领域教师的 environment 与 reward 仍然昂贵；
- 通用学生能否完整恢复每个教师上限，仍需逐领域验证。

## 蒸馏方法的严格区分

| 方法 | 学生看到什么 | 教师何时参与 | 主要优势 | 主要缺陷 |
| --- | --- | --- | --- | --- |
| 答案蒸馏 | 教师最终回答 | 数据生成阶段 | 简单、便宜 | 丢失过程与错误恢复能力 |
| Trace SFT / Off-Policy 蒸馏 | 教师完整推理轨迹 | 训练前生成静态数据 | 稳定、易扩展 | 学生上线时进入自己的状态，产生 exposure bias |
| 单教师 On-Policy 蒸馏 | 学生轨迹上的教师 token 分布 | 训练过程中持续参与 | 稠密监督、贴合学生分布 | 教师推理成本高，师生差距过大时不稳定 |
| Multi-Teacher On-Policy 蒸馏 | 多领域学生轨迹上的对应教师分布 | 按领域路由持续参与 | 并行专家、能力整合、减少跷跷板 | 教师同源、路由、版本编排复杂 |
| 参数合并 | 多个教师 checkpoint | 训练后权重操作 | 不需大量再采样 | 权重冲突，难以完整继承各领域能力 |

### 为什么 on-policy 如此重要

如果学生总在教师走过的完美轨迹上学习，它不会处理自己产生的小错误。on-policy 让训练数据由当前学生产生，因此监督覆盖的是学生真实会访问的状态。

这与 Agent 训练尤其相关。工具调用早一步出错，后续页面、文件和上下文都会不同。仅模仿教师成功轨迹，很难教会模型从偏离状态恢复。

### 为什么 token 级信号比最终 reward 更稠密

最终 reward 只能告诉模型整条任务成功或失败，无法定位哪一步导致失败。教师分布可以在每个生成位置提供相对偏好，让学生知道当前状态下哪些 token 或动作更接近专家策略。

但稠密不等于真实。教师也可能在学生陌生轨迹上不可靠，所以同源性和分布对齐成为 MOPD 的关键工程条件。

### MOPD 与普通多 Agent 的区别

多 Agent 系统是在推理时让多个模型协作；MOPD 是在训练时用多个教师把能力压回一个学生。前者增加线上调用，后者增加训练成本但希望保持单模型 Serving。

两者可以组合，但解决的问题不同。MOPD 的目标是让最终模型内部拥有多个领域能力，而不是每次请求都调用专家委员会。

## 为什么“Recipe 就是 Org Chart”

### 1. 每个领域教师背后都是一个小型模型项目

一个 coding teacher 需要代码环境、测试 verifier、任务生成和软件工程 RL；搜索 teacher 需要网页环境、浏览工具和检索奖励；安全 teacher 又需要红队数据、策略和风险评价。

它们不是给同一模型换几份数据，而是多套相对独立的研究 pipeline。

### 2. 并行开发需要统一契约

为了在 MOPD 中整合，团队至少需要统一：

- base model 与 tokenizer；
- 通用 SFT 起点；
- checkpoint 命名与交付节奏；
- prompt schema 与领域路由；
- rollout 格式和工具协议；
- teacher 输出与 top-k 概率接口；
- eval 与回归标准；
- 算力优先级和失败重跑机制。

没有这些契约，算法上可并行的专家会在集成阶段重新串行。

### 3. 复杂 recipe 的最大风险是不可归因

如果同一版本同时更换 SFT 数据、RL reward、环境、采样温度、教师和推理系统，最终分数变化无法归因。模型变差时，团队也不知道应回滚哪一层。

保守 recipe 的真正价值是可诊断，而不只是实现容易。复杂度预算应该与观测、日志和 ablation 能力同步增长。

### 4. 组织容量决定可尝试的搜索空间

拥有更多算力并不只意味着跑更大模型，也意味着可以同时训练更多教师、保留更多 checkpoint、运行更多 eval 和探索更多 recipe 分支。

所以 frontier lab 与学术团队的差距，不只是一次训练用了多少 GPU，而是每轮决策前能获得多少并行证据。

## Environment：Agentic RL 的新数据层

### 1. Environment 包含什么

一个训练环境通常不只是一套题，还包括：

- 可交互的软件或网站；
- 初始化数据和用户状态；
- 工具、权限与动作接口；
- 能够反复重置的任务世界；
- prompts 或任务生成器；
- verifier 与 reward；
- 运行稳定性和维护服务。

环境决定模型能看到什么状态、执行什么动作、获得什么反馈。它既是训练数据生成器，也是 Agent 能力边界。

### 2. 为什么比静态数据贵

静态问答只需保存输入与答案。环境需要持续运行、处理状态变化、隔离不同 rollout、模拟外部服务，并保证 verifier 读取到真实结果。

网页和软件升级后，环境还要维护兼容。成本因此更接近长期软件产品，而不是一次性标注项目。

### 3. Environment 市场的四种商品

| 商品 | 交付内容 | 商业价值 | 风险 |
| --- | --- | --- | --- |
| 软件克隆 | 可交互应用与假数据 | 提供训练世界 | 缺任务和 verifier，不知道训什么 |
| 任务包 | prompts、初始状态、目标 | 快速生成 rollouts | 可能与真实用户分布脱节 |
| Eval / Verifier | 可执行完成标准 | 能证明模型变好 | 容易被过拟合或 gaming |
| 完整训练环境 | 世界、任务、验证、维护 | 可直接接入 RL | 昂贵、依赖供应商、权利复杂 |

### 4. 开放生态的机会与约束

环境比完整模型 recipe 更容易由小团队分工建设，但仍需要解决许可证、数据隐私、维护责任和贡献激励。开放一个静态仓库远远不够，真实价值在环境是否长期可运行和可评分。

对企业而言，发布环境也可能是一种分发策略：让所有 Agent 更会使用自家产品，并把自家 benchmark 变成行业能力指标。

## RL API 与后训练平台的商业模式

### 1. Tinker 式 API 提供了什么

它把分布式训练、推理 rollout、learner、权重同步和硬件编排封装成简单接口。研究者可以更集中地修改 reward、数据、环境和算法，而不必先搭建完整集群。

### 2. 为什么适合小团队

- 无需一次租用上万张互联 GPU；
- 平台能以更高利用率聚合多个客户；
- 大型 MoE 训练和推理基础设施可复用；
- 失败实验按使用量付费，减少长期容量承诺；
- 团队可以先验证 recipe，再决定是否自建。

### 3. 为什么平台希望把训练导向推理

训练 job 是阶段性的，推理流量是持续的。平台若同时负责训练和 Serving，可以获得更稳定收入，也能用数值一致性和优化后的推理引擎降低客户上线摩擦。

商业闭环可以写成：

`环境与数据 -> RL / 蒸馏训练 -> checkpoint -> 平台 Serving -> 线上轨迹 -> 下一轮训练`

### 4. 客户需要警惕什么

- 权重能否完整导出；
- 导出后是否能在其他引擎复现质量；
- 训练日志、optimizer state 和 rollout 是否归客户；
- 平台是否保留数据或教师输出；
- 推理价格变化后迁移成本有多高；
- API 抽象是否阻止研究者访问关键训练动态。

### 5. 商业价值的相对位置

访谈给出的判断是：裸 compute 最接近商品，训练 API 位于中间，持续 inference 更接近高质量业务。这个排序并非绝对，仍取决于算力合同、软件差异、客户留存和模型流量。

## 对模型公司与研究团队的启示

### 1. 不要先问“要不要上 MOPD”

先回答四个问题：

1. 多领域 joint RL 是否已经出现明显 see-saw？
2. 是否有独立领域能够训练出显著强于通用模型的 teachers？
3. trace SFT 后是否存在明显 exposure bias 或能力恢复不足？
4. 团队是否能管理共同 base、教师版本和多轮 student rollouts？

若前两个问题都不成立，MOPD 可能只是增加复杂度；若第四个问题不成立，理论收益也难稳定兑现。

### 2. 为 recipe 设置复杂度预算

每增加一个领域教师，都同时增加环境、数据、训练、评测、版本和集成成本。团队应给每个新增模块写清：预期能力增量、可观测指标、失败回滚方式和长期维护人。

技术路线不是模块越多越先进，而是单位组织复杂度能否换来可复验的能力增量。

### 3. 保存过程资产，不只保存最终模型

MOPD 和渐进蒸馏要求保存：

- 各领域教师的中间 checkpoint；
- 每轮 student rollout；
- prompt 路由与教师选择；
- token 级蒸馏统计；
- 领域 eval 与通用回归；
- 训练失败和 reward hacking 记录；
- 不同版本的 base、SFT 与环境依赖。

未来重建或升级 recipe 时，这些过程资产可能比最终权重更有价值。

### 4. 评估 post-training 不能只看最终 benchmark

至少应比较：

| 维度 | 需要观察的指标 |
| --- | --- |
| 能力恢复 | 学生恢复每个 teacher 能力的比例 |
| 通用性 | 新领域和未见任务是否提升 |
| 稳定性 | 训练崩溃、reward hacking、能力遗忘 |
| 数据效率 | 每单位 rollout 和 teacher compute 的增益 |
| 组织效率 | 教师能否并行交付，集成等待时间 |
| Serving | 模型大小、输出长度、延迟与每任务成本 |
| 可复现性 | 外部团队能否用公开资产复验主要结论 |

### 5. open recipe 的目标不必是照搬 frontier lab

开放团队可以选择更简单、可解释的 recipe，集中研究某个关键环节；也可以通过开放环境、教师 checkpoint 或训练 API，补足 frontier recipe 中最稀缺的组件。

科学价值来自知道什么有效、为什么有效和何时失效，不只来自把公开榜单推高几个点。

## 反共识与金句

> 以下为访谈原意的中文整理，不视为逐字引文。

### 关于后训练演进

- 现代 post-training 不是在管理一条 loss curve，而是在管理一张 org chart。
- 简单 recipe 可以做出强模型，但它未必允许你继续投入 compute 爬坡。
- OLMo 3 的问题不是不知道 R1，而是把 reasoning 移植进旧 recipe，而没有重建 recipe。
- InstructGPT 的三个经典部件没有全部消失，但几乎都不再是今天的能力中心。
- SFT 没有变得不重要，它从主角变成了 cold start、行为接口和能力整合层。
- DeepSeek-R1 的关键不是“纯 RL”，而是让 RL 负责发现能力，再用多阶段训练修复模型。

### 关于 DPO 与方法时尚

- frontier lab 不再写 DPO，不等于 DPO 对所有团队都没用。
- 一个方法可能因为 recipe 更成熟而失去边际收益，也可能只是暂时不流行。
- 偏好损失看似简单，却能改变数学、代码和推理策略，这件事本身很反直觉。
- 对一个刚搭起来的 recipe，能稳定拿到的收益可能比理论上最先进的方法更重要。

### 关于蒸馏

- 蒸馏不是“抄闭源答案”的同义词，内部领域专家的能力回流也是蒸馏。
- trace distillation 教学生走教师的正确路线；on-policy distillation 教学生修正自己实际走过的路线。
- MOPD 不是把多个模型权重平均，而是在一个学生策略里重新学习多个教师。
- 最强教师不一定是最好的教师，师生距离太大时，学生可能根本学不会。
- 如果中间 checkpoint 对渐进蒸馏有用，训练历史就不再是可以随手删除的临时文件。
- MOPD 让专家团队可以并行，也迫使整个组织统一 base、数据契约和版本节奏。

### 关于复杂度

- 一次改太多东西，recipe 会在自己的复杂度下崩溃。
- 保守 recipe 不是技术落后，而是给新团队留下可诊断空间。
- 论文中的几个方框，背后可能是数十个团队和数月的交付依赖。
- 没披露的方法不能当作不存在，技术报告比较首先是证据比较。
- 两篇 frontier 报告给出相反温度 schedule，说明这个领域离成熟工程手册还很远。

### 关于环境与平台

- Agentic RL 的稀缺品正在从静态数据转成能运行、能重置、能验证的世界。
- 一个环境值不值钱，不只看软件做得像不像，还看它能否稳定地产生训练信号。
- 小团队也许复制不了 frontier recipe，但可以做好一个专业环境。
- 训练 API 最好的商业出口，不是卖更多训练 job，而是承接模型上线后的长期 token。
- 模型权重可以带走，不代表训练到推理的迁移成本为零。

### 关于研究与职业

- pre-training 与 post-training 的 compute 配比，是一家 lab 对未来进步来源的真实下注。
- 当前开放研究最糟糕的均衡是：拿到算力的人，更容易证明自己的想法正确。
- 高薪岗位可能同时提供最好的学习资源，也可能把 junior 锁在一个很窄的局部任务里。
- 不要只优化“有没有赶上这波”，要优化是否在形成可迁移的科学判断。
- 巨额融资扩大了实验规模，也可能迫使新 lab 走向与大公司相似的路线。

## 观点、事实与证据边界

| 内容 | 性质 | 边界 |
| --- | --- | --- |
| InstructGPT 使用 SFT、偏好 reward model 与 PPO | 论文事实 | 不代表当前闭源实验室仍按相同权重使用 |
| Tülu 3 采用 SFT、DPO、RLVR | 公开 recipe | 代表开放研究方案，不等同 frontier lab 内部方案 |

| inference 比训练 API 更好的生意 | 商业判断 | 仍取决于毛利、留存、容量合同和竞争格局 |
| recipe 复杂度由 org chart 决定 | 经验性框架 | 可用于解释执行上限，不是可直接测量的单一因果关系 |

## 最终结论

这期对话给出的不是一份固定后训练配方，而是一套理解 recipe 演进的方法。

第一，算法名称只是表层。SFT、DPO、RL 和蒸馏一直都在，真正变化的是哪一阶段负责发现能力、哪一阶段负责整合能力，以及监督来自真人、规则、环境还是教师模型。

第二，多教师 On-Policy 蒸馏的核心价值不是“教师更多”，而是把多领域能力生产拆成可以并行的专家项目，再让通用学生在自己的状态分布上吸收专家策略。它解决了 joint RL 的干扰和静态蒸馏的 exposure bias，却引入了同源教师、版本对齐和多轮编排的新复杂度。

第三，frontier post-training 的壁垒越来越像工业系统。算力决定能跑多少 rollout，环境决定模型能经历什么，verifier 决定什么行为被奖励，组织结构决定多少专家可以并行，checkpoint 历史决定能力能否渐进整合。

第四，开放生态的机会不必只围绕复刻完整 frontier model。完整 recipe 很难复制，但开放团队仍可以在环境、verifier、训练 API、教师 checkpoint、消融研究和可复现流程上提供关键公共基础设施。

最终，后训练竞争不会收敛成“谁找到一个更好的 loss”。**真正领先的实验室，是能把领域专家、环境、数据、算力和反馈组织成持续能力爬坡，同时仍能解释每一轮模型为什么变好的实验室。**
