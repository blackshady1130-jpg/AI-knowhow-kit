科学，是一个没有上限的广大世界。

从物理、化学、生物，到材料、机器人、人工智能，科学世界横跨不同的知识体系、研究范式与实验方法。

如果 AGI 乃至 ASI 最终得以实现，那么它一定会成为真正通用的跨学科科学家（General AI Scientist）：不局限于某一个领域，而是能够跨越不同学科与科学体系，理解问题、调用工具、分析证据、复现研究、提出假设并完成验证，最终将知识、计算、实验与现实世界连接成统一的科学发现闭环，在所有科学领域持续推动新的发现，并系统性加速人类技术进步。

要迈向这样的 General AI Scientist，第一步，是学会如何衡量它。

而衡量的第一步，就是看它能否把人类已经完成的科学工作重新做对，并交出可以独立验证的证据——也就是**可靠复现（Reproduction）**。

为此，UniPat AI 推出**PaperBenchX**，第一次把“可靠复现”这件事，放进 10 种原生科学环境中接受系统测评，所包含的 93 个复现任务横跨 12 个研究方向，以 3168 条专家校验的评分项为标准，以重新生成的证据为依据。结果显示，表现最强的 GPT-6 Astra，也仅有 13.98% 的完整复现率。

**PaperBenchX，让跨学科科学复现可量化，让 General AI Scientist 可衡量。**

## 可靠复现：通用科研能力的第一道检验

**可靠复现，是迈向新科学发现的重要基础。**它让已有结论接受独立检验，也为后续研究提供可核查的证据。已有研究提供了明确的目标与参照，让我们能够通过重新生成的证据，评估 AI 的科研能力。

这需要三项相互关联的能力：

- **实验重建：**将论文中的文字、公式与图表落实为具体的模型、条件和参数，并结合领域知识，对未充分说明的细节作出判断。
- **专业执行：**操作领域原生科学软件，选择合适的计算设置、检查诊断信息，判断计算是否稳定、结果是否收敛。
- **科学验证：**检查模型设定、计算过程与后处理是否符合科学要求，确认结果能够支持目标结论，并提供可独立重新生成和核验的证据。

跨越学科之后，这些判断所依赖的研究方法、专业工具与证据标准也随之变化。

**已有的研究复现基准大多集中在 AI 与机器学习领域。**以**OpenAI**的**PaperBench**为代表的工作，推动了论文复现能力的评测，但任务主要依赖相对统一的机器学习软件栈；其他跨领域科学基准，则更多考察科学编程、数据分析、工作流执行或专业软件使用等特定能力。

**跨学科论文关键实验的完整复现流程，仍缺少充分的评测。**

**为此，UniPat AI与合作企业、高校联合推出PaperBenchX——首个面向多学科、端到端论文结果复现的 Benchmark。**

**PaperBenchX围绕这一目标推进了三个方向：**

- **从以 AI 和机器学习为主的论文复现，扩展到更广泛的科学领域。**
- **从通用编程环境，拓展到各学科实际使用的科学软件与平台。**

- **覆盖实验重建、执行与结果验证的完整流程。**

## 93 个复现任务：在原生科学环境中检验科研能力

**PaperBenchX从 93 篇研究论文中构建了 93 个复现任务，覆盖 12 个研究方向、10 种领域原生科学环境，包含 3168 条专家校验的评分项。PhD级领域专家在整套任务的构建与验证中，累计投入超过 1000 小时。**

每项任务都要求 Agent 重新完成论文中指定的**关键实验**，并生成**支持目标结论的证据**。Agent 会获得论文、公开任务说明与相应运行环境，最终提交一套**可执行的复现工作流**。

**论文中的结果对 Agent 可见；专家参考工作流、私有评分规则及其容差、参考产物则保持隐藏。**评测关注的是，Agent 能否通过自己的工作流，重新产生科学上有效的结果。

![正文配图 3](https://mmbiz.qpic.cn/sz_mmbiz_png/NPuEh32rKRXq9fBTUKibbksPRkFk9lYP9wGmjJIvseULGpRDt82Jb35pEBQViccuj3gugQ1uics20WgnhBx2EKNLbbmdibhEvfBykfgBScKJKkY/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=1)

****PaperBenchX 的任务分布、来源论文与评分项构成****

PaperBenchX 将跨学科论文复现放进领域原生科学环境，并由评测系统独立重跑工作流，以重新生成的证据验证研究结果。

这套端到端评测通过**三项关键设计**实现：

**1、领域原生环境：让 Agent 使用实际研究所需的专业科学软件。**

任务运行于 Ansys HFSS、Ansys Lumerical、Meep、PySCF／GPU4PySCF、ABACUS 等科学软件与平台中。不同环境拥有各自的模型表示、数值约定、参数体系与执行流程。Agent 需要理解这些差异，选择适合研究问题的设置，并正确解释软件输出。专业工具的使用因此成为评测内容的一部分。

**2、长程任务与资源预算：支持指定实验的完整执行。**

科学任务的计算规模与资源需求各不相同。PaperBenchX 根据任务需要配置计算资源与执行预算，让 Agent 在明确的条件下完成研究。在这一过程中，Agent 需要安排计算、检查中间结果、诊断失败，并决定是否调整参数或重新运行。

**3、科学验证：检查实验过程与结果的有效性。**

**每项得分都必须有独立重跑生成的有效证据支持，Agent 的“复现成功”自述不能替代证据。**PaperBenchX 从以下三个层面检查提交结果：

- **独立重跑：**系统移除生成的输出与临时执行状态，在禁止外网访问的隔离环境中重新运行 Agent 提交的工作流，并独立记录运行状态与产物来源。只有本次重跑生成的产物，才能作为评分证据。
- **证据溯源：**重跑产生的日志、原始数据、计算轨迹、收敛记录与派生指标，被固定为只读证据。每项科学判断都需要追溯到这些产物：判断计算是否收敛，需要相应记录；报告的物理量需要原始输出及其分析过程。
- **科学判定：**数值一致性、单位、文件结构与容差等可直接检查的要求，由程序判定；需要领域解释的要求，由统一的科学评分模型依据私有评分规则与参考证据评审。

**这套评测的基础，是每一道任务背后明确的科学要求、可运行的专家参考工作流，以及经过校准的评分规则。**这些都需要在任务构建阶段逐项建立和验证。

## 从论文到考题：科学复现任务的构建与验证

一篇论文进入评测前，需要先明确复现范围、配置专业环境，并由专家验证参考流程与评分规则。

**PaperBenchX将这一过程分为“构建候选任务”和“验证与审核”两个阶段，共九个步骤。**

![正文配图 4](https://mmbiz.qpic.cn/sz_mmbiz_png/NPuEh32rKRX1nGexygtlLllx8rmsUWKfJEP5vWaO2vdBkU6iaMsXIP2x238xN9qujY7dHThPtCR5GUr6RZdQmfLeU8h3zMMxU5HM6pPHhgUE/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=2)

*PaperBenchX 的两阶段、九步任务构建与验证流程*

### 第一阶段：构建可运行的候选任务

**第 1—2 步：选择论文与研究主张，界定科学范围。**

领域专家选择研究论文及其中具有科学意义的研究主张，检查其能否在软件、许可证、算力和时间限制下复现，再明确目标图表、模型配置、实验条件及变体、观测量、允许的方法替代，以及支持结论所需的证据。

**第 3—4 步：配置专业环境，编写公开任务说明。**

专家配置领域原生科学环境，并在公开说明中明确任务范围、所需产物、提交位置与工作流运行入口。私有评分规则与参考实现保持隐藏。

**第 5 步：实现参考工作流，完成初次运行检查。**

专家在配置好的环境中实现并运行私有参考工作流，确认专业仿真软件能够调用、指定实验能够在资源限制内完成，所需参考产物能够生成。**只有这套端到端流程成功运行，任务才能进入候选阶段。**

### 第二阶段：验证与审核

**第 6 步：将科学要求拆解为细粒度评分项。**

评分项覆盖模型构建、参数设置、软件执行、数值收敛、后处理与结论验证。每项均明确获得分数所需的证据、判定规则、容差与权重，使各项要求能够分别评分。

**第 7 步：在干净环境中重跑专家参考流程。**

私有参考工作流需要在最终容器的干净副本中，通过与 Agent 提交相同的接口重新执行。这一步检查流程是否依赖残留状态、未声明文件或隐藏设置，并确认参考产物能够在最终资源限制下重新生成、供评分器读取。

**第 8 步：用不同完成程度的工作流校准评分。**

团队对成功、部分成功和无效的工作流进行评分，检查规则能否奖励有证据支持的进展、拒绝缺失或相互矛盾的证据，并区分完整复现与看似合理但科学上无效的结果。

**第 9 步：由两名独立领域专家复核。**

两名独立专家检查任务的科学范围、公平性、可复现性、证据要求与评分表现。

任务范围、环境或参考工作流出现问题，需要返回第一阶段；评分项、评分规则或评分器出现问题，则返回第 6 步。**所有受影响的运行检查、评分校准与专家审核都须重新完成。只有通过完整流程的任务，才能定稿并纳入正式基准。**

经过这一流程，论文中的科学要求被落实为明确的任务、可运行的参考流程和可逐项判定的评分标准。PaperBenchX 据此评测当前 AI 的跨学科复现表现，进一步观察其能力与不足。

## 评测结果：识别 Agent 的科研能力缺口

**PaperBenchX**在同一组 93 个任务上，评测了 10 组前沿模型与 Agent 框架配置。

表现最好的**GPT-6-Astra（Codex）平均加权得分为 59.08%，完整复现率仅为 13.98%——即 93 个任务中的 13 个。**

两个指标记录了不同层面的表现：平均加权得分先计算每项任务中各评分项的加权得分，再对 93 个任务取平均；完整复现率则统计任务得分**严格超过 90%**的比例。前者记录部分进展，后者衡量任务是否达到基准定义的完整复现标准。

**受测 Agent 已能完成部分科研工作，但完整的端到端复现仍然困难。 全部 93 个任务中，有 70 个未被任何受测配置完整复现。**

不同研究方向上的表现也存在明显差异，没有任何一个受测配置在所有方向上领先。进一步拆解研究环节与执行轨迹，PaperBenchX 揭示了这些差距的具体表现。

*（a）受测配置的不同阶段得分；（b）交互轮数与得分关系；（c）抽样轨迹工作流时间分配*

- 科学验证，是平均得分最低的环节

在全部受测配置中，建模（Modeling）、执行（Execution）与验证（Validation）的平均得分分别为**62.70%、61.84% 和 42.80%**。

Agent 能够完成部分建模与软件执行，但正确处理结果、确认其科学有效性，并形成支持论文结论的证据，仍然更加困难。一次成功的运行，也可能重新生成不正确的结果。

**PaperBenchX 的分阶段评分帮助定位不同研究环节的能力差距。**结合独立重跑与证据来源检查，评测还能够区分实验构建错误、错误结论，以及无法核验的证据，为分析失败原因提供依据。

- 交互效率，需要结合复现表现判断

Fable 5.1 和 Fable 5 配置的截尾平均交互轮数分别为**113.0 轮**和**112.0 轮**，平均加权得分分别为**58.17% 和 57.96%**。相比之下，DeepSeek-V4.1-Flash 配置的交互轮数为**372.6 轮**，得分为**45.47%**。

论文的轨迹分析指出，较长的执行过程有时包含反复尝试、故障恢复，或沿着不恰当的模型设定继续计算。因此，交互数量需要结合实际完成的科学工作来理解：更多操作，并未稳定对应更好的复现表现。

- 前期科学判断，影响后续计算的价值

研究从五个模型中分别抽取 50 条轨迹，分析论文理解与实验方案重建、代码实现、原生软件执行、诊断调试与证据重跑等环节的时间分配。在按工具操作记录统计的时间中，原生软件执行占比达到**51.8%—63.3%**。

大量时间用于计算，而这些计算能否产生支持目标结论的证据，又依赖前期对研究问题、模型、参数与实验流程的判断。错误设定即使被顺利执行，也可能无法完成目标实验的复现。

这些分析提示，科研 Agent 的改进需要关注领域知识的运用、实验组织、故障诊断与科学验证。

**PaperBenchX 为这些改进提供了具体的检验依据。**开发者可以结合分阶段得分、运行轨迹与证据检查定位问题，再通过同一套任务与评分标准，检验后续调整是否提高了科学要求的完成程度，以及端到端复现的成功率。

## 12 个开放测试 · 81 个封闭测试

**PaperBenchX**从每个研究方向中选取一个代表性任务，共开源**12 个测试任务**，供社区运行任务、检查评测方法，并研究科研 Agent 的能力与不足。同时维护 81 个封闭测试任务，有限开放，避免评测污染。

公开资源包括任务说明、评分细节与相应评测资源。根据科学软件的许可条件，环境的提供方式有所不同：

- **9 个任务提供完整、可再分发的开源科学计算环境。**
- **3 个任务依赖商业软件。**团队公开任务说明、评分细节、运行环境说明与统一评测框架；研究者取得有效许可证后，可自行配置对应环境并运行评测。

完整任务包将**任务说明**、**运行环境**与**评测资源**分开组织，主要包括：

- instruction.md：任务说明。 明确 Agent 需要完成的科学目标与交付要求。
- task.toml：预算与运行配置。 记录执行预算和环境元数据。
- environment/：运行材料。 包含 Dockerfile、compose 等环境配置，以及论文、补充说明、起始代码与任务输入。
- tests/：评测资源。 包含评测入口、rubric.json评分规则，以及重跑与检查所需的资源。这些资源在评测时与 Agent 可见材料分开。

社区可以通过这些 Demo 评测 Agent、调试复现工作流，并检查具体的任务要求与评分机制。

其余任务则保留为未公开的评测集，用于持续检验后续 Agent 的科学复现表现，维持 PaperBenchX 的区分度与长期评测有效性。

## Next Step

**PaperBenchX**的评测表明，受测 Agent 已能在建模与执行中取得部分进展，但表现最好的配置，也只有**13.98%**的任务达到完整复现标准。从理解论文、运行软件，到重新取得支持研究结论的科学证据，仍有明显的能力差距。
