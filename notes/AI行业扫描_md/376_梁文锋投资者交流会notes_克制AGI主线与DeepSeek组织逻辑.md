## 一句话总览

这场交流会展示了一套高度一致的 DeepSeek 公司操作系统：把 AGI 视为终局目标，把“克制”作为资源配置原则，以开源、低价和有限商业边界换取团队凝聚力、生态支持与长期技术概率；C 端、B 端和 API 收入可以提供现金流与下行保护，但不能反过来牵引研究主线。

这套逻辑最强的地方是内在一致，最需要验证的地方也很清楚：AGI 路线是否会按预期推进，持续学习是否真是下一道可跨越的门槛，团队能否在扩张中保持稳定，算力效率能否持续抵消资源差距，以及模型层的低价与开源最终能留下多少可持续价值。

## 先看结论：这场交流会最重要的 12 个判断

### 1. “克制”是 DeepSeek 的战略函数，不只是价值观

梁文锋反复说“克制”，具体落在五个选择上：

- 不以利润最大化定 API 价格；
- 不把春节后的 C 端流量做成超级 App 争夺战；
- 不急于铺垂直产品线；
- 不希望向上游芯片和下游应用全面垂直整合；
- 不把开源视为商业利益的让渡，而把它视为完成 AGI 的必要条件。

这里的真实优化目标是“提高做成 AGI 的概率”。收入、用户、市场份额都可以拿，但不能占用主线资源。

### 2. 开源的护城河不在权重保密，而在成本、时间和落地能力

梁文锋认为，即使公开同一版本的模型，第三方也很难做到相同部署成本、推理效率和服务质量。模型能力长期会收敛，稳定差异主要剩下：

1. 成本；
2. 时间，也就是早几个月还是晚几个月做到；
3. 用户体验。

这是一个很明确的判断：权重本身不会形成长期垄断，模型公司真正要守的是全栈效率和迭代速度。

### 3. API 定价采用“合理回报”口径，但原稿里的财务表述不能直接建模

交流会给出的定价原则是：购入设备后，约十个月收回设备成本。梁文锋同时提到“六倍利润”，并判断当前价位以下需求弹性已经很弱。

这几个说法需要拆开看：

- “十个月回本”可能指设备投资回收周期；
- “六倍利润”可能是 ASR 错误，也可能使用了不同于财务利润的口径；
- “继续降价不会明显增加需求”是管理层判断，不是披露出来的弹性实验。

因此，这部分适合用来理解定价哲学，不适合直接推 ARR、毛利率或估值。

### 4. C 端、B 端和 API 是 AGI 研发过程的副产物，也是商业下行保护

梁文锋把现有商业化描述为“顺便做的”：模型在通往 AGI 的过程中自然产生 API、C 端用户和 B 端收入，公司用少量人维护服务，不让产品目标反向定义模型路线。

问答中他又给出一个更务实的底线：即使技术冻结，单靠 API 服务也可能支撑一家上市公司。这说明 DeepSeek 并非拒绝商业化，而是把商业化分成两层：

- 上层目标：继续推进 AGI；
- 下层保底：用已有模型能力建立可持续现金流。

### 5. 技术路线图是“语言模型 → CoT → Agent → 持续学习 → AI 加速 AI → 具身”

梁文锋把近几年的能力进步理解为逐层叠加：

- 语言模型提供基础能力；
- CoT 抬高复杂推理上限；
- Agent 扩展模型可完成的任务范围；
- 持续学习让模型真正进入长期组织环境；
- 能持续学习的 AI 可以参与开发下一代 AI，形成非线性进步；
- 具身智能放在后面，让前一阶段的 AI 帮助开发现实世界系统。

世界模型、视频生成和多模态在他的路线图中不是当前智能主线。多模态会做，但被定义为组件。

### 6. 持续学习是核心研究命题，但交流会并没有给出已成立的方法

梁文锋的判断很强：Agent 之后的下一道门槛是持续学习，没有它，AI 无法像员工一样在公司里工作两个月后形成背景知识。

他的技术置信度却很克制：

- 全世界还没有找到明确 work 的方法；
- DeepSeek 内部有一些有前途的想法，但尚未做通；
- 这不是一个单点技术，可能需要算法、系统和工程的组合；
- 现阶段更像“摸奖”，需要很多人持续思考，而不是成立一个大项目就能解。

因此，“持续学习是下一步”属于路线判断，不是交付时间承诺。

### 7. DeepSeek 的第一用户是 DeepSeek 自己

问答中最有战略含量的一句话是：下一代模型的第一目标，首先是让 DeepSeek 自己用得好，帮助团队更快开发下一版模型。

内部采用在这里承担的是研发飞轮功能：

`模型能力提升 → 研究与工程效率提升 → 更快开发下一代模型 → 再提升内部效率`

如果这个闭环成立，产品采用和外部商业化是随之而来的结果。它也给了模型评测一个更硬的标准：模型是否真的减少了下一版模型研发中的人工时间、实验成本和返工。

### 8. 团队稳定被定义为唯一不可退让的核心利益

梁文锋认为，钱和资源都可以再获得，真正不可逆的风险是核心团队流失。公司愿景、期权、研究自由和低强度工作方式，都服务于同一个目标：让关键研究人员长期留下。

这个判断揭示了 DeepSeek 的组织观：

- 人才优势不是“每个人更聪明”；
- 优势来自如何让聪明人长期合作；
- 愿景承担了协调与激励功能；
- 组织稳定比短期收入、市场份额和产品完整度更重要。

### 9. DeepSeek 不是纯扁平组织，而是“正式任务 + 自主探索”的双轨制

公司运行有两条线：

- 自上而下的正式任务，例如集中完成模型发布；
- 自下而上的自主研究，由个人判断什么重要。

梁文锋给出的经验比例是：正式安排最好不要超过员工时间的一半。另一半保持自主探索。随着公司扩大，他也明确承认，部分部门必须建立严谨层级，其他部门继续保持松散和扁平。

比“没有 KPI、没有组织架构”更准确的描述是：DeepSeek 把管理集中到需要协同交付的部分。

### 10. 中美模型差距首先是算力差距，人才差距被视为二阶结果

梁文锋把国内外模型、人才和应用差距大体归因于资源：

- 国内研究团队能做的实验更少；
- 人才成长机会因此受限；
- 更大的激活参数模型不仅训练不起，也缺少训练前的充分实验；
- 当前策略是在可训练、可部署的规模上把效率做到极致。

他的追赶叙事是：接受一段时间差，用显著更少的算力做出接近能力，再逐步把时间差缩短；在总算力存在数量级差距时，全面超越不现实，局部超越可以争取。

### 11. 低成本既是商业承诺，也是资源受限下的 Scaling 手段

DeepSeek 对计算效率的重视有两个来源：

- 让更多用户用得起；
- 同样算力下训练更大模型、做更多实验。

这让“低成本”同时连接愿景、产品和研究，具体工作覆盖模型架构、kernel、编译器、推理系统和硬件适配，远多于压低 API 标价。

### 12. 国内基模公司会收敛，模型层很难长期维持暴利

梁文锋判断，中国当前做基模的公司过多，资源被重复分散；当市场认识到模型层只有合理利润，玩家会收敛到三四家左右。

这个判断背后的逻辑是：

- 模型能力差距会逐渐收敛；
- 成本与时间决定阶段性领先；
- 低价玩家会不断压缩高价玩家的利润空间；
- 大模型公司不可能拿走 AI 价值链的大部分利润。

对投资来说，真正的问题由“谁能做出模型”变成“谁能持续获得算力、保持迭代速度、控制单位任务成本，并在模型商品化后仍然掌握价值入口”。

# 一、愿景与“克制”：DeepSeek 如何定义自己的目标函数

## 1. 愿景不是口号，而是资源配置

梁文锋开场把“愿景”定义为实际运行方式，不是墙上的文字。DeepSeek 早期没有上市或利润最大化目标，团队靠一个未成文但大方向一致的目标聚合：做对人类有用的 AI。

从后续内容看，这个愿景至少约束四类决策：

- 是否开源；
- 收取多少利润；
- 要不要争 C 端和垂直应用；
- 研究人员时间应该放在哪里。

愿景在这里承担了传统 KPI、预算审批和产品战略的一部分功能。

## 2. “克制”具体克制什么

梁文锋说“克制是一种战略” `[00:25:32]`。它并不等于不赚钱，而是限定公司要捕获的价值范围：

- 可以卖 API，但不按利润最大化定价；
- 可以保留 C 端用户，但不以成为超级 App 为目标；
- 可以做 B 端，但不成立庞大销售和交付体系牵引研究；
- 可以支持多模态，但不因市场热度改写智能路线；
- 可以自建集群，但只有在收益足够大时才考虑自研芯片；
- 可以和伙伴竞争，但尽量不把整个生态变成零和关系。

他的判断是，AI 市场足够大，过度索取会引来更便宜、更开放的挑战者；只拿合理收益，反而提高公司活下去并做成 AGI 的概率。

## 3. “西瓜与芝麻”的时间偏好

春节后的 C 端流量被视为“芝麻”，AGI 是后面的“西瓜”。这个比喻表达的是很强的时间偏好：当技术范式仍快速变化时，过早建立产品线、广告、电商、本地生活或重交付体系，很可能在几个月后失去价值。

DeepSeek 的选择是保留可低成本获得的用户与收入，不围绕它们重构公司。

### Comment

这套逻辑成立，需要三个条件：

1. AGI 机会足够大，而且与现有研究主线连续；
2. 公司能在商业投入克制的同时持续拿到资金和算力；
3. 延后产品化不会丢掉不可逆的分发、数据和客户入口。

前两个条件决定 DeepSeek 能不能继续向前，第三个条件决定它即使做出更强模型，能否留下足够价值。模型层越来越可替换时，“不争入口”可能是克制，也可能把运行时、客户反馈和数据飞轮交给其他平台。

# 二、开源与商业化：模型公司应该赚哪一段钱

## 1. 开源被同时解释为愿景选择和商业选择

梁文锋没有把开源包装成单纯公益。他的论证有两层：

- AI 的总价值足够大，单一公司不可能独占；
- 即使模型权重开放，低成本部署和稳定服务仍然困难。

因此，DeepSeek 可以开放最强模型，并在官方 API 上依靠更低成本继续竞争。

他还明确说：

- 开源模型与官方部署模型相同；
- 不会开源一个较弱版本、自己保留更强版本；
- 希望第三方部署成功，甚至愿意帮助竞争对手复现；
- 真正担心的是第三方部署质量差、成本高，损害模型体验。

## 2. 对护城河的定义

交流会里的护城河并非“秘密算法”，而是：

- 模型架构和训练效率；
- kernel、编译器和推理系统；
- 服务成本；
- 发布速度；
- 组织能否把大量细节做完；
- 用户体验。

开源会让知识扩散，但不会让所有公司立刻具备同样的系统能力。

## 3. API 的合理利润与需求弹性

梁文锋披露的内部原则是十个月收回设备成本。他认为，当前价格已经低到多数用户不会因为再降价而增加使用，因此继续降价既不增加收入，也不明显增加社会价值。

这是一条很关键、也很需要验证的假设：

- 如果需求确实缺乏弹性，继续降价只是压缩收入；
- 如果 Agent、长上下文和批处理工作负载对价格高度敏感，降价可能释放新的任务，而不是只给现有调用打折。

内库 `AI_SCAN 349` 对这个问题的判断更适合做经营监控：降价是 margin erosion 还是 market expansion，取决于降价后是否出现新的高频、长链路、Agentic workload。只看 token 单价或调用量都不够。

## 4. 商业化被安排成“副产品 + 保底”

主讲部分强调：

- C 端是 AGI 研发的副产物；
- B 端/API 也是技术台阶自然产生的服务；
- 商业化一直在做，只是没有以商业化为目标；
- 彻底转向产品的时间点仍然很远。

问答部分补上了资本市场视角：

- B 端收入和 C 端用户已经形成商业基础；
- 若需求继续扩大，公司有机会接近盈利；
- 即使技术不再进步，卖 API 也能形成保底业务。

DeepSeek 的商业模型可以概括为“先不让收入定义研发”，并非拒绝收入。

## 5. 模型层的长期价值捕获

梁文锋判断，大模型公司不可能拿走整个 AI 价值链的大部分利润。模型差距最终会集中在时间和成本，玩家收敛后维持充分竞争。

### Comment

结合用户内库的 MaaS 判断框架，DeepSeek 还要回答一个控制点问题：

> 如果 Agent runtime、权限、日志、评测、客户反馈和任务数据都沉淀在别的平台，DeepSeek 会不会被压成一个高质量、低价格、但可替换的模型调用层？

开源与低价可以扩大使用，却不自动形成反馈闭环。后续要观察：

- 官方 API 是否能获得足够真实任务数据；
- DeepSeek 自有产品是否形成高质量默认工作流；
- 第三方生态反馈能否回流训练；
- B 端是否需要安全、权限、审计、SLA 和交付能力，而这些是否会反向要求更重的组织。

# 三、AGI 路线：持续学习为什么被放在 Agent 之后

## 1. 当前模型的能力边界

梁文锋认为，只要问题、上下文和指令足够完整，当前模型已经能在很多局部任务上超过人类。现实问题是，组织无法每次都把完整背景写进 prompt。

他的员工类比很准确：

- 新员工在公司工作两个月，会认识同事、理解流程、知道默认规则；
- 当前 AI 每次都需要被重新告知“小王是谁、在哪里、应该怎么联系”；
- 即使窗口足够长，把所有背景不断塞进上下文也不现实。

因此，Agent 可以扩大动作空间，却还不能替代长期进入组织的人。

## 2. 阶梯式路线图

交流会给出的路线图：

```text
语言模型
  ↓
Chain of Thought
  ↓
Agent
  ↓
持续学习
  ↓
AI 帮助开发下一代 AI
  ↓
具身智能
```

后一步使用前一步的能力。梁文锋把“先做持续学习、后做具身”称为更轻松的路线，因为模型可以帮助人类开发后续系统。

## 3. 奇点不是临界点，而是非线性连续过程

他不认为存在一个清晰的突然跃迁时刻。进步是连续的，但 AI 能加速 AI 研究，因此后段速度可能非线性上升。

在这一框架下，AGI 的第一项用途是帮助 DeepSeek 迭代下一版模型，职业替代并非首要验证场景。

## 4. 世界模型、多模态与具身的位置

梁文锋的优先级很明确：

- 多模态对产品重要，但在当前阶段是组件；
- 视频生成可以是好生意，但不直接决定智能上限；
- “世界模型”概念太宽，不是当前训练主线；
- 具身最终绕不过去，但应放到 AI 已能参与研发之后。

这里讨论的是研究顺序，并未否定多模态或具身的长期价值。

## 5. Scaling 仍然有效

梁文锋说，DeepSeek 尚未看到语言模型 Scaling 的上限。当前模型大小由可用资源决定，不代表这一规模已经足够。

他把 Scaling 拆成：

- 模型规模；
- 数据规模；
- 训练成本和效率。

对国内团队而言，讨论“Scaling 已到头”还太早，因为算力约束使团队尚未充分探索这条曲线。

### Comment：持续学习不能被简化成“更长记忆”

内库 `AI_SCAN 347` 对持续学习的补充很重要。一个真正可用的 continual learning 系统至少要解决：

- 哪些信息进入 weights/adapters，哪些留在 RAG、数据库或日志；
- 新知识怎样更新而不破坏旧能力；
- 如何避免 catastrophic forgetting；
- 个人、团队和公司记忆如何隔离；
- 学到的内容如何评测、审计和撤回；
- 模型更新的训练成本是否低于每次重读上下文的成本。

因此，在持续学习真正成立前，企业 Agent 仍需要 Context Infra：外部状态、RAG、KV/cache、权限、日志、工作流记忆和人工验收。它们可以逼近“长期员工”的体验，但不能等同于模型已经会持续学习。

# 四、研究与数据：下一代能力如何被做出来

## 1. 持续学习研究被称为“摸奖”

问答中，有人询问如何在明确的 Coding Agent 目标和不确定的持续学习研究之间分配资源。梁文锋的回答是：

- 持续学习的早期想法实验不一定消耗大量卡；
- 它更需要很多人长期思考；
- 现阶段很难用传统项目制分配资源；
- 公司会把它保持为重要问题，允许多人低门槛探索。

这和 DeepSeek 的自主研究时间相匹配：未知问题通过分布式探索找突破，明确的模型发布再切换到集中协作。

## 2. 高质量数据的瓶颈被定义为时间

梁文锋认为，国内后训练与美国的主要差距之一是高质量数据积累。高端标注在中国并没有显著成本优势，真正的扩张速度受限于：

- 专家培养；
- 标准形成；
- 数据生产和审核周期；
- 团队积累时间。

他甚至说，可以把公司一半的核心研究员理解为在“标数据”。这里的“标”更可能不只是传统外包标注，也包括命题、示范、轨迹、筛选、评审和训练信号设计。

## 3. 幻觉被归为可通过后训练改善的产品问题

梁文锋认为，幻觉可以通过更好的 post-training 改善，只是并非当前最高优先级。

这个说法需要边界。内库 `AI_SCAN 046` 的材料指出，幻觉也与预训练中的分布学习、后训练激励和 benchmark 奖励猜测有关。它不能只靠“多投入一些标注”解决。更完整的方案还包括：

- 允许模型表达不知道；
- 调整评测和奖励机制；
- 引用与外部验证；
- 工具调用和检索；
- 针对高风险场景设定拒答与人工复核。

## 4. 数据质量比数据规模更值得警惕

内库 `AI_SCAN 320`、`322` 与交流会形成互补：

- 当前很多模型能力提升仍依赖任务特定的专家轨迹、rubric、环境和 verifier；
- AI 合成数据只有在题目、参考答案、测试和奖励信号都正确时才有价值；
- verifier 错误会把大规模训练变成大规模放大噪声；
- 真正昂贵的是专家能否定义好任务、识别 corner case，并给出可复用的判断标准。

这也是为什么“高质量数据需要时间”比“融资后多买一些数据”更接近真实瓶颈。

## 5. 交流会中相对缺失的一环：评测

整场会议对技术路线、算力和组织谈得很多，对以下问题谈得较少：

- 持续学习如何验收；
- “模型对 DeepSeek 自己有用”用什么指标判断；
- 成本优势是在什么 workload 下成立；
- 中美模型差距用哪些任务和口径衡量；
- 后训练数据怎样检查 verifier 与污染；
- Agent 是否能恢复失败、保持长期状态并完成真实任务。

这不代表 DeepSeek 内部没有评测，而是这场投资者交流会没有提供足够证据。后续研究不应把管理层判断直接替代 task-level evidence。

# 五、组织：愿景驱动、双轨研究与扩张边界

## 1. 共识是决策机制

梁文锋说，公司重大决策先寻找团队共识。他的权威来自共识，个人引导作用有限。

这与“愿景驱动”构成一套机制：

- 愿景定义大方向；
- 研究人员自主判断具体问题；
- 达成共识后集中执行；
- 领导者负责引导和收敛，而不是持续派任务。

## 2. 两条管理线

### 自上而下：正式任务

用于模型发布、工程交付等需要多人协作的工作。公司统一目标、拆分任务、集中完成。

### 自下而上：自主探索

研究人员选择自己认为重要的问题。只要资源允许，可以直接探索，不需要层层协调。

梁文锋希望正式任务不要超过一半时间。这个比例不是制度文本，更像组织设计原则。

## 3. 为什么“不太加班”

他给出两个原因：

- 研究需要松弛，过度排期会损害探索；
- 公司高度聚焦，不做很多产品补齐和商业扩张，因此任务总量更少。

换句话说，松弛来自主动缩小边界，不是所有事情都做、再要求员工高效完成。

## 4. 唯一核心利益：关键团队稳定

梁文锋把团队稳定说成唯一不可退让的利益。融资和期权的一个重要功能，是稳定早期核心人员。

这个判断也暴露了组织的集中风险：

- 技术路线高度依赖少数长期人员；
- 未成文愿景在新人扩大后可能被稀释；
- 自主探索依赖较强的选人和同侪标准；
- 共识机制在规模变大后可能拖慢决策；
- 产品、服务和基础运营可能长期处于“不完善但可用”的状态。

## 5. 扩张后会出现分层组织

问答中梁文锋明确承认，公司已经在调整：

- 有些部门需要严谨层级；
- 有些研究部门继续扁平；
- 如果不调整，很多事情无法推进。

因此，不应把 DeepSeek 归纳成“永远无组织、永远无 KPI”。更准确的说法是：

> 研究核心保持高自主，规模化交付建立必要层级，组织形式随任务性质分化。

## 6. DeepSeek 不是 Bell Labs

梁文锋拒绝用 Bell Labs 作为直接模板。DeepSeek 有利润以外的使命，但仍然是必须自己活下去的公司，B 端和 API 最终要承担现金流责任。

### Comment

内库 `AI_SCAN 278` 对 Anthropic 的分析可以作为对照。两家公司都把组织当成模型能力的一部分，但方向不同：

- Anthropic 更强调研究、产品、工程、安全和商业化的闭环；
- DeepSeek 现阶段更强调研究自由、技术聚焦、低成本与有限商业边界。

DeepSeek 的组织优势能否延续，取决于它能不能完成一次“选择性正规化”：把服务、集群、数据、评测和商业运营做成稳定系统，同时不让这些系统吞掉研究自主性。

# 六、算力、效率与国产芯片

## 1. 对中美差距的归因

梁文锋认为，主要差距是资源，不是基础人才：

- 卡少导致实验少；
- 实验少影响人才成长；
- 模型规模受可用算力约束；
- 研究资源不足比单次训练资源不足更严重。

他举了大量卡量、激活参数和采购计划数字。由于主持人明确提醒这些内容敏感，且 ASR 可能有误，本 Notes 不把它们当作公开事实复述。

可以保留的战略判断是：

> 训练一次大模型并不等于具备研究该规模模型的能力。真正的门槛是能否在正式训练前完成足够多的架构、数据和效率实验。

## 2. 追赶策略：以效率换时间

问答里，他把国内路线概括为：

- 接受模型规模和时间上的阶段性落后；
- 用显著更少算力做出接近能力；
- 逐步把一到两年的时间差缩短到半年、三个月；
- 总资源差距存在时不谈全面超越，只争取局部领先。

这是一个资源约束下的 Pareto 选择，不是“少量算力天然更先进”。

## 3. 为什么效率是核心能力

效率连接了四个目标：

- 降低用户价格；
- 提高官方 API 毛利空间；
- 在同样算力上训练更大模型；
- 让模型可以迁移到国产硬件。

内库 `AI_SCAN 345`、`338` 提供了更完整的系统视角：真实成本由模型架构、kernel、推理框架、芯片、网络、内存、缓存、batching 和 workload 一起决定。公开 API 单价只是一层，不能替代真实吞吐、延迟和单位成功任务成本。

## 4. 对 CUDA 与国产生态的判断

梁文锋认为，CUDA 护城河正在减弱，理由包括：

- AI 可以帮助重写软件生态；
- TileLang 这类高级语言降低 kernel 开发门槛；
- AI 计算硬件越来越专用，不必继续继承游戏卡时代的兼容包袱；
- 外部供应约束迫使国内团队完成适配。

他把 TileLang 视为迁移到不同硬件的关键抽象层。问答中又说，使用高级语言会大幅提高开发效率，底层执行损失约 1%—2% 可以接受。

## 5. 国产硬件的瓶颈分成生态与产能

他的判断是：

- 软件生态有机会较快解决；
- 芯片性能仍存在代际差距；
- 真正长期约束可能转向产能；
- 几年内仍会受限，五年后不一定继续卡在同一位置。

### Comment

这里需要把管理层信心与产业事实分开：

- “一年内生态不再是问题”是预测；
- “五年后产能不再受限”也是预测；
- TileLang 能否跨芯片稳定达到接近手写 kernel 的性能，需要真实模型、真实集群和真实 workload 验证；
- 软件可移植不等于芯片供应、互连、HBM、良率和大集群稳定性已解决。

“能不能跑”只说明完成了初步适配。更有价值的观察指标包括：

- 训练有效利用率；
- 线上吞吐与时延；
- 故障率和恢复时间；
- 功耗与 TCO；
- 不同模型架构迁移成本；
- 新硬件从到货到可生产使用所需时间。

# 七、行业格局：模型、应用和生态的利润如何分配

## 1. 模型公司数量会收敛

梁文锋判断，国内基模玩家过多，重复训练分散了资源。随着模型层利润回到合理区间，市场会收敛到少数公司。

他没有认为某一家会形成长期暴利，因为：

- 模型能力差距会缩小；
- 时间领先通常只有几个月；
- 成本更低的竞争者会压价；
- 开源降低模型能力的扩散门槛。

## 2. 中国的结构性优势主要是成本与产品

问答中，他没有泛化“中国全面领先”，而是只给出两个可能的结构性优势：

- 成本控制；
- 产品体验。

其他方面未必存在系统性优势。这一点比很多宏大叙事更克制。

## 3. 通用 Agent 先于垂直 Agent

面对金融、法律、医疗等垂直产品问题，梁文锋的现阶段排序是：

1. Coding Agent；
2. 通用 Agent；
3. 其他垂直 Agent。

垂直场景仍有价值；DeepSeek 把它们暂时靠后，原因是国内商业模式尚未清晰，现阶段投入通用能力的边际收益更高。

### Comment

结合用户内库的“结果买单”框架，这个排序在模型公司内部合理，但不应外推成所有创业公司的优先级。垂直 Agent 是否成立，仍要逐项看：

- 原有预算在哪里；
- 结果能否验收；
- 失败由谁兜底；
- 专家数据和流程能否沉淀；
- 模型变强后产品会变厚还是被吞掉。

DeepSeek 选择 Coding/通用 Agent，优化的是自身通往 AGI 的路径；应用公司选择垂直场景，优化的是客户预算与结果闭环。两者不是同一道题。

# 八、问答部分逐题整理

## Q1. 持续学习什么时候突破，需要什么技术

**回答要点：**

- 目前全球都没有公认有效的方法；
- 持续学习是问题集合，不是一项单独技术；
- 可能同时需要模型、算法、系统和工程；
- DeepSeek 有一些看起来有希望的想法，但尚未做通；
- 没有给出明确时间表。

**应如何理解：**  
路线优先级很高，技术成熟度仍处探索期。

## Q2. 开源生态还缺不缺人才，会不会形成垂直模型矩阵

**回答要点：**

- AI 人才短缺只是阶段性现象，培养速度会很快；
- 国内做基模的公司过多，未来会收敛；
- DeepSeek 有扶持生态的意愿，但人力有限；
- 没有给出清晰的垂直模型矩阵规划；
- 模型公司不应拿走价值链大部分利润。

**应如何理解：**  
梁文锋对人才供给乐观，对模型公司数量偏悲观，对生态治理没有给出成熟方案。

## Q3. AI 能否依靠仿真或合成数据超越人类

**回答要点：**

- 他认为可以在一定范围内超越，人类未见过的 AlphaGo 棋步是例子；
- 当前看不到这种能力的最终上限；
- 真实数据还是仿真数据并非二选一，可能有多种方法。

**边界：**  
回答较短，没有讨论开放任务的 verifier、世界反馈和数据污染问题。

## Q4. 现在建设算力集群，会不会三年后快速过时

**回答要点：**

- 英伟达卡可按约五年折旧理解；
- 国内卡因代际落后，经济寿命可能更短；
- 在合理价格下，能买到先进卡仍然划算；
- 当前更大的问题是买不到，不是算不过账。

**边界：**  
具体折旧年限受电价、利用率、代际性能、维护成本和 workload 影响，不能作为统一财务口径。

## Q5. 中国模型如何消解算力差距

**回答要点：**

- 接受一定的模型规模和时间落后；
- 用技术效率减少所需算力；
- 目标是逐渐缩短追赶时间；
- 全面超越不现实，重点方向可能局部超越。

## Q6. 持续学习为何排在通用智能之前

**回答要点：**

- 当前 Agent 的局限在于不能有效持续学习；
- 如果模型能持续学习，它会大幅提升 AI 研究效率；
- DeepSeek 希望模型首先帮助自己开发下一版模型；
- 先做出持续学习，再借助 AI 推进 AGI，是更省力的路径。

## Q7. AGI 还有多久，国产硬件能否追上

**回答要点：**

- 当前范式下，国内模型一两年内有机会接近国外，甚至更早实现部分平替；
- 这不等于 AGI，因为他至少要求模型具备持续学习；
- 国产硬件生态可能先改善，产能问题需要更久；
- 对五年后不再受同样产能约束持乐观态度。

**边界：**  
这是方向性预测，不是正式时间表。

## Q8. 公司扩大后，组织架构怎么变

**回答要点：**

- 早期没有严密架构；
- 人数扩大后必须调整；
- 部分部门建立层级，部分部门继续扁平；
- 调整已经开始，否则很多事情无法推进。

## Q9. 下一版本和更大模型的节奏

**回答要点：**

- 舒适发布节奏大约两三个月一版；
- 当前较小激活参数规模还能继续优化；
- 与国外未公开大模型的差距，需要更大规模模型弥补；
- ASR 中涉及具体版本名、参数和时间多处不清，不宜复述为确定计划。

## Q10. AGI 有没有临界点

**回答要点：**

- 没有清晰临界点；
- 进步过程连续；
- 因为 AI 能加速 AI 研究，速度可能非线性；
- 语言模型 Scaling 暂未看到上限。

## Q11. 具身、品位和直觉在路线中是什么位置

**回答要点：**

- 具身最终必须进入，因为人的大量需求发生在现实世界；
- 最理想的路径是先让 AI 帮助迭代 AI，再让 AI 帮助迭代机器人；
- 他认为当前 AI 不缺品位和直觉，缺的是持续学习。

**边界：**  
“不缺品位和直觉”是强判断。写作或局部选择上的 taste，不等于长期开放环境中的研究品位、因果理解和价值判断。

## Q12. 明确目标与不确定研究之间怎么分配资源

**回答要点：**

- ASR 中 “Office/MIS” 等词可能识别错误；
- 梁文锋认为早期持续学习研究不一定大量耗卡；
- 它更像很多人低成本探索的“摸奖”；
- 真正消耗大量资源的是模型训练、发布和效率实验；
- 公司需要让不确定问题持续处于大家的注意力中。

## Q13. 幻觉怎么解决

**回答要点：**

- 可以通过更好的 post-training 改善；
- DeepSeek 会处理，但不是当前最高优先级；
- 他更偏向把它归到产品问题。

**边界：**  
高风险领域不能把幻觉只作为体验问题，需要外部验证、拒答、责任链和人工复核。

## Q14. 数据标注和后训练差距

**回答要点：**

- 高端标注在中国没有明显成本优势；
- 国内积累起步更晚；
- 扩张瓶颈主要是时间，不是短期资金或卡；
- DeepSeek 会增加投入，但无法通过一次融资瞬间补齐；
- 核心研究人员大量参与数据工作。

## Q15. 中国相对美国有什么结构性优势

**回答要点：**

- 成本；
- 产品体验；
- 其他方面未必存在结构性优势。

## Q16. 会不会做金融、法律、医疗等垂直 Agent

**回答要点：**

- 国内商业模式尚不清晰；
- 现阶段优先通用 Agent；
- Coding Agent 优先级最高；
- 垂直 Agent 暂时靠后。

## Q17. 科研理想与资本市场如何平衡

**回答要点：**

- 公司希望两者都要；
- B 端/API 可以形成商业基础和盈利可能；
- 现有业务给 AGI 研究提供下行保护；
- 即使技术冻结，也可以转向把 API 服务做好。

## Q18. 有没有可模仿的组织对象，是否像 Bell Labs

**回答要点：**

- 没有直接模仿对象；
- 组织形式来自每个阶段的现实约束；
- DeepSeek 与 Bell Labs 不同，必须自己商业化和生存；
- 利润以外的追求不妨碍它仍是一家公司。

## Q19. TileLang 会不会牺牲底层效率

**回答要点：**

- 梁文锋认为会大幅提高开发效率；
- 高级语言减少代码量，重写算子更快；
- 当前仍主要由人编写，同时在探索让 AI 写 TileLang；
- 他接受约 1%—2% 的底层执行损失；
- 价值在于摆脱对单一硬件生态的强依赖。

# 九、结合内库后的战略 Comments

## Comment 1：DeepSeek 真正稀缺的不是“开源”，是低成本地把开放模型做成生产系统

内库 `AI_SCAN 319` 对 DeepSeek V4 的判断与本次交流会一致：开放权重只是开始。真正使用还需要模型、硬件、推理框架、缓存、Tools Prompt 和 Agent Harness 的全栈适配。

因此，DeepSeek 的可持续优势要看：

- 开源后第三方达到官方效果需要多久；
- 官方 serving 成本是否持续领先；
- 新模型能否迅速进入主流 Agent harness；
- 开源生态是否替 DeepSeek 承担适配成本；
- 生态改进是否能回流官方版本。

## Comment 2：“十个月回本”要改写成单位任务经济性

设备回收周期无法单独说明 API 生意质量。需要继续拆：

- GPU 利用率；
- input/output 比例；
- cache hit；
- reasoning token；
- 峰谷负载；
- 错误重试；
- Agent 工具调用；
- 任务成功率；
- 人工返工；
- 设备折旧和残值。

内库 `AI_SCAN 325`、`338`、`349` 的共同指向是：每百万 token 标价必须落到单位成功任务成本上比较，同时检查降价是否释放了新增工作负载。

## Comment 3：持续学习是模型命题，也是 Context Infra 命题

会议把持续学习放在 Agent 之后，抓住了长期组织使用的核心痛点。但产品不能等研究突破后再解决。

现阶段可落地的分层是：

- weights/adapters：长期稳定的技能、风格和组织直觉；
- KV/cache：高频复用的运行时状态；
- RAG/database：精确事实和最新数据；
- context window：当前任务工作区；
- logs/trace：可审计的执行历史；
- skill/SOP：专家方法、检查点和验收标准。

持续学习未来可能重写这些层的边界，但不会让它们全部消失。

## Comment 4：高质量数据不是采购品，而是组织能力

梁文锋说瓶颈是时间，内库 `AI_SCAN 320`、`322` 提供了原因：

- 专家必须先把任务讲清楚；
- rubric 和 verifier 要覆盖真实题意；
- 失败案例需要被识别和分类；
- 数据要进入可运行环境验证；
- 训练后还要检查泛化、遗忘和 reward hacking。

“一半研究员在标数据”如果属实，说明前沿模型公司的数据工作已进入研发核心，不再是外包流水线。

## Comment 5：组织是 DeepSeek 当前最强优势，也可能是扩张时最大的断点

愿景、低商业压力、自主研究和团队稳定形成了正反馈。问题是，这个系统高度依赖：

- 老员工共享隐性共识；
- 领导者对研究方向的判断；
- 同侪对质量的非正式约束；
- 相对有限的产品和客户承诺。

当 B 端、集群、合规、服务稳定性和多硬件适配扩大后，公司必须把一部分隐性 know-how 写成流程、接口、评测和责任链。组织正规化太慢，交付会失控；太快，研究文化会被吞掉。

## Comment 6：国产算力的机会来自软硬件协同，不是单点替代

具体卡量容易过时，也属于敏感信息。更值得保留的是 DeepSeek 的抽象层思路：

> 用高级 kernel DSL、编译器和 AI 辅助代码，把模型从单一硬件生态中解耦。

这与内库 `AI_SCAN 345` 的系统判断一致。芯片竞争不能只比峰值算力，要看模型架构、kernel、通信、内存、网络、编译器和集群运行是否共同优化。

## Comment 7：DeepSeek 的路线主动放弃了一部分价值捕获，也主动暴露了控制点风险

梁文锋希望伙伴做应用、第三方部署开源模型、公司只聚焦最核心一块。这能减少组织负担，也会让其他公司掌握：

- 用户入口；
- Agent runtime；
- 企业权限和审计；
- 客户流程；
- 任务日志；
- 失败与人工修正数据；
- 结果验收标准。

如果这些资产不回流，DeepSeek 可能拥有强模型，却缺少最接近真实工作的训练信号。后续应观察它能否在不重做整个应用栈的前提下建立高质量反馈通道。“要不要做更多 App”只是表层选择。

# 最终判断

这场交流会最值得记住的不是 DeepSeek 准备买多少卡、下一版模型有多少参数，也不是某个版本会在几月发布。那些数字敏感、易错，而且很快过时。

真正有长期价值的是梁文锋对公司边界的定义：

- 目标是 AGI，不让阶段性产品重写目标；
- 开源和低价直接进入组织与技术路线，不只承担市场营销功能；
- 模型公司只拿合理利润，把应用机会留给生态；
- 团队稳定比短期市场份额更重要；
- 算力不足时，用效率、聚焦和时间差竞争；
- 先让模型帮助自己做下一代模型，再谈更广泛的智能替代。

这套系统能让一家资源不占优的公司保持方向感，也有明显代价：它押注技术进步持续快于产品壁垒形成，押注开源生态能带来回流，押注未成文愿景能跨过组织扩张，押注持续学习最终可解。

判断 DeepSeek，不能停在“相信或不相信 AGI 叙事”。更有用的做法是持续检查这四个闭环是否出现：

1. 模型是否真正提高了 DeepSeek 自己的研发效率；
2. 低成本是否转化成更高的单位算力产出和单位任务经济性；
3. 开源使用是否回流成数据、生态和迭代速度；
4. 团队扩张后，研究自主与规模化交付能否同时成立。

只要这四个闭环持续增强，“克制”就是战略优势。闭环没有形成，“克制”也可能变成对商业控制点让渡过多的解释。
