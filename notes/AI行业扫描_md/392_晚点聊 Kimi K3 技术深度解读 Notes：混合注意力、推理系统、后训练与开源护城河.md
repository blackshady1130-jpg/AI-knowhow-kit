# 晚点聊 Kimi K3 技术深度解读 Notes：混合注意力、推理系统、后训练与开源护城河

> 说明：本文基于《晚点聊》播客 ASR 转写稿及用户提供的节目介绍整理。嘉宾为 RadixArk / SGLang 创始成员赵晨阳、华盛顿大学博士生曾致远，分别从推理系统和算法角度解读 Kimi K3。原稿存在少量模型名、公司名和英文术语识别错误，本文只还原能够由上下文确认的内容。涉及未公开训练细节、美国实验室内部能力、公司估值影响和未来模型节奏的部分，均按“嘉宾观察或推测”处理，不等同于独立核验事实。节目中的价格、性能和 benchmark 数字也保留其当时口径，不应脱离模型版本、任务与部署环境外推。

## 一句话总览

Kimi K3 的意义，不只是一个接近闭源前沿的 2.8T / 3T 级开放权重模型，而是它把一组此前只在小模型或论文中成立的激进技术，同时扩展到了主线前沿模型：KDA 线性注意力与 Gated MLA 全局注意力混合、NoPE、Attention Residuals、近千专家的 Quantile Balancing、Per-head Muon、FP4 QAT，以及面向 agent 的训练环境和 kernel development agents。

这期访谈最有价值的判断可以概括为四点：

1. **架构创新已经从“替换 Transformer”变成“重组 Transformer”。** K3 几乎替换了原始 Transformer 的每个部件，但仍保留了 attention 作为信息混合接口。未来更可能出现异构混合架构，而不是某一种注意力路线彻底取代其他路线。
2. **模型贵不贵、快不快，必须按任务总成本和推理链路拆解。** K3 当前体感较慢，既有供给因素，也有新架构尚未被 Serving Stack 完全吃透的原因；它在长任务中的 token 效率可能抵消较高单价。
3. **开放权重并未开放下一代模型的生产能力。** 权重是一次训练的结果，环境、验证器、数据生产系统、算力和迭代机制才是持续产生新权重的流水线。
4. **模型“自我改进”不是跨过某个神奇阈值，而是越来越多研发环节被 agent 接管。** 在 kernel、优化器等目标明确、奖励便宜、结果可验证且难作弊的领域，闭环已经出现；通用递归自我改进仍受环境、评测和泛化能力限制。

## 最高价值观点清单

### 1. K3 的里程碑意义，来自“激进架构在超大规模上真正成立”

节目将 K3 视为首批达到约 3T 总参数规模的开放权重模型之一。规模本身不是唯一价值，更重要的是它没有沿用保守的全注意力架构，而是把多项新技术组合后稳定训练、完成后训练并交付真实用户。

此前 Kimi Linear 已验证 KDA 与全局注意力混合，但模型规模只有数十 B。K3 把同类设计放大约数十倍，并支持百万上下文。这说明一项架构从论文走向前沿模型，需要同时跨过：

- scaling law 是否成立；
- 大规模训练是否稳定；
- 后训练是否能恢复和放大能力；
- 推理系统是否能部署；
- 长任务中是否真的产生用户价值。

“在小模型上有效”与“能成为前沿模型主干”之间，隔着一整套系统工程。

### 2. K3 已进入高价值长任务区间，但不等于全面比肩闭源模型

曾致远的个人使用体感是，K3 在不少任务上接近当时的 Claude 前沿模型，长时间运行、完成复杂任务和前端开发尤其突出。赵晨阳也提到 K3 生成小游戏和网页的体验，认为它的前端生成能力非常有辨识度。

局限也很具体：

- 小任务反馈偏慢；
- 面对用户尚未想清楚的复杂任务，模型有时会直接替用户做决定；
- 更理想的行为应是识别高影响歧义并发起讨论；
- 当前 API、Serving Stack 与算力供给仍影响总体体验。

因此，“比肩 Fable”只能在具体任务上讨论。K3 的突破是把开放模型推进到一批真实 agent 工作流，而不是证明所有能力都与最强闭源模型等价。

### 3. 前端能力突出，背后是评测、数据和视觉反馈闭环的共同作用

嘉宾认为，模型在某个垂直方向异常突出，最直接的解释通常是该方向的 eval 和训练数据做得更好。

K3 的前端能力可以从公开报告中看到几个线索：

- 单独构建 WebDev 类评测；
- 预训练增加代码与渲染结果配对的多模态数据；
- 后训练加入 Web Development 任务；
- 原生多模态能力允许模型写代码、查看截图、再修改代码；
- 强化学习可以把页面视觉结果转化为反馈信号。

这类“代码 → 渲染 → 视觉检查 → 修改”的 watching loop，比单纯模仿高质量代码更接近真实前端开发。

### 4. 技术报告越详细，并不代表核心配方越开放

嘉宾观察到，近年的模型技术报告往往更愿意披露架构、预训练和基础设施设计，却对后训练数据、环境、奖励和 recipe 描述更少。

这不是因为后训练变得不重要。恰恰相反，agent 能力越来越依赖：

- 任务环境；
- 难题生成；
- 验证器；
- rollout 策略；
- harness 配置；
- 失败筛选与训练配比。

公开模型结构可以帮助社区部署这一代模型；没有环境和验证器，外部团队仍难复现下一代模型。

### 5. K3 对闭源实验室估值的影响，取决于企业是否能承担自部署

曾致远转述，美国部分前沿实验室从业者担心强开放模型会影响闭源实验室的商业预期。逻辑并不复杂：

- 企业不愿把私有代码和业务数据发送给第三方 API；
- 开放模型经过领域微调后已足够完成内部任务；
- 企业或托管服务商有能力部署和维护模型；
- 数据主权与长期成本足以抵消自部署复杂度。

满足这些条件时，企业可能从闭源 API 转向私有部署。

但这不是自动发生的。超大模型需要昂贵算力、推理框架、量化、监控和后训练能力。开放权重降低了模型获取成本，却没有消除运营门槛。

### 6. 开放权重的安全问题具有不可逆性

赵晨阳用“坐标一旦广播就无法收回”形容开放权重。权重发布后会被镜像、量化、微调和再分发，衍生版本快速增加，原发布方无法通过下架恢复控制。

因此，开放模型安全不能沿用普通 SaaS 发布后的召回逻辑。决策必须发生在开放之前，并同时考虑：

- 能力滥用风险；
- 防守者获取能力的价值；
- 权重全球扩散的不可逆性；
- 模型限制是否会被微调移除；
- 国际协调是否可能；
- 对创新、竞争与公共研究的影响。

嘉宾总体支持在有限治理下持续分享前沿能力，但并不主张把所有环节无条件开放。

### 7. “开源是否追平闭源”不是单一模型分数问题

模型只是 AI 价值链的一部分。即使开放模型在 benchmark 上追平闭源模型，双方仍可能在以下方面存在差距：

- 数据生产系统；
- RL 环境与任务图谱；
- 验证器和 reward 设计；
- 训练与推理算力；
- 内部最强模型的可用时间；
- 产品分发和真实用户反馈；
- 模型迭代速度。

开放权重缩小的是某一时点的能力差距，未必缩小下一代模型的研发周期。

### 8. 权重是结果，环境才是可复用的生产资料

本期最值得反复引用的一句话是：

> 权重是一次训练的产物，环境是能够反复复用并产生下一代权重的流水线。

开放 K3 权重意味着全世界能够使用这一代智能，但如果训练环境、知识图谱任务系统、原始领域专家、验证规则和算力管线没有开放，社区仍未获得“怎样训练出 K4”的方法。

这也重新定义了模型公司的护城河：长期价值不只在模型文件，而在持续构造任务、产生反馈和完成迭代的能力。

### 9. Transformer 已成为“忒修斯之船”

赵晨阳认为，今天已不存在“老老实实做 Transformer”。K3 对原始结构做了大量替换：

- attention 由 KDA 线性注意力和 Gated MLA 全局注意力混合；
- residual connection 变成深度方向的 attention；
- FFN 使用高度稀疏的 MoE；
- 显式位置编码基本移除；
- 优化器、精度和路由也被重新设计。

Transformer 更像一个可组合接口：用可微模块反复混合序列和深度上的信息。部件可以不断替换，attention 这一“船名”仍被保留。

对新架构研究的启示是，不一定要推倒整个范式。一个优秀组件只要能与现有系统组合，并在 scaling 中证明自己，就可能在很短时间进入主线模型。

### 10. 模型自我改进不是突然跨过阈值，而是研发自动化比例持续上升

节目反对“某一代模型突然学会自我进化”的戏剧化叙事。

更接近现实的过程是：模型团队将越来越多工作交给 agent，包括检索、生成训练任务、筛选样本、构建 RL 环境、运行 eval、分析失败和优化 kernel。人类介入从逐步规定动作，转向定义目标、约束和验收标准。

这是一条连续曲线：

`人工完成 → AI 辅助 → AI 承担子流程 → AI 完成端到端流程 → 人类只定义目标和验收`

所谓正反馈，来自研发流程逐步被自动化，而不是模型脱离外部监督后凭空变强。

### 11. Kernel 是递归改进最先成立的领域之一

K3 技术报告披露，早期 checkpoint 已能参与优化后续训练和推理所需的 kernel。任务覆盖单算子、算子融合、不同开发语言和 BF16、FP8、FP4 等精度。

这个闭环之所以成立，是因为 kernel 同时满足三个条件：

- **奖励便宜**：在硬件上运行即可测量速度；
- **结果可验证**：与 PyTorch 基准比较数值正确性；
- **作弊空间有限**：可以检测打表、缓存输出或恶意重放等投机方式。

奖励设计采用两层标准：先保证正确性，再比较专家实现和硬件上限。模型越接近物理极限，reward 越高。

这说明受限领域的递归改进已经发生，但它依赖清晰边界，不能直接外推成通用智能的自我进化。

### 12. RSI 的真正瓶颈往往是 Eval 和 Harness

如果结果无法便宜、稳定地评估，模型就无法知道哪次尝试更好。

数学和早期 coding 进步快，一个重要原因是答案、测试和性能较容易验证。新闻报道、战略判断和大型仓库功能则需要更复杂的质量标准，reward 更昂贵、更主观，也更容易被表面指标欺骗。

因此，模型能力提升后，下一个瓶颈会转向：

- 能否构建真实任务；
- 能否获得环境反馈；
- 能否发现 reward hacking；
- 能否评估长任务的最终质量；
- 能否把验证器规模化运行。

### 13. K3 当前的“慢”，不能简单归因于算力不足

赵晨阳把用户感知的速度拆成三个指标：

1. **首 token 延迟（TTFT）**：请求发出后多久开始返回；
2. **单用户解码速度**：输出开始后 token 之间的间隔；
3. **排队时间**：大量用户竞争推理资源时等待多久。

三者成因不同。算力供给主要影响排队和总体吞吐；首 token 延迟还高度依赖前缀复用和 Prefill；解码速度则受模型结构、KV / recurrent state 读写和 kernel 优化影响。

新架构发布初期，Serving Stack 还没有完成针对性优化，模型可能暂时处于“又贵又慢”的阶段。当前速度更能反映架构有多新、适配有多难，而不一定代表架构长期上限。

### 14. Agent 模型应比较任务总成本，而不是百万 token 标价

节目引用的当期 API 定价显示，K3 单 token 价格明显高于此前一些中国模型。但赵晨阳认为，在复杂 agent 场景中，更有意义的指标是：

`单任务总成本 = 输入 + 输出 + 缓存 + 工具调用 + 重试 + 绕路 + 人工接管 + 失败返工`

一个单价便宜的模型，如果需要更多 token、反复重试或无法完成任务，最终成本可能更高。

节目引用 Kimi 内部 benchmark 说明，K3 在部分设置下以较低成本接近更强模型；这些数字属于发布方口径，不能直接外推。但它提出的比较单位是正确的：模型经济性应按成功任务计算。

### 15. 前缀复用是长上下文 Agent 的关键基础设施

coding agent 的请求会反复携带仓库、系统提示、工具定义和历史状态。大量上下文在相邻请求之间相同，真正新增的部分很小。

如果共享前缀命中，Serving 系统可以复用已经计算的状态，显著降低 Prefill、TTFT 和成本。若无法命中，即使增量问题很短，也要重新处理几十万 token。

因此，前缀缓存不是小优化，而是长任务是否经济可行的前提之一。

### 16. KDA 让前缀缓存从“只追加笔记本”变成“反复擦写白板”

传统 KV cache 基本是 append-only：旧前缀计算后不再修改，后续 token 继续追加。KDA 的 recurrent state 则会随每个 token 原地更新。

这给跨请求复用带来新难题：

- 一个请求读取状态时，另一个请求可能正在改写；
- 需要 snapshot、copy-on-write 等并发控制；
- 哈希块与物理块的粒度可能要解耦；
- 缓存生命周期不再只是创建和追加，还包括覆盖、共享与回退。

线性注意力减少了长上下文存储，却把更多复杂度转移给状态管理系统。

### 17. NoPE 不是没有顺序，而是不使用显式位置编码

K3 没有采用常见的显式位置编码。模型仍然知道 token 先后，因为 KDA 的 recurrent update、gating 和 decay 本身对顺序敏感。

NoPE 对扩展上下文有一个直接好处：当训练从 8K、64K、256K 逐步扩到 1M 时，不需要额外处理 RoPE base、插值和外推参数。

这项设计并非 K3 首创，真正的工程意义在于它被成功扩展到约 3T 参数和百万上下文。

### 18. Quantile Balancing 解决近千专家下的极端负载均衡

K3 的 MoE 路由设置约为从 896 个 routed experts 中为每个 token 选择 16 个，稀疏程度很高。

如果专家负载失衡：

- 冷专家得不到足够 token 和梯度，容量被浪费；
- 热专家收到过多 token，形成计算和通信瓶颈；
- 训练可能因路由失控而不稳定。

传统 auxiliary load-balancing loss 会干扰主训练目标。DeepSeek V3 类方法改用 bias 调整，但固定步长仍需调超参数。

Quantile Balancing 利用当前 routing score 分布，估计每个专家距离 top-16 门槛的差值，直接计算更合适的 bias。它从“知道专家过冷或过热”推进到“估计应该调多少”。

嘉宾推测，这可能是 K3 能稳定扩到超大 MoE 的关键因素之一；公开报告无法证明它是唯一原因。

### 19. KDA 与 MLA 证明：线性注意力和全局注意力不必二选一

K3 大约以 3:1 的方式混合 KDA 与 Gated MLA：多数层使用更高效的线性注意力，周期性插入全局注意力，模型末端再保留全局层。

两者分工不同：

- KDA 用固定大小 recurrent state 高效累积序列信息；
- MLA 让 token 直接访问完整历史，保留高容量全局交互；
- KDA 负责效率和顺序敏感；
- MLA 缓解固定状态压缩导致的细节遗忘。

3:1 比例来自小模型实验和 scaling 验证，不代表在 3T 规模上已穷尽所有比例。超大模型无法为每个部件做完整 ablation，架构研发仍高度依赖小模型代理实验。

### 20. 线性注意力管理遗忘，但不能消除容量瓶颈

KDA 把任意长历史压入固定大小的 recurrent state。优点是状态不随上下文线性增长，代价是信息在有限容量中相互干扰，早期细节可能衰减。

Delta rule、channel-wise forget gate 和 retention lower bound 能更聪明地控制写入与遗忘，但不能创造无限容量。

K3 缓解百万上下文遗忘的关键仍是混合架构：KDA 不必独自记住所有细节，周期性的 MLA 负责重新访问完整历史。

### 21. “6.3 倍解码加速”有严格适用条件

赵晨阳特别澄清，6.3 倍来自更早的 Kimi Linear 论文，不是 K3 技术报告直接测得的统一结论。

它描述的是：在相近模型规模、约 1M 上下文的特定设置下，以线性注意力为主的混合架构相比传统全注意力架构，解码 token 速度可达到约 6.3 倍。

机制来自状态规模差异：

- 全注意力每生成一个 token，都要读取随上下文增长的 KV cache；
- 线性注意力读取固定大小 recurrent state；
- 上下文越长，差距越明显。

嘉宾分享的 SGLang 实现估算中，KDA 层每请求状态约为固定 54MB，而 MLA 层仍按 token 增长，百万上下文约产生 27GB 量级状态。数字依赖具体实现和精度，作用是说明混合架构如何削减大部分层的存储与搬运。

### 22. Attention Residuals 把 attention 从序列方向旋转到深度方向

传统 residual connection 将之前各层输出不断相加。模型越深，新层写入的信息越容易被庞大的 residual stream 稀释，后层也无法直接选择要读取哪一层。

Attention Residuals 的思路是：

- 正常 attention 在 token 之间选择信息；
- Attention Residuals 在不同深度的 layer representation 之间选择信息；
- 每层使用可学习 query，与当前 token 在浅层的表示匹配；
- 后层可选择性读取更早层产生的信息。

K3 实际使用 block 化设计，而不是让所有层完全互相 attention，以控制内存和通信成本。

### 23. Attention Residuals 与 mHC 解决同一问题，但信息压缩方式不同

mHC 使用多条 residual streams，每层动态混合输入并把输出分发回不同 stream；历史信息最终仍递归压缩进固定数量的状态。

Attention Residuals 更像为深层模型提供历史目录，允许跨层选择性读取。从理论表达能力看，它更接近深度方向的全局 attention；代价是保留历史 representation 带来的内存和通信负担。

两条路线都已在前沿模型中成立。未来胜负更可能由具体 execution、系统成本和训练稳定性决定，而不是概念上的表达能力上限。

### 24. Per-head Muon 的目标是让不同注意力头获得更均衡的更新

优化器决定如何把梯度转化为稳定、有效的参数更新。Muon 会先对 momentum 近似正交化，避免更新过度集中在少数方向。

普通做法把多头注意力的大投影矩阵一起处理，规模较大的 head 可能主导更新。Per-head Muon 将不同 attention head 分开做归一化或正交化，使各头更新尺度更均衡。

算法概念不复杂，工程实现却有难点：QKV 常被融合和切分，优化器状态分散在不同 GPU rank 上。系统需要重建 head 边界、合并小矩阵并重叠通信与计算，否则优化器收益会被分布式开销吞掉。

### 25. AI 研究优化器，不只要提出公式，还要设计可靠的小规模代理实验

优化器研究天然适合 agent：提出方案、写代码、跑实验、观察 loss 和稳定性、再修改，目标相对清楚。

但真正昂贵的问题是，小模型上有效的优化器能否扩到大模型、长训练周期和不同参数形状。

因此，auto research 的更高价值可能是同时研究两件事：

1. 哪个优化器更好；
2. 哪种小规模实验最能预测大规模结果。

如果 agent 能找到高相关、低成本的 proxy experiment，就能减少大规模失败实验，比单纯自动搜索优化器更节省算力。

### 26. MOPD 首先是一种组织解耦方法

K3 先训练九个领域专家，再通过 Multi-Teacher On-Policy Distillation 合并成统一模型。

这样做的重要原因不是理论上一定优于联合 RL，而是不同领域的后训练已经高度异构：

- 数据不同；
- 环境不同；
- reward 不同；
- rollout 长度不同；
- harness 不同；
- 训练算法和基础设施也可能不同。

如果把 coding agent、general agent、reasoning 等任务塞进一次联合 RL，所有团队的 recipe 会强耦合，合版压力巨大。

MOPD 让各团队只需交付训练好的专家模型，再由统一流程蒸馏能力。它把“合并九套训练系统”变成“合并九个模型的行为”。

### 27. 能否写成论文，与方法是否重要不是同一回事

Attention Residuals 能形成干净的研究问题、明确基线和可比较指标，因此适合发表论文。MOPD 更像绕开复杂组织和训练耦合的工程 recipe，很难构造一个干净、普适的对照实验。

这意味着，公开论文会系统性低估一类重要创新：

- 训练管线组织方式；
- 数据与环境的配比；
- 合版策略；
- 失败处理；
- 训练和推理协同；
- 内部工具与流程。

模型能力不只来自可发表的新算法，也来自难以公开、难以归因的系统方法。

### 28. On-policy 与 Off-policy 蒸馏的区别，在于轨迹由谁生成

蒸馏的技术定义是把 teacher 的能力传给 student，目的不一定是压缩模型，也可以是领域合并。

**Off-policy 蒸馏：** teacher 预先生成固定答案或轨迹，student 在离线数据上模仿。社交媒体讨论“从闭源 API 蒸馏模型”时，通常指这一类。

**On-policy 蒸馏：** student 自己生成轨迹，teacher 对 student 当前轨迹提供打分或稠密监督，再更新 student。

On-policy 数据始终贴近 student 当前分布，更适合能力合并和持续改进，但通常需要更深入访问 teacher 的 logits、权重或评分能力。只有闭源 API 最终输出时，往往只能做有限的 off-policy 模仿。

### 29. “自己蒸馏自己就原地飞升”仍缺少可扩展外部信号

如果没有可验证环境、外部奖励或新信息，模型很难仅靠自己的输出持续提高。

蒸馏可以搬运、压缩或合并已有能力，但并不自动创造正确的新知识。真正的提升仍需要 scalable supervision，例如测试结果、硬件性能、环境状态、人类评价或更强 teacher 的信息。

技术名称中出现 distillation，不代表模型已经实现无外部监督的自我进化。

### 30. KDA 让投机采样回退机制必须重写

投机采样由小模型先猜一批 token，再让大模型一次验证。若只接受前几个 token，大模型必须回退到猜测前状态。

传统 attention 只需丢弃未接受 token 的尾部 KV。KDA 会原地更新 recurrent state，完整快照 69 层状态的代价很高。

SGLang 的做法是只存每步状态的极小投影，约 1KB 量级；回退时从上一个 checkpoint 出发，重放被接受 token 对状态的更新。它类似记录棋步而不是每一步复制整个棋盘。

嘉宾称，Kimi 报告也采用了相近思路。这是架构创新如何迫使推理系统重新设计的典型案例。

### 31. 更强 Agent 需要更高权限，也需要更强隔离

Agent Env 的设计哲学不是通过限制工具能力保证安全，而是用更好的沙盒隔离允许模型更自由地探索。

Kimi 从容器路线转向 Firecracker microVM，以减少单个 agent 导致操作系统崩溃、死锁或影响其他沙盒的风险。

核心关系是：

`隔离越可靠 → 可授予权限越高 → 探索空间越大 → 训练信号越接近真实任务`

安全和能力并非简单零和。更好的系统隔离可以同时提高 agent 能力边界和事故控制能力。

### 32. Partial Rollout 用算法宽容换取系统吞吐

Agent RL 的轨迹可能包含上千次工具调用和百万 token，同一 batch 中少数超长任务会拖住所有请求。

Partial Rollout 不等待全部轨迹完成：达到一定完成比例后，已结束轨迹先进入训练，未结束轨迹保存状态并在下一轮续跑。

代价是轨迹前后可能来自不同 checkpoint，产生 off-policyness。K3 使用正则和局部策略约束，容忍有限偏差，换取采样系统更高利用率。

这说明前沿 RL 并非追求数学上的绝对纯净，而是在统计有效性和系统吞吐之间做工程权衡。

### 33. 训练环境应覆盖多种 Harness，避免模型只会一种工作流

K3 训练管道将 agent harness 表示为可组合模块，包括：

- 工具接口；
- system prompt；
- 上下文管理；
- Skills；
- Memory；
- 不同工作流配置。

训练中组合多种 harness，可以减少模型过拟合某个工具或产品。模型不能只学会“美团流程”，换到“饿了么”就失效；对海外产品而言，同样可能表现为只会 Gmail、不适应 Outlook。

随着 agent 产品增多，harness 泛化会成为独立能力维度。

### 34. Flash KDA 的难点是串行状态依赖和缓存生命周期

Softmax attention kernel 主要受内存带宽限制；KDA kernel 还要处理 chunk 间递归状态的串行依赖。

最朴素的实现每算完一个 chunk 再传递状态，会导致计算资源等待。Flash KDA 尝试重叠 chunk 内计算与跨 chunk 状态传输。

由于旧状态可能被覆盖，kernel 还必须知道：

- 状态何时持久化；
- 写入哪个 slot；
- 哪些请求正在共享读取；

- 回退和复用时怎样恢复。

KDA 模糊了 kernel 与缓存管理的边界，推理框架需要更完整的状态生命周期抽象。

### 35. QAT 的价值不仅是省显存，也是保持 RL 训推一致

K3 从 SFT 阶段开始进行 Quantization-Aware Training，并尽量让 RL rollout 与训练阶段使用相同量化配置。

如果采样时使用 FP4，训练更新时却假设 BF16 策略，两个“同一 checkpoint”实际产生的 token 概率会有偏差。这也是一种 off-policyness；对于高度稀疏 MoE，细小误差可能放大成训练不稳定。

因此，QAT 的作用包含两层：

- 让模型更早适应量化噪声；
- 让产生数据的策略与被优化的策略尽可能一致。

实现这一点需要训练、推理和 kernel 团队高度协同。

### 36. Kernel Development Agents 会影响芯片生态，但不会自动打破 CUDA 护城河

K3 已能为不同 GPU / GPGPU 目标生成和优化 kernel，这可能缩短新芯片适配新模型的时间。开放推理框架也让国产或替代芯片更快进入模型生态。

但同一套 agent 未必能直接泛化到下一代 DSL、指令和硬件特性。英伟达也可以使用 kernel agents 优化自己的下一代工具链。

因此，kernel agent 降低了手工优化成本，却不会天然只帮助挑战者。最终影响取决于：

- agent 对新硬件的泛化速度；
- 厂商能否提供可验证环境；
- 编译器、DSL 和调试工具是否开放；
- 生态是否能快速反馈真实 workload。

### 37. 开放模型短期超过闭源仍有“内部模型代差”障碍

曾致远判断，未来数月开放模型全面超过闭源仍有难度。原因是开放模型通常追赶已经公开的闭源模型，而前沿实验室内部可能已有领先公开版本半代到一代的系统。

这是嘉宾基于行业观察的推测，无法从公开信息验证。它提醒我们区分三条前沿：

1. 对公众开放的最强模型；
2. 公司内部可用的最强模型；
3. 已经训练完成但尚未形成产品的模型。

开放与闭源的比较通常只看到第一条。

### 38. 持续学习首先缺评测，而不是缺一句定义

“模型能否持续学习”不是 0 或 1。模型可能会在某类任务中快速适应，却无法把经验迁移到新 DSL、新工具或新环境。

即使 kernel 是最容易验证的领域，现有 agent 面对下一代工具链仍可能需要额外训练。这说明泛化范围尚有限。

在把持续学习定义为下一代模型标志之前，需要建立能够衡量以下内容的 eval：

- 学到新任务需要多少样本和计算；
- 新知识能否保留；
- 是否破坏旧能力；
- 能否迁移到新工具和新环境；
- 学习过程是否安全、可控、可回滚。

### 39. 模型进步可能经历平台期，但突破未必来自全新范式

嘉宾认为，模型发展仍可能出现平台期。突破不一定是推翻 Transformer，也可能来自架构、数据、优化器、RL 环境和 Serving 的一系列改进共同抬高平台。

最近的进展在研究者眼中未必是范式革命，但对普通用户已经带来显著体验变化。这说明“技术是否本质突破”和“产品是否出现跃迁”是两个不同问题。

## K3 技术架构总览

| 模块 | 要解决的问题 | K3 的做法 | 主要收益 | 新增工程代价 |
| --- | --- | --- | --- | --- |
| 序列信息流 | 百万上下文下 KV 与计算爆炸 | 约 3:1 混合 KDA 与 Gated MLA | 大多数层状态固定，全局层保留完整交互 | recurrent state 复用、并发和回退更复杂 |
| 位置信息 | 长上下文外推和 RoPE 调参 | NoPE，依靠 KDA 的顺序敏感更新 | Progressive context extension 更直接 | 顺序建模高度依赖 KDA 设计 |
| MoE 路由 | 896 专家、top-16 下负载失衡 | Quantile Balancing | 不引入 auxiliary loss，bias 调整更精细 | 依赖 score 分布估计与大规模验证 |
| 深度信息流 | 深层 residual stream 中新信息被稀释 | Attention Residuals | 后层可选择读取浅层 representation | 保存历史层表示增加内存和通信 |
| 优化器 | 多头更新尺度不均、训练不稳定 | Per-head Muon | 各 attention head 更新更均衡 | 分布式 QKV 切分下需重建 head 边界 |
| 低精度训练 | FP4 噪声与 RL 训推不一致 | SFT 起做 QAT，采样与训练配置对齐 | 降低量化损失和策略偏差 | 需要独立 kernel 与训练系统支持 |
| Agent 后训练 | 多领域 recipe 强耦合 | 九领域专家 + MOPD 合版 | 团队可独立迭代，统一模型吸收能力 | teacher 评分与合版仍需稳定系统 |
| Agent 环境 | 长轨迹、权限、安全与 harness 过拟合 | microVM、Partial Rollout、可组合 Harness | 更高权限、更高采样吞吐、更强泛化 | 状态持久化和 off-policy 控制更难 |

## 推理系统拆解

### 一、速度问题应按三个阶段诊断

| 用户感知 | 核心指标 | 主要影响因素 |
| --- | --- | --- |
| 请求发出后迟迟无响应 | TTFT | 排队、Prefill、前缀命中、上下文长度 |
| 已开始输出但逐字很慢 | Inter-token latency | Decode kernel、状态读取、模型结构、批处理 |
| 高峰期明显变慢 | Queue time | 可用算力、调度、并发、请求长尾 |

只说“模型慢”无法指导优化。三项指标需要分别测量。

### 二、混合注意力改变了缓存形态

全注意力的 KV cache 随 token 增长，读取多、状态不回写；KDA 使用固定 recurrent state，存储少但每步更新。

推理框架因此需要同时管理：

- append-only KV；
- 可变 recurrent state；
- 前缀树共享；
- copy-on-write；
- checkpoint 与 rollback；
- 投机采样重放；
- 跨请求并发安全。

未来推理框架的价值，会越来越体现在能否统一管理多种 attention 状态，而不只是支持更多模型名称。

### 三、长上下文收益主要来自降低状态搬运

长任务解码的瓶颈常不是算术运算，而是每生成一个 token 都要搬运巨大的历史状态。

KDA 把多数层的历史压缩成固定状态，MLA 只在少数层保留按上下文增长的全局信息。上下文越长、并发越高，节省的 HBM 和搬运越有价值。

### 四、新架构的性能有一个“生态学习曲线”

模型发布后，推理团队需要完成：

- 正确性适配；
- kernel 优化；
- 量化；
- 前缀缓存；
- 批处理和调度；
- 多硬件后端；
- 故障和回退机制。

初始 API 速度只是起点。评价新架构要同时看发布当日性能、一个月后的优化空间和跨平台可移植性。

## 后训练与自动研究

### 一、九个专家先分后合，是模型组织架构的映射

不同领域小组拥有自己的任务、环境和训练系统。MOPD 允许团队围绕领域最优独立工作，再把模型行为汇总到统一 student。

这类似软件工程中的接口化：每个团队交付可消费的模型能力，而不是要求所有团队共享同一套内部实现。

### 二、蒸馏至少要区分四种目的

| 蒸馏方式 | 数据由谁生成 | 目的 | 主要边界 |
| --- | --- | --- | --- |
| 大模型到小模型 | Teacher | 模型压缩、降低推理成本 | Student 容量限制 |
| 外部 API 离线蒸馏 | Teacher 固定输出 | 模仿回答、推理或轨迹 | 通常是 off-policy，监督较稀疏 |
| 多领域专家合版 | Student rollout，多个 Teacher 评分 | 合并不同领域能力 | 需要 teacher 深度访问和稳定评分 |
| 自蒸馏 / 迭代蒸馏 | 当前或历史模型 | 稳定、迁移或放大已有能力 | 没有外部信号时无法无限创造能力 |

### 三、自动研究需要“研究环境”，不只是更强模型

一个可持续的自动研究系统至少需要：

1. 可生成候选方案；
2. 可执行实验；
3. 有便宜、可靠的指标；
4. 能检测作弊和指标投机；
5. 能判断小实验是否可扩展；
6. 能保存失败和复现过程；
7. 有算力预算与停止条件；
8. 人类能审核高风险变化。

Kernel optimization 满足大部分条件，因此进展更快；开放式科学和产品研究仍缺稳定 verifier。

## 开源模型真正开放了什么

### 已经开放的层

- 某一代模型权重；
- 模型结构与部分训练说明；
- 部分推理 kernel 和 Serving 适配；
- 社区量化、微调和衍生版本；
- 部分 Agent 环境代码或接口；
- 使用、研究和私有部署的可能性。

### 通常仍然保留的层

- 完整预训练与后训练数据；
- 数据生产和筛选流水线；
- 领域专家的原始 checkpoint；
- RL 任务环境全集；
- 验证器、reward 和反作弊策略；
- 内部最强模型和研究 agent；
- 大规模算力、调度与实验基础设施；
- 产品用户反馈与数据飞轮；
- 下一代模型的路线和失败经验。

### 更准确的开放程度模型

可以把开放分成五层：

1. **访问开放**：公众能否调用 API；
2. **权重开放**：能否下载和私有部署；
3. **修改开放**：许可证是否允许微调、量化和商业使用；
4. **复现开放**：数据、代码和训练 recipe 是否足以重现本代模型；
5. **迭代开放**：环境、验证器和算力系统是否足以训练下一代。

K3 显著推进了前几层，但没有让最后一层完全开放。

## 可复用判断框架

### 框架一：评价一项模型架构创新

每项技术都问五个问题：

1. **瓶颈是什么**：算力、内存、通信、稳定性还是能力？
2. **机制是什么**：它具体改变哪条信息流或训练过程？
3. **收益在哪里**：训练、Prefill、Decode、长上下文还是后训练？
4. **复杂度转移到哪里**：Kernel、缓存、调度、数据还是验证器？
5. **证据边界是什么**：小模型、消融实验、技术报告还是生产 workload？

KDA 降低 KV 增长，却增加 recurrent state 生命周期复杂度，是“收益与复杂度转移”的典型案例。

### 框架二：评价 Agent 模型经济性

不要只比较 token 单价，至少计算：

`单位成功任务成本 = 模型输入 + 输出 + 缓存 + 工具 + 沙盒 + 重试 + 验证 + 人工接管 + 失败返工`

同时记录：

- 成功率；
- wall-clock time；
- token 总量；
- 前缀命中率；
- 工具调用次数；
- 人工介入率；
- 长尾任务比例；
- 最终结果质量。

### 框架三：判断一个领域是否适合模型自我改进

优先选择满足以下条件的任务：

1. 目标可以形式化；
2. reward 计算便宜；
3. 结果可重复验证；
4. 作弊方式有限且可检测；
5. 实验周期足够短；
6. 失败成本可控；
7. 训练环境与真实环境差距较小。

Kernel、编译优化和部分数学任务更接近这一条件；新闻、战略和开放式研究仍较远。

### 框架四：分析蒸馏争议

看到“某模型靠蒸馏”时，先追问：

1. Teacher 和 student 分别是谁？
2. 蒸馏目的是压缩、追赶、合版还是稳定？
3. 轨迹由 teacher 还是 student 生成？
4. Teacher 提供最终答案、token 概率还是稠密评分？
5. 是否有可扩展外部监督？
6. 蒸馏后还进行了多少 RL 和环境训练？
7. 是否有控制变量证明能力增益来自蒸馏？

### 框架五：评估开放模型护城河

按以下链条审视，而不是只看 benchmark：

`权重 → 推理系统 → 私有部署 → 微调 → 数据 → 环境 → Verifier → RL → 产品分发 → 用户反馈 → 下一代权重`

越靠后的环节越能持续复利，也越难通过下载权重复制。

### 框架六：评估持续学习

持续学习需要一组分阶段指标：

- 获取新技能的样本效率；
- 适应新工具的时间；
- 旧能力遗忘程度；
- 跨环境迁移；
- 长期知识保留；
- 对错误经验的纠正；
- 更新过程的安全与可回滚性。

没有这些指标，“持续学习”仍只是方向口号。

## 反共识与金句

以下为对节目观点的中文提炼，非逐字引语。

1. **这个世界上早已不存在“老老实实做 Transformer”；Transformer 是 AI 研究里的忒修斯之船。**
2. **优秀的新组件不需要等一个新范式，只要能组合、能扩展，就会被主线模型迅速吸收。**
3. **权重是一次训练的产物，环境才是不断产生下一代权重的流水线。**
4. **开放权重缩小的是能力快照差距，不一定缩小迭代速度差距。**
5. **模型当前慢，很多时候说明 Serving Stack 还没有学会这套新架构，而不是架构天然慢。**
6. **Agent 模型的价格单位应该是成功任务，不是百万 token。**
7. **线性注意力与全局注意力不是路线之争，而是可以承担不同功能的组件。**
8. **KDA 节省了 KV，却把复杂度搬进了状态管理、回退和并发控制。**
9. **6.3 倍不是 K3 的通用速度结论，而是百万上下文特定对比下的解码优势。**
10. **AI 自我改进没有神奇临界点，只有越来越多研发步骤被自动化。**
11. **RSI 最先在 reward 便宜、可验证、难作弊的领域发生。**
12. **MOPD 的第一价值可能不是算法更强，而是让九个训练团队不必共享一套复杂 recipe。**
13. **蒸馏可以搬运能力，但没有外部监督就不能无限创造能力。**
14. **更强 Agent 不一定需要更少权限；它需要更强隔离来安全获得更多权限。**
15. **训练和推理不是两个系统，RL 要求产生数据的模型与被更新的模型尽可能一致。**
16. **持续学习首先缺少的是尺度和评测，而不是定义。**
17. **很多技术路线都能到达前沿，最终差距常在 execution。**

## 对行业各方的含义

### 对模型公司

- 模型架构、后训练环境和 Serving 必须共同设计。
- 发布权重可以获得生态，但长期护城河仍是环境、Verifier、数据和迭代速度。
- 高度异构的 agent 领域适合专家团队独立训练，再通过蒸馏合版。
- 研究 agent 应优先进入可验证、高反馈密度的内部任务。
- 量化不能只在部署末端补做，RL 训推一致需要从训练阶段规划。

### 对推理基础设施公司

- 异构 attention 会成为常态，统一状态抽象比单模型适配更重要。
- Prefix Cache 需要同时支持 append-only KV 和可变 recurrent state。
- 投机采样、回退、快照、copy-on-write 和状态重放会成为核心能力。
- 性能优化要按 TTFT、Decode 和 Queue 分拆，不用一个 tokens/s 掩盖全部问题。
- 新架构发布后的适配速度，将直接决定开放模型能多快进入生产。

### 对 Agent 应用公司

- 模型选型应测单位成功任务成本和 wall-clock time。
- 不能假设模型在一个 harness 上训练后会自然适配所有工具组合。
- 高权限 agent 必须配套 microVM、权限隔离、审计和可回滚状态。
- 模型替用户做决定的问题，需要通过交互、澄清策略和风险分级解决。
- 私有部署带来数据控制，也会带来算力、运维和模型迭代负担。

### 对数据、环境与评测公司

- 价值正在从静态 SFT 数据转向任务环境、Verifier、失败恢复和反作弊。
- 一套能反复生成新任务和新奖励的环境，比一次性数据集更具复利。
- 持续学习和自动研究都需要跨时间、跨工具的评测，而不是一次 benchmark。
- 产品应证明数据如何进入具体训练阶段，以及能否提高单位成功任务结果。

### 对芯片与编译器公司

- Kernel agents 会降低新模型适配新硬件的成本。
- 提供标准测试、性能基线和可编程环境，有助于 agent 自动优化。
- 竞争优势会从手写 kernel 数量，部分转向环境、DSL、验证器和社区反馈速度。
- 现有领先厂商同样可以利用 agent，因此自动化不会天然重排市场。

### 对投资与产业分析

- 开放模型对闭源实验室的冲击，需要按企业私有部署可行性分层估算。
- 模型价格下降不等于价值全部商品化；环境、算力、Serving 和分发仍能承接利润。
- 评估模型公司时，应追踪下一代权重的生产周期，而不只看当前分数。
- “开源追平闭源”需要同时比较能力、成本、迭代速度和数据飞轮。

## 精简结论

K3 的核心价值不是某一项 benchmark 第一，而是它证明多项激进组件能够在约 3T 参数、百万上下文和真实 agent 后训练中共同成立。

在算法层，KDA 与 MLA 说明线性注意力和全局注意力可以分工；Attention Residuals 改造深度信息流；Quantile Balancing 和 Per-head Muon 解决超大规模训练中的负载与稳定性。每项创新都降低一个瓶颈，也把复杂度转移到新的系统环节。

在 Infra 层，KDA 降低长上下文 KV 搬运，却要求推理框架重新设计前缀共享、并发写入、投机采样回退和状态生命周期。K3 当前体感较慢，不足以判断架构长期效率；新模型需要给 Serving 生态时间完成优化。

在后训练层，九个专家通过 MOPD 合版，反映了 agent 训练环境的高度异构。蒸馏在这里承担的是组织解耦和能力合并，而不是“复制一个外部模型”。模型持续变强仍依赖外部监督、环境和验证器。

在开放生态层，K3 让全世界获得这一代权重，却没有完全开放产生下一代权重的流水线。真正长期的竞争发生在数据、环境、Verifier、算力、Serving、产品反馈和迭代速度上。

这期节目最终提供了一套理解前沿模型的更好方法：不要孤立讨论算法、分数或价格，而要把模型架构、训练系统、推理基础设施、Agent Harness、评测环境和单位成功任务成本放在同一张图里。
